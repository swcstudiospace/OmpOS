# Phase 3 · Plan 02 — Session-run workflow: direct runner + Temporal worker behind the flag (WFLW-01..03)

## Objective

One workflow definition (provision → run prompt → collect → teardown-in-finally), executed in-process by `DirectSessionRunner` when `Workflows:Enabled=false` (default), or by a Temporal .NET worker when true; determinism proven by replay; routing criteria documented.

## Wire facts (03-RESEARCH.md VF-4 — authoritative)

`Temporalio` **1.20.0** + `Temporalio.Extensions.Hosting` **1.20.0** (same version, pin BOTH in Directory.Packages.props — you own that file this wave). Replay without server: `WorkflowReplayer` + `WorkflowHistory.FromJson`. Determinism: no `DateTime.Now`/`Task.Run`/`Guid.NewGuid()`/`Random` in workflow code — `Workflow.UtcNow`, `Workflow.Random`, `Workflow.NewGuid`, `Workflow.Delay`. Hosting: `AddHostedTemporalWorker` (set deployment options at registration). Worker in `services/OmpOS.Workflows.Worker`, never referenced by API/UI projects (architecture test enforces).

## Tasks

1. `src/OmpOS.Workflows` (NO Temporal dependency — Temporal types live only in the worker project): `ISessionRunWorkflow` (`Task<SessionRunResult> RunAsync(SessionRunInput, IWorkflowContext ctx)`), `ISessionRunActivities` (`ProvisionSandbox`, `RunPrompt` (streams into the session log, heartbeats via `IWorkflowContext.Heartbeat(string)`), `CollectArtifacts`, `TeardownSandbox` — teardown in a `finally` semantics enforced by the runner, not the activity author), `SessionRunInput/SessionRunResult` plain records. `DirectSessionRunner : ISessionRunWorkflow` — sequential in-process execution with the finally-teardown; deterministic (clock/random injected via `IWorkflowContext`).
2. `SessionRunWorkflow` + `SessionRunActivities` (adapter classes carrying `[Workflow]`/`[Activity]`-equivalent metadata ONLY in the worker project): the worker project defines `TemporalSessionRunWorkflow` wrapping the SAME `ISessionRunWorkflow` instance graph so logic exists once (WFLW-01); activities get retry policy (initial 1 s, backoff 2×, max 3) + heartbeat calls.
3. Worker: `Program.cs` builds a Host; `WorkerOptions{Enabled (Workflows:Enabled), Address, Namespace, TaskQueue}` bound with ValidateOnStart; when disabled the host exits 0 immediately WITHOUT registering Temporal services (test: startup log/no-listener assertion); when enabled registers `AddTemporalClient` + `AddHostedTemporalWorker(SessionRunWorkflow)`. Compose profile `workflows` already defines the `temporal` service (dev server) — document `temporal server start-dev` equivalent in the ADR.
4. Replay test: check in `TestData/histories/session-run.json` — a minimal exported history for the workflow type. Two-stage honesty: the fixture is generated ONCE by running the Temporal path against the dev server IF available (`temporal` CLI present? check; if absent, build the history JSON by hand from the documented schema and mark `[REPO: dotnet.temporal.io testing docs]`); `TemporalReplayTests` runs `WorkflowReplayer` over it and MUST pass determinism. If hand-built, add open-question row Q-WF-HISTORY (verify fixture against a real dev-server export later).
5. `SessionRunWorkflowContractTests<T>` abstract fixture: happy path provisions→runs→collects→tears down in order; prompt failure still tears down (finally guarantee); provision failure leaves session not-Running; heartbeat events observed; run against `DirectSessionRunner` (and reusable for the Temporal impl later, WFLW-03).
6. `ADR-0003-workflow-routing.md`: route through Temporal ONLY when a run must survive process restarts or needs durable retries/timers; everything else stays direct. Include the compose-profile dev-server instructions and the WorkerOptions surface.
7. `Directory.Packages.props`: add `Temporalio` 1.20.0 + `Temporalio.Extensions.Hosting` 1.20.0; worker csproj references them; `src/OmpOS.Workflows` references NEITHER (architecture: API/UI must not reach Temporal — extend the architecture test's forbidden-reference list for `OmpOS.Workflows`→Temporal only if the existing rule shape allows; otherwise assert via a new RepoHygiene test grepping the csproj).
8. Register worker + test project in `OmpOS.slnx` + `OmpOS.Linux.slnf` (worker IS in the Linux filter — it is plain .NET; the Temporal connection is runtime config, not build-time).
