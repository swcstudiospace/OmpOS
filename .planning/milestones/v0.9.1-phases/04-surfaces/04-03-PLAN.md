# Phase 4 · Plan 03 — Engine hosts + MAUI Blazor Hybrid head (DESK-01, MOB-01, SHELL-01)

## Objective

`IEngineHost` seam with in-process (desktop: in-memory adapter or local `omp acp`) and remote-only (mobile: API + SSE resume on `Window.Resumed`) implementations — testable on Linux as plain net10.0 code; MAUI head as a thin multi-targeted shell excluded from the Linux filter; macOS build human-deferred.

## Constraints

- The MAUI head CANNOT compile on this Linux host (no macOS/Android/Windows workloads). Verification for the head = project files exist, multi-target set, excluded from `OmpOS.Linux.slnf`, and NOT in the Linux build path. All testable logic lives in `src/OmpOS.EngineHost` (net10.0) — the head only wires DI.
- Layout deviation (recorded): D-01 did not list `src/OmpOS.EngineHost`. It is an L2 library (references Harness.Abstractions + Harness.InMemory + Harness.Acp) so the host logic is unit-testable without MAUI. Amend ADR-0002 with a dated addendum; add `OmpOS.EngineHost` to `LayerMap` at layer 2 and to `OmpOS.slnx` (NOT `OmpOS.Linux.slnf` change needed — it IS Linux-buildable, so it goes in both, unlike the MAUI head).

## Tasks

1. `src/OmpOS.EngineHost` (net10.0): `IEngineHost { IAsyncEnumerable<HarnessEvent> SubmitPromptAsync(...); Task CancelAsync(); EngineHostDescriptor Descriptor; }`; `EngineHostDescriptor { Kind: InProcess|Remote, Isolation, Attestation }` (reuses Contracts enums — the UI renders the real boundary per the anti-pattern rule); `InProcessEngineHost` (binds `InMemoryOmpAdapter` sessions or an `OmpAcpClient` session created from a local `omp` path — injectable factory so tests never spawn), `RemoteEngineHost` (API base URL; create/submit via HttpClient; SSE resume with `Last-Event-ID`/Seq de-dup; `Reconnect()` for resume-on-foreground). Window-state persistence, single-instance guard, crash-safe session recovery are interfaces only (`IWindowStateStore`, `ISingleInstanceGuard`, `ISessionRecovery`) with no-op/fake defaults + open-question rows (Q-DESK-PERSIST, owner: desktop).
2. MAUI head `apps/OmpOS.App`: csproj multi-target `net10.0-android;net10.0-ios;net10.0-maccatalyst` (+Windows Tizen omitted), `SingleProject` properties, MauiProgram registering BlazorWebView + `OmpOS.UI` root + `IEngineHost` (desktop targets: `InProcessEngineHost`; mobile: `RemoteEngineHost` — decided by `DeviceInfo.Platform` at registration); `Window.Resumed` hook calls `RemoteEngineHost.Reconnect()` on mobile. Content = `OmpOS.UI`'s session surface. Mark `EnableMaui=false`-safe: the csproj must NOT be picked up by a bare `dotnet build` at repo root on Linux (it is excluded from the slnf and from `OmpOS.slnx` it is registered but the slnf gates Linux CI; register in `OmpOS.slnx` only).
3. Tests `tests/OmpOS.EngineHost.Tests` (net10.0): host kind selection; in-process happy path via in-memory adapter (no real omp spawn); remote resume: scripted HttpClient handler returns events 1..5 then a connection drop; `Reconnect()` replays 6..12 exactly once (Seq de-dup); persistence/guard interfaces default no-ops; descriptor honesty (Railway/None-style capability values surface unchanged).
4. ADR-0002 addendum: dated section "Phase 4 amendment — EngineHost library" with the deviation rationale. README gains the heads table (WEB verified on Linux/browser; DESK/MOB structure verified, binaries human-deferred to macOS CI).
5. Architecture: add `ompos.enginehost` to `LayerMap` at the same layer as Harness.InMemory (2) and confirm the layer tests pass (EngineHost must NOT reference Api/Web/App).
6. Register `src/OmpOS.EngineHost` + tests + `apps/OmpOS.App` in `OmpOS.slnx`; add EngineHost + tests to `OmpOS.Linux.slnf`; the App stays OUT of the slnf. Own `OmpOS.slnx` this wave (plan 02 agent is done by the time this wave starts — sequential waves; if running concurrently, coordinate).

## Verification

`/root/.dotnet/dotnet test tests/OmpOS.EngineHost.Tests` green; `/root/.dotnet/dotnet build OmpOS.Linux.slnf` unaffected by the App; `grep apps/OmpOS.App OmpOS.Linux.slnf` matches nothing.
