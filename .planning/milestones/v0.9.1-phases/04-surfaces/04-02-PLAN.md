# Phase 4 · Plan 02 — Blazor WASM web head + Vercel static deploy (WEB-01..02)

## Objective

Standalone Blazor WASM head hosting `OmpOS.UI`, API base URL from configuration, SSE consumption with browser-visible streaming; `vercel.json` static deploy (SPA rewrite + CSP headers); vertical slice smoke in a real browser against the in-memory adapter API.

## Facts (04-RESEARCH.md VF-2 — authoritative)

`vercel.json`: `framework: null`, installCommand = dotnet-install.sh with `-JsonFile global.json`, buildCommand = `./.dotnet/dotnet publish -c Release -o output` (full path), `outputDirectory: output/wwwroot`, SPA catch-all rewrite; never mix `routes` with `rewrites`/`headers`; CSP needs `wasm-unsafe-eval` and connect-src for the API origin.

## Tasks

1. `apps/OmpOS.Web`: standalone WASM (net10.0, `Microsoft.AspNetCore.Components.WebAssembly.Sdk` via framework), hosts `OmpOS.UI`; base URL from `appsettings.json` (`Api:BaseUrl`, overridable by query/env at boot — no hardcoded hosts); `ApiSessionClient` (create/list/get session, submit prompt) + `SseEventStream` (native `EventSource`-equivalent via `HttpClient` with `response body streaming` — WASM HTTP supports streaming response; parse `id:`/`event:`/`data:` frames, client-side Seq de-dup, `Last-Event-ID` on reconnect with backoff).
2. Vertical slice wiring: `Program.cs` registers an `IEngineHost`-equivalent remote binding — in the WEB head the "engine" is the API; the in-memory adapter lives server-side. For the browser smoke, `dotnet run` the Phase 2 API with the in-memory adapter and point the WASM head at it.
3. `vercel.json` at repo root per VF-2, CSP/security headers included (`script-src 'self' 'wasm-unsafe-eval'`, `connect-src` api origin placeholder `https://api.ompos.local` documented, X-Content-Type-Options, Referrer-Policy, X-Frame-Options DENY).
4. Tests `tests/OmpOS.Web.Tests` (plain net10.0, no bunit needed): `ApiClientTests` — SSE frame parser unit tests (split fixture frames incl. reconnect with Last-Event-ID, duplicate Seq dropped, terminal event stops) using the captured Phase 2 fixtures; publish smoke: `dotnet publish` the Web head succeeds and `output/wwwroot` contains `index.html` + `_framework/` (assert in test via publish output path or a script step recorded in the runbook).
5. Browser smoke (orchestrator-run, recorded in `docs/runbooks/local-dev.md` § Vertical slice): serve `dotnet run --project services/OmpOS.Api` (in-memory adapter) + serve published WASM head locally; drive headless Chrome: open app → create session → submit scripted prompt → observe streamed blocks + terminal state; screenshot recorded. AXE-core run against the page (best-effort; critical/serious must be zero, else fix-up).
6. Register project + tests in `OmpOS.slnx` + `OmpOS.Linux.slnf` (own both files this wave). No new packages.

## Verification

`/root/.dotnet/dotnet test tests/OmpOS.Web.Tests` green; publish output exists; browser smoke recorded with screenshot.

## Requirement coverage

WEB-01 (WASM head + config-driven base URL + streaming + browser smoke), WEB-02 (vercel.json schema + headers; actual Vercel deployment is post-milestone — deploy config verified by schema + publish output shape).
