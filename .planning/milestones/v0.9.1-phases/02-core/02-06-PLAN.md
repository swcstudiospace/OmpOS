# Phase 2 · Plan 06 — API host: endpoints, SSE resume, guards, ops (API-01..03, OPS-01..04)

## Objective

Secured, observable ASP.NET Core 10 minimal API: validated session endpoints, SSE with `id:`=Seq + gap-free resume, rate limiting, locked CORS, committed build-time OpenAPI 3.1, correlation, health, fail-fast config, OTel hooks, no-op auth boundary.

## Verified versions (02-RESEARCH.md VF-3..VF-7 — pin these)

`Microsoft.Extensions.ApiDescription.Server` 10.0.12, `OpenTelemetry` + `OpenTelemetry.Extensions.Hosting` 1.20.0, `OpenTelemetry.Instrumentation.AspNetCore` 1.19.0, `Scalar.AspNetCore` 2.17.14 (Development only). Framework packages (`Microsoft.AspNetCore.OpenApi`) come from the shared framework — do NOT add PackageReferences for them.

## Tasks

1. Convert `services/OmpOS.Api` to `Microsoft.NET.Sdk.Web` (it is a class-library placeholder; keep target framework + existing ProjectReferences; update `OmpOS.slnx` build entries if needed). Layer stays L3 — the architecture test already forbids referencing L4.
2. `ApiOptions` (`Api:Cors:Origins[]`, `Api:MaxPromptLength`, `Api:RateLimit:PromptsPerMinute`, `Workflows:Enabled` switch placeholder) bound via `AddOptions<ApiOptions>().BindConfiguration(...).ValidateDataAnnotations().ValidateOnStart()`; missing required variable fails startup with a message naming it (test asserts exception text contains the key name). Update `.env.example` with every variable.
3. Endpoints: `POST /sessions {ownerId}` → 201 + Session; `GET /sessions` → list; `GET /sessions/{id}` → 200/404; `POST /sessions/{id}/prompts {prompt}` → 202 (prompt accepted; harness call goes through `IOmpSession` from the configured adapter — in Phase 2 wire the `InMemoryOmpAdapter` behind `IHarnessSessionFactory` DI alias); validation: content-type `application/json` enforced (415 otherwise), body size limit from options (413), empty/oversize prompt → 400 with ProblemDetails; `OmpOSError(PromptInFlight)` → 409 ProblemDetails. All responses carry `x-correlation-id`.
4. `GET /sessions/{id}/events`: SSE via `TypedResults.ServerSentEvents` + `SseItem<StreamEventPayloadPayload-shaped-string>` — **each event serialized with `SseItem<string>(json, eventType: payload-kind, eventId: Seq.ToString())`** (VF-3 pitfall: the SseItem overload takes per-item eventType/EventId only). `Last-Event-ID` header OR `?since=` query resumes from that Seq inclusive; after catch-up the stream tails live appends (single per-session `Channel<StreamEvent>` broadcaster so replay+live cannot duplicate); terminal `CompletedPayload`/`ErrorPayload` event ends the response. Heartbeat comment every 15 s via `ReconnectionInterval`/comment line.
5. Rate limiting: `AddRateLimiter` with `SessionRateLimiterPolicy` — partition key = session id from route, token bucket `PromptsPerMinute`; applied to the prompts endpoint; rejection → 429 + Retry-After. CORS: `AddCors` policy locked to `Api:Cors:Origins` (empty default = no cross-origin allowed); test asserts disallowed origin gets no CORS headers.
6. OpenAPI: `AddOpenApi()` + `MapOpenApi()`; `Microsoft.Extensions.ApiDescription.Server` with `OpenApiGenerateDocumentsOnBuild=true`, `OpenApiDocumentsDirectory=docs/api`, `--file-name openapi --openapi-version OpenApi3_1`; commit `docs/api/openapi.json`. Scalar mapped in Development only. Freshness check: integration test runs build-generated doc equality (compare committed file bytes to regenerated).
7. Middleware: `CorrelationIdMiddleware` — accepts `x-correlation-id` or generates `Guid.CreateVersion7()`, sets `HttpContext.TraceIdentifier` + response header, pushes into `ILogger` scope; `AuthBoundaryMiddleware` + `IUserContext`/`SingleDevPrincipal` no-op provider (fixed principal "local-dev", documented extension point in XML docs); user text never concatenated into control/log messages — log redaction: prompt bodies logged as `<redacted len=N>` unless `OmpOS:Debug:LogPrompts=true` (OPS-03/04).
8. Health: `MapHealthChecks("/health/live")` (self) and `"/health/ready"` with tagged checks: harness adapter readiness (in-memory always ready), repository check, Temporal connectivity check registered only when `Workflows:Enabled=true` (Phase 3 fills the real check; in Phase 2 it's a no-op tagged check that reports Healthy when the flag is false and Degraded when true with no endpoint — config wiring only, no Temporal package yet).
9. OTel: `AddOpenTelemetry()` with AspNetCore instrumentation + metrics: `ompos.sessions.count`, `ompos.stream.latency` (histogram, ms, recorded in the SSE streamer), `ompos.parser.fallback.rate` (counter), `ompos.sandbox.provision.time` (registered, not yet emitted); OTLP exporter + console exporter switchable via `Otel:Exporter` (none default); traces across endpoint→service→harness in-memory path (test asserts one trace with ≥3 spans via in-memory exporter or `Otel:Exporter=console` capture — prefer adding `OpenTelemetry.Exporter.InMemory` ONLY if such a package exists at a stable version; otherwise assert via ActivityListener).
10. Tests (`tests/OmpOS.Api.IntegrationTests`, WebApplicationFactory + in-memory adapter): `SessionEndpointTests` (CRUD + validation matrix + 409 PromptInFlight + 415 + 413 + 429 + CORS lockout + correlation header round trip); `SseResumeTests` — submit scripted 12-event prompt, read stream, disconnect after event 5, reconnect with Last-Event-ID=5, assert events 6..12 exactly once, no gaps (Seq continuity), terminal event present; `GuardTests` — missing required env fails startup naming it, health endpoints, OpenAPI doc freshness vs committed file, redaction unit test (log output contains `<redacted`, not the prompt).
11. Register in `OmpOS.slnx` + `OmpOS.Linux.slnf`; locks regenerate; `docs/architecture.md` data-flow section gains one sentence pointing at the SSE endpoint contract (no duplication).
