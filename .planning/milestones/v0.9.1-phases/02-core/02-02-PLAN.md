# Phase 2 · Plan 02 — Harness abstractions, state machine, in-memory adapter, WebSocket stub

## Objective

Typed harness surface (HARN-01), explicit tested state machine (HARN-02), deterministic scripted in-memory adapter with six failure modes (HARN-03), bounded WebSocket stub + reusable contract fixtures (HARN-06).

## Shapes (from REQUIREMENTS.md:31-36 — authoritative)

1. `HarnessEvent` union as abstract sealed-hierarchy records with `[JsonPolymorphic]`-free plain C# (discriminated by derived type): `TextDeltaEvent(string Text)`, `ThoughtEvent(string Text)`, `ToolCallEvent(string CallId, string Name, string PayloadJson)`, `ToolCallUpdateEvent(string CallId, string Status, string PayloadJson)`, `PermissionRequestEvent(string CallId, string Name, string PayloadJson)`, `PlanEvent(string Markdown)`, `UiBlockEvent(OmpOS.Contracts.Ui.UiBlock Block)`, `ErrorEvent(string Message, bool Retryable)`, `CompletedEvent(string Reason)`.
2. `HarnessState` enum: Disconnected, Connecting, Handshaking, Ready, Streaming, Cancelling, Faulted, Disposed. `HarnessStateMachine` static class: `IReadOnlyDictionary<HarnessState, IReadOnlySet<HarnessState>> AllowedTransitions`; `void TransitionTo(HarnessState)` instance wrapper throwing `InvalidHarnessTransitionException` on illegal moves. Allowed: Disconnected→Connecting; Connecting→Handshaking|Disconnected|Faulted; Handshaking→Ready|Disconnected|Faulted; Ready→Streaming|Connecting|Disposed|Faulted; Streaming→Cancelling|Ready|Faulted; Cancelling→Ready|Faulted|Disconnected; Faulted→Connecting|Disposed; Disposed→∅.
3. `HarnessException` abstract + derived: `ProcessStartHarnessException`, `HandshakeTimeoutHarnessException`, `MalformedFrameHarnessException`, `DisconnectedHarnessException`, `BackpressureHarnessException`, `DuplicateCompletionHarnessException` (all carrying optional inner exception + context string).
4. `IOmpSession : IAsyncDisposable`: `Task CreateAsync(CancellationToken)`, `Task ResumeAsync(string sessionId, CancellationToken)`, `IAsyncEnumerable<HarnessEvent> SubmitPromptAsync(string prompt, PromptOptions options, CancellationToken)`, `Task CancelAsync(CancellationToken)`, `HarnessState State { get; }`, `IReadOnlyDictionary<string, string> AdvertisedCapabilities { get; }` (empty for in-memory). `PromptOptions`: `bool Steer` default false.
5. `IAcpTransport : IAsyncDisposable`: `Task ConnectAsync(CancellationToken)`, `Task SendAsync(ReadOnlyMemory<byte> frame, CancellationToken)`, `IAsyncEnumerable<ReadOnlyMemory<byte>> ReceiveAsync(CancellationToken)`, `Task CloseAsync(CancellationToken)`.
6. `InMemoryOmpAdapter` (src/OmpOS.Harness.InMemory): ctor takes `InMemoryScript` — a deterministic queue of steps: emit events (fixed sequences incl. one `UiBlockEvent(MarkdownBlock)`), throw one of the six failure exceptions, or complete. Implements a session factory `IOmpSession CreateSession()`; state machine enforced throughout (Connecting→Handshaking→Ready→Streaming→Ready→Disposed on the happy path).
7. `WebSocketOmpTransportStub` implementing `IAcpTransport`: every method returns `Task.FromException(new NotImplementedException("remote WebSocket transport: NotAvailable — owner: platform, tracked in docs/open-questions.md Q-HARN-WS"))` wrapped in the typed-pattern the contract fixture expects: a `NotAvailable` marker via `HarnessException`-derived `ProcessStartHarnessException("WebSocket transport not available (stub)")`. Bounded: no protocol work. Owner-tagged open question added to `docs/open-questions.md` (append row, id `Q-HARN-WS`, owner `platform`).

## Contract fixtures (tests/OmpOS.Harness.ContractTests)

- `OmpSessionContractTests<T>` where T : IOmpSession factory — abstract tests: create→ready; submit happy path yields the scripted sequence in order; cancel during stream yields CompletedEvent("cancelled") and state returns to Ready; dispose idempotent; submit after dispose throws `ObjectDisposedException`.
- `AcpTransportContractTests<T>` where T : IAcpTransport factory — connect/send/receive/close round trip against a loopback in-memory pair (helper `LoopbackAcpTransportPair` in the same project), close idempotent, receive after close throws `DisconnectedHarnessException`.
- Both fixtures compile against abstractions only (no reference to InMemory project).

## Tests

- `HarnessStateMachineTests`: every transition in the allowed table asserted once, every pair NOT in the table throws (exhaustive 8×8 theory).
- `InMemoryAdapterTests`: scripted happy path event order incl. UiBlock; capabilities empty; multiple sessions independent.
- `FailureModeTests` (six): process-start failure → `ProcessStartHarnessException`; handshake timeout → `HandshakeTimeoutHarnessException`; malformed frame script step → `MalformedFrameHarnessException`; mid-stream disconnect → `DisconnectedHarnessException` after partial events (consumer must see the events before the error); backpressure: bounded `Channel<HarnessEvent>` capacity 4, slow consumer + >4 events script → writer completes via bounded-drop policy surfacing `BackpressureHarnessException` on overflow; duplicate completion script → `DuplicateCompletionHarnessException`.
- New test projects `tests/OmpOS.Harness.Abstractions.Tests`, `tests/OmpOS.Harness.InMemory.Tests`, `tests/OmpOS.Harness.ContractTests` (csproj shape from Contracts.Tests; ContractTests references only Harness.Abstractions; InMemory.Tests references InMemory + ContractTests), all registered in `OmpOS.slnx` + `OmpOS.Linux.slnf`.
