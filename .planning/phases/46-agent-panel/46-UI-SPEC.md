# Phase 46 — UI Design Contract

> Visual and interaction contract for the Agent Panel, the default surface of the Avalonia native head (`apps/OmpOS.Native`, `src/OmpOS.Native.Views`, Avalonia 12.1.4). Locked decisions D1 to D9 in `46-CONTEXT.md` are inputs, not re-decided here. This document extends the Phase 20 contract (`20-UI-SPEC.md`); every rule there that is not changed below still holds. Generated by gsd-ui-researcher; verified by gsd-ui-checker.

## Focal Points

One primary visual anchor per screen state:

| Screen state | Anchor | Why it leads |
|--------------|--------|--------------|
| Session selected (default) | The transcript with the composer under it | Largest region, `Surface` (60%) background, the only region that scrolls content the user wrote or is waiting for. |
| No sessions | The empty-state block in the thread region with the filled `New agent` button | The only accent-filled element on screen. |
| Panel loading | The loading heading in the thread region | The only text that changes. |
| Tool open | The tool host that replaces the thread | The rail stays; the tool header names what is open. |

Hierarchy, in the order the eye should read: selected rail row, thread title, transcript, composer, pipeline strip, inspector.

## Scope of the Phase 46 Surface

- One main window titled `OmpOS`. No dialog, no second window. Confirmations are inline bars (see Behaviour).
- Window: initial size 1280 x 800, `MinWidth` 960, `MinHeight` 640 (assumption 1 in `46-CONTEXT.md`; the window is 960 x 640 minimum, not the Phase 20 value 640 x 480).
- Three regions, left to right: **Agents rail**, **Thread**, **Inspector** (collapsible). The skip link stays above them.
- The panel replaces `ConversationListView` as the left column and replaces the bottom toggle rows of `MainView`. Nothing else in `MainView` is removed (see "Where Every Existing Tool Lives").

### Responsive rules (no other breakpoints)

| Window width | Rail width | Inspector default | Notes |
|--------------|-----------|-------------------|-------|
| 1200 px or more | `OmpOS.Size.AgentRailWidth` (280) | expanded, `OmpOS.Size.InspectorWidth` (320) | Thread gets the rest (680 px at 1280). |

Code behind reads `Bounds.Width` of `MainView` and switches the rail width and the first-run inspector state. The 1200 px threshold is one named constant in `MainView.axaml.cs`.

## Where Every Existing Tool Lives

The rail has two views, chosen by a segmented pair of toggles at its top: **Sessions** (the default, the session list) and **Tools** (a vertical list of the existing toggles). All existing toggles keep their `x:Name` and `AutomationProperties.Name` exactly (assumption 3). They are declared in `MainView.axaml` (same name scope as today, so `FindControl` and `ShellHarness` keep working) inside a `StackPanel x:Name="ToolsViewHost"`, which is shown in place of the session list while **Tools** is checked.

| `TerminalToggle` | Terminal | `Terminal` | Tools view, group **Workspace** | Thread region (`ToolHost`) |

| `ConventionsToggle` | Conventions | `Workspace conventions` | Tools view, group **Workspace** | Thread region (`ToolHost`) |
| `WorkspaceSearchToggle` | Workspace search | `Workspace search` | Tools view, group **Workspace** | Thread region (`ToolHost`) |

| `ExportToggle` | Export | `Transcript export` | Tools view, group **Session** | Thread region (`ToolHost`) |

Rules:

- A tool that uses `ToolHost` or `AgentsHost` replaces only the **thread region**, below the thread header. The rail and the inspector stay. `OpenTool` keeps its present behaviour: opening one closes the others and the Agents window.
- While a tool is open the thread region draws a tool header row (`Tool header`: the tool name in the Label role, semibold, and a `Close tool` button named `Close tool`, 44 px). `Close tool` returns to the transcript and moves focus to the toggle that opened the tool.
- Selecting a session row, pressing `Ctrl+N`, or pressing `Ctrl+2` closes the open tool and shows the thread.
- The three group headers (`Panels`, `Workspace`, `Session`) are `TextBlock`s, not tab stops.
- Transcript search (`SearchHost`, `TranscriptSearchView`) keeps its present place under the transcript and opens with `Ctrl+F` (see Keyboard Map). The approval controls (`RunControlsHost`, `RunControlsView`) keep their place above the composer.

## Agent Row and Status Chip

### Status mapping (rail row, thread header chip)

`SessionCatalogModel` maps `SessionSummary.Lifecycle` and the live `RuntimeStatus` (through `RuntimeStatusMap`) to one row status. The view draws the status text and glyph below. Groups are shown in this order; an empty group is not drawn.

| Group header | Row status text | Source value | Glyph | Text colour | Sort inside group |
|--------------|-----------------|--------------|-------|-------------|-------------------|
| `Needs you` | `Needs approval` | `RuntimeStatus.NeedsAttention` | Needs you | `StatusWarning` | oldest waiting first |
| `Needs you` | `Waiting for you` | `RuntimeStatus.AwaitingInput` | Awaiting input | `StatusWarning` | oldest waiting first |
| `Running` | `Running` | `RuntimeStatus.Running` | Running | `TextPrimary` | most recent activity first |
| `Running` | `Queued` | `RuntimeStatus.Queued` | Queued | `TextPrimary` | most recent activity first |
| `Lost` | `Lost` | `SessionLifecycle.Lost` or `RuntimeStatus.Unreachable` | Lost | `StatusWarning` | most recent activity first |
| `Idle` | `Ready` | `SessionLifecycle.Created` | Ready | `TextSecondary` | most recent activity first |
| `Idle` | `Paused` | `RuntimeStatus.Paused` | Paused | `TextSecondary` | most recent activity first |
| `Idle` | `Closed` | no engine attached, lifecycle Paused or Completed (closed by the operator) | Closed | `TextSecondary` | most recent activity first |
| `Finished` | `Completed` | `RuntimeStatus.Completed` | Completed | `StatusSuccess` | most recent activity first |
| `Finished` | `Failed` | `RuntimeStatus.Failed` | Failed | `StatusError` | most recent activity first |

An unknown or unmapped value (a future `RuntimeStatus`) renders as the group `Idle` with text `Status unknown` and the Ready glyph; it never throws.

### Row layout

```
[ group header band, only on the first row of a group: Label role, semibold, TextSecondary, 24 px, no hit area ]
[ title (Body role, TextPrimary, one line, ellipsis; semibold when selected)                             ]
[ (status chip) · last activity · task tag                                                              ]
```

- Row `MinHeight` is `OmpOS.Size.SessionRowMinHeight` (64): 8 top padding, title 22.5, chip 24, 8 bottom padding. A group-start row is 24 taller.
- Second line, left to right, Label role (13), `Gap.Xs` between items:
  1. Status chip (glyph plus status text, see below).
  2. Last activity: `just now` under 10 s, `{n} s ago` under 60 s, `{n} min ago` under 60 min, `{n} h ago` under 24 h, `{n} d ago` beyond. Computed from the injected `TimeProvider`; refreshed every 30 s by the model; the refresh is silent (no announcement).
  3. Task tag: `Task {taskId}` in `TextSecondary` when `TaskId` exists, else `Graph {last 8 characters of GraphId}` when only a graph exists, else nothing. Mono font for the id part.
- Long-running flag: after the chip the text `Long-running` is appended in `TextSecondary`. It is text, not colour.
- Stale flag (no activity beyond the model's threshold while Running): the last-activity text is replaced by `Quiet for {n} min` in `StatusWarning`.
- The selected row: `SurfaceActive` background, the 2 px `AccentPurple` left border (existing style), title semibold. Selection is never signalled by colour alone: weight and the left bar change too.
- Row accessible name: `{title}, {status text}, {last activity}` plus `, long-running`, `, quiet for {n} min` and `, {task tag}` when present. The group header band and the glyph are `AccessibilityView=Raw`.

## Composer Behaviour

The composer reuses `ComposerView` and `ComposerViewModel` (existing names, Phase 20 rules: Send and Stop always enabled and always in the tab order; blank send is a no-op; the draft clears only when the host accepts the message). Changes:

| State | Placeholder | Send button name | Follow-up | Stop |
|-------|-------------|------------------|-----------|------|
| Idle, session ready | `Describe a task for this agent…` | `Send message` | hidden | enabled; with nothing running it shows `No response is running.` in `Session status` |
| Run active | `Steer the running agent… It is delivered after the active turn.` | `Steer message` | visible, text `Queue follow-up`, name `Queue follow-up message` | enabled; stops the run at once |
| Awaiting approval | as Run active | `Steer message` | visible | enabled |

Send, Steer, Follow-up and Stop semantics:

| Action | Input | Result |
|--------|-------|--------|
| Send | Enter, or Send button, when idle | Starts a run from the draft (`ComposerViewModel.SendAsync`); the pipeline starts. |
| Steer | Enter or Send button, or `Ctrl+Enter`, while a run is active | `RunInputScheduler.SteerAsync`. While follow-ups wait, the steer queues behind them as a follow-up so messages keep their send order (existing rule). The entry appears in Steering history and Substrate records it when reachable. |
| Follow-up | `Ctrl+Shift+Enter` or the Follow-up button, while a run is active | `RunInputScheduler.QueueFollowUp`. It starts when the active run completes. A full queue (16) refuses with the copy above and keeps the draft. |
| Newline | Shift+Enter | Inserts a line (`AcceptsReturn`). |
| Stop (button) | click or Enter or Space on the button | Stops the run at once. No confirmation. Partial output stays. |
| Stop (key) | Esc in the prompt while a run is active | Opens the stop confirmation bar (below). Esc with nothing running does nothing. |

Partial output stays in the thread.` Buttons `Stop agent` (focused when the bar opens) and `Keep running`. Focus rules:

- After **New agent**: prompt of the new session.
- After closing a session: the next row (or the previous when it was last); with no rows left, `Start first agent`.
- After the close confirmation is dismissed: `Close this agent`. After the stop confirmation is dismissed: the prompt.
- After `Close tool`: the toggle that opened the tool.
- When the inspector collapses while focus is inside it: focus moves to `Inspector`.

## High Contrast

Avalonia 12.1.4 has no OS high-contrast or forced-colours reader (recorded in Open Items). The panel is built so it holds when colours are replaced:

- Status, selection, severity and focus never rely on colour alone. Every status has a glyph and a word. The selected row also gets a semibold title and a 2 px left bar. Errors and warnings carry the words `failed`, `degraded`, `unavailable`, `needs approval`.
- Chips and tool toggles have a 1 px `TextSecondary` border (non-text, at least 3:1 on every background, contrast-tested). The focus ring is 2 px.
- Region boundaries are `Surface`, `SurfaceRaised` and `SurfaceActive` steps plus the 1 px borders on chips; no region edge depends on a tint difference alone below the 3:1 text pairs.
- Both token variants (Light, Dark) satisfy every pair listed below. The shell pins Light today; a Dark switch needs no panel change.
- Text is never placed over an image or a gradient. No transparency carries meaning (the pulse changes opacity but the word and the glyph carry the state).

## Claude's Discretion

Choices the locked decisions left open. Each has a one-line reason.

1. **Tools live in a rail view, not a toolbar.** Twelve toggles do not fit a 960 px bar without horizontal scrolling, and a scrolling bar is hostile to keyboard users. A rail view keeps them one Tab away and mirrors an activity bar.
2. **The rail keeps names and `x:Name` of the old toggles.** Tests and `FindControl` keep working; only their parent changes.
3. **Enter keeps its Phase 20 meaning while a run is active.** Ctrl+Enter and Ctrl+Shift+Enter are added instead of redefining Enter, so the existing composer tests hold.
4. **Esc confirms before stopping; the Stop button does not.** Esc is easy to hit by accident; the button is a deliberate act.
5. **Confirmation bars, not dialogs.** A modal would add a window and a focus trap; an inline bar with a safe default is simpler and testable.
6. **Closed sessions stay in the catalog.** Closing stops the engine (AL-10) but keeps the work, so `Reopen agent` is possible.
7. **One pipeline strip button, not four.** It keeps one tab stop and one 44 px bar while still reading as four labelled pills; details are one activation away.
8. **Stage Retry means re-check.** A stage is an observation, not a unit of model work; re-probing is the only retry that is always safe.
9. **Inspector collapsed by default under 1200 px.** The thread keeps at least 400 px, enough for a prompt and three composer buttons.
10. **No new colour token.** Existing roles cover every use; new sizes only, so no new contrast pair exists.
11. **Glyphs drawn as strokes in status colours.** Status colour roles are text roles already contrast-tested; the same value works for a 1.5 px stroke.
12. **Group headers inside the first row of a group.** One `ListBox` keeps Up and Down continuous across groups and one tab stop.
13. **Substrate event rows only if the observer emits them.** The panel does not ask the observer for more than the contract allows (D9).
14. **Window minimum raised to 960 x 640.** The panel needs rail 240, thread 400 and room for the inspector at 320.
