<feature>
  <name>Unknown-kind-safe JSON polymorphism for UiBlock and StreamEvent payloads</name>
  <files>src/OmpOS.Contracts/Ui/UiBlockConverter.cs, src/OmpOS.Contracts/Streaming/StreamEventPayloadConverter.cs, src/OmpOS.Contracts/Serialization/OmpOsJsonContext.cs</files>
  <behavior>
    Known kind string plus full body maps to its sealed record and serializes back with the kind first. Cases: {"kind":"code",...} maps to CodeBlock; {"kind":"a2ui",...} maps to UnknownBlock with OriginalKind a2ui; missing kind maps to UnknownBlock with null OriginalKind; UnknownBlock writes its stored Raw verbatim. Same shape for StreamEvent payloads with an UnknownPayload fallback. Missing required member on a known kind throws JsonException. Plain anonymous-object serialization throws InvalidOperationException.
  </behavior>
  <implementation>Custom JsonConverter on each abstract base holding an Ordinal kind-to-Type map, resolving known kinds through options.GetTypeInfo (source-generated, AOT-safe), falling back to the Unknown record with the JsonElement root cloned; write path serializes Unknown raw verbatim and otherwise serializes via the derived TypeInfo then inserts the kind discriminator first. Every derived type listed in JsonSerializable on OmpOsJsonContext with camelCase, WhenWritingNull, and string-enum conversion. No JsonPolymorphic attribute on converter-backed bases.</implementation>
</feature>

## Edge probes (explicit assumptions, spec-less fallback)

FOUND-02 adjacency (when two Seq values are exactly equal, do they merge or stay distinct): StreamEventSeqComparer.Compare returns 0 for equal Seq and the comparer never merges events; dedup-by-Seq is a Phase 2 client concern. FOUND-02 empty (empty or single-element input): an empty event list sorts to an empty list; covered by the comparer tests. FOUND-02 ordering (equal elements, stable order): List.Sort is not stable; any Phase 2 code needing stable order must sort by (Seq, insertion index) — recorded as a documented assumption on StreamEventSeqComparer. FOUND-03 adjacency/empty/ordering/concurrency: lock-file concurrency is last-writer-wins via --force-evaluate and locked mode fails closed on drift (NU1004); an empty PackageVersion set restores clean. FOUND-06 empty (empty JSON object {}): deserializes to UnknownBlock with empty Id and null OriginalKind, never throws — pinned by the missing-kind test. FOUND-06 encoding (whose definition of length/equality): all kind matching uses Ordinal string comparison and Id is an opaque string; no normalization is applied.
