## What changed in the product

- The API has an owner-token mode (`Api:Auth:Mode=OwnerToken`), an allow-list of subjects for OIDC deployments, per-subject rate-limit partitions, hosting hardening (forwarded headers, HSTS, security headers, Kestrel limits, request timeouts, startup and shutdown probes, SSE keep-alive), an allow-listed engine environment, a 0700 workspace per session, a non-dumpable process and an approval policy for the direct run path.
- The web head has a connect screen, an auth gate with the token in memory only, routes with titles and focus, a route announcer, an error boundary, a not-found page, an About page, a bounded transcript and an offline shell that never caches credentials or streams.
- The real bundle is built by `scripts/vercel/build-web.sh` and checked by `check-no-demo.sh`; the Demo stays a build-time variant.

## Defects the real run found (all fixed)

| Defect | Fix |
|--------|-----|
| After every turn of a real omp session the transcript showed "Unsupported content (ContextUsageEvent)": omp reports the context window use at the end of each turn, the API mapped it to an unknown kind and the head rendered unknown kinds | `849780ef`: stored as `context_usage` with its two numbers, never rendered; tests in `SessionRunActivitiesTests`, `ProjectionReplayTests`, `ContextUsageFoldTests`; the browser run asserts it stays away |
| The vendored terminal stylesheet was imported from inside another stylesheet; axe-core re-fetched the nested import relative to the page and got three 404s | Imported from the entry stylesheet |
| The API ends the stream of a session whose run has completed | The driver posts the prompt first, then reads the stream (a harness change; the behaviour is intended) |
