# Phase 66.2 Context: Hosted real web app

Milestone v0.16.0, inserted after Phase 66.1 on 2026-10-29. Requirements AG-HW-1 to AG-HW-12. Decision record: `docs/decisions/ADR-0021-hosted-single-operator-deployment.md`. Runbooks: `docs/runbooks/hosting.md`, `docs/runbooks/deploy-and-rollback.md`, `docs/runbooks/integration-autonogrammer-2026-10-29.md`. Harness: `scripts/hosted/README.md`. Threat model: `docs/security/hosted-threat-model.md`.

## What this phase does

The owner asked on 2026-10-29 ("ultrathink orchestrate workflowz") for three things: bring the code to a production-ready, enterprise-grade standard; turn `https://ompos-web.vercel.app`, which is only a Demo with a simulated engine, into a fully working and accessible web application; and use the files of the concurrent session in `~/src/repos/ompos-autonogrammer` or work them together with ours.

This phase is the second part for the web head and the API behind it: the real bundle (no Demo code) signs in, talks to a hosted API over HTTPS, streams real agent turns, shows tool approvals and survives a reload and a lost connection. The first part (the rename and the integration with the other line) is Phase 66 and `docs/runbooks/integration-autonogrammer-2026-10-29.md`; accessibility is Phase 66.3; CI, supply chain, operations documents and brand are Phase 66.4.

## Decisions

| ID | Decision | Evidence |
|----|----------|----------|
| D66.2-1 | The other line is adopted by replay onto a fresh branch of `origin/main`, not by merge: its un-renamed commits are cherry-picked, `scripts/rebrand` is run again, and the generated files are regenerated. Only its committed state is used; its worktree is never touched. | `docs/runbooks/integration-autonogrammer-2026-10-29.md`; `docs/runbooks/rebrand-autonogrammer.md` section 3 |
| D66.2-2 | The first hosted deployment is for one operator. `Api:Auth:Mode=OwnerToken` takes a bearer token whose SHA-256 digest is in configuration; the browser keeps the token in memory only; `GET /auth/config` tells the client which mode runs. Multi-user sign-in stays ADR-0030 and keeps the `mode` field. | ADR-0021 D1 to D3 |
| D66.2-3 | Hosted runs are narrowed: the engine child process gets an allow-listed environment, a 0700 workspace per session and a non-dumpable API process; the direct run path gets an approval policy with kinds and grantable tools, deny-all by default. No sandbox provider exists (HOST-04), so the host is the boundary. | ADR-0021 D4, D5; OQ-173, OQ-174, OQ-183 |
| D66.2-4 | The Demo stays a build-time variant (`AutonogrammerDemo`). The real bundle is built by `scripts/vercel/build-web.sh` and checked free of Demo code by `scripts/vercel/check-no-demo.sh`, which has a positive control on the Demo bundle. The Demo moves to its own Vercel project only with the owner's approval. | ADR-0017, ADR-0021 D6; Q-DEP-1 |
| D66.2-5 | The hosted path is verified here with the real `omp acp` and a scripted OpenAI-compatible model server, so no credential and no network egress are needed. This proves the harness loop, streaming, approvals, resume, the token and the rate limiter; it says nothing about a real model (OD-07). | `scripts/hosted/README.md` |
| D66.2-6 | Names that live outside the repository stay as they are until the owner renames them: the GitHub repository, the Vercel project `ompos-web` and its hostnames, and the Railway project, service and volume of the staged worker. New resources get the new name. | `scripts/rebrand/rebrand.config.json` protected patterns |
| D66.2-7 | Nothing is pushed, merged or deployed, no infrastructure is provisioned and no secret is changed without one explicit approval at the end of the run (the ultrathink plan, question 4). | `ultrathink-ship`, this phase's summary |
| D66.2-8 | The transcript uses progressive disclosure (the latest 50 turns and a "Show earlier messages" button), not virtualization, so that every rendered turn stays in the accessibility tree and in find-in-page. | `src/Autonogrammer.UI/Components/SessionView.razor` |
