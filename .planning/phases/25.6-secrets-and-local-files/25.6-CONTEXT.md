# Phase 25.6 Context: Secrets and Local Files (fix F-E)

Source: 25.1-FINDINGS.md section 5 (M-13, M-15, M-16). The owner accepted all eight fix phases on 2026-10-26; F-E runs fifth. Owner answer on consent (2026-10-26): confirm once per repository; consent is keyed by repository path and the setup file hash; a changed file asks again.

## Decisions

- D1 (M-13, AgentOsProvider origin): the constructor refuses an endpoint that is not https, unless it is http on a loopback host (`Uri.IsLoopback`: localhost, 127.0.0.0/8, ::1). The refusal is an `ArgumentException` on `endpoint`, raised before any request. The bearer token (`Authorization`) and the `x-rivet-token` header go only to the configured origin.
- D2 (M-13, redirects): the `HttpClient` is injected, so the provider cannot switch redirects off on a client it does not own. Two measures: `AgentOsProvider.CreateHttpClient()` returns a client over `SocketsHttpHandler { AllowAutoRedirect = false }` for production wiring, and `SendAsync` refuses any 3xx response and any response whose request URI is on another origin (`NotAvailableException`, no token in the message). A caller that injects its own redirect-following client is still stopped on the response, but the first hop could already have carried the headers; the factory is the real fix. No production caller exists yet (only tests construct the provider), so there is nothing to migrate.
- D3 (M-15, compose file mode): the compose file moves into a private per-sandbox directory `<temp>/ompos-podman-<id>/` created with `UnixFileMode` 0700, and the file is created with `FileMode.CreateNew` and `UnixCreateMode` 0600, so there is no chmod-after window. On Windows no mode is set (user profile ACLs). Cleanup deletes the file and then its directory when empty. The helper is `OwnerOnlyFiles` in `src/OmpOS.Sandbox`; the existing credential staging file already used the same pattern and is unchanged.
- D4 (M-16, consent design): `ISetupConsentStore` (IsGranted / RecordGrant, keyed by `SetupConsentKey(RepositoryPath, SetupSha256)`), `ISetupConsentPrompt` (async `SetupConsentDecision` Granted or Denied with a reason), `DenyingSetupConsentPrompt` as the default, `FileSetupConsentStore` as the persistent store. `SetupRunner.RunAsync` gains the store and the prompt as required parameters and returns `SetupStatus.ConsentRefused` without running anything when consent is absent or denied.
- D5 (hash source): the SHA-256 is computed from the raw bytes `SetupFileReader` parses (one read), never from a second read, so the approval describes exactly what runs.
- D6 (when to ask): a setup that declares steps or environment variables needs consent. An empty setup (no file, or `steps: []` with no environment) runs nothing and asks nothing. Environment-only setups ask because variables such as `LD_PRELOAD` change what the run executes.
- D7 (store state): one JSON file, `version: 1`, under the per-user application data folder (`OmpOS/setup-consent.json`; `FileSetupConsentStore.DefaultPath()`), path given by the caller like `PluginStateStore`. Reads are fresh on every call. Writes go to a temp file (0600) renamed over the target. One approval per repository path (the latest hash). A corrupt, empty, unmapped-member, null-grants, or unknown-version file is no consent, is moved to `setup-consent.json.quarantined-*`, and never throws. An approval that cannot be saved fails the run before any step runs (no silent loss).
- D8 (heads): no head implements a real prompt in this phase; no head calls `SetupRunner` today (only tests do), so the default prompt is the shipped behaviour and a head must supply its own `ISetupConsentPrompt` when it wires the run. Recorded in ADR-0005 section 9 and open risk 1.

## Assumptions

- Phase 25.5 is partial and stays partial; its residuals do not block this phase.
- Subagents edit files only; the lead runs the one gate.
