# Phase 2 · Plan 01 — Catch-all prompt parser

## Objective

Every input string yields exactly one `IntentEnvelope` via an ordered DI-registered recognizer chain whose fallback is unremovable, implementing PARSE-01..04.

## Contracts (existing, do not change)

`src/OmpOS.Contracts/Intents/IntentEnvelope.cs` (RawText, NormalizedText, Kind, Arguments, Resources, Confidence, Diagnostics), `IntentKind` (Chat, SlashCommand, Mention, Directive, Magic, Steer, FollowUp, Fallback), `Diagnostic`. Parse rules: PARSE-01..03 in `.planning/REQUIREMENTS.md:24-27`.

## Tasks

1. `IPromptRecognizer` in src/OmpOS.Parser: `int Order { get; }`, `RecognizerResult? TryRecognize(PromptInput input)` where `PromptInput` carries `RawText`, `NormalizedText` (trimmed, newline-normalized to `\n`), `bool IsInsideCodeFence`, `IReadOnlyList<string> Lines`; `RecognizerResult` = `(IntentKind Kind, double Confidence, IReadOnlyDictionary<string,string> Arguments, IReadOnlyList<string> Resources, string RecognizerName)`.
2. Recognizers (each sealed, one file): SlashCommand (`^/[a-z][\w-]*(\s+.*)?$` → Arguments["command"], Arguments["args"], only when line 0 and not in fence), Mention (`@\w[\w.-]*` tokens and `path/to/file` references after "in " or backticked paths → Resources), Directive (`key: value` pairs at line starts, ≥1 match, args from pairs), MagicKeyword (standalone lowercase words `ultrathink`, `orchestrate`, `workflowz`, `jevify` in prose — ignored inside triple-backtick fences, inline single-backtick spans, or HTML tags; Arguments["keyword"]), Steer (text while session running — decided by caller-supplied context flag `PromptContext.IsSessionRunning`, kind Steer), FollowUp (`PromptContext.HasCompletedPrompt` + heuristic "follow-up" markers "also ", "then ", "next "), Fallback (always matches, Confidence 0.0, kind Fallback).
3. `PromptParser` (sealed, DI-friendly): ctor takes `IEnumerable<IPromptRecognizer>`; orders by `Order` ascending, stable; **appends `FallbackRecognizer` last after ordering regardless of its registered Order** (hardwired terminator — cannot be removed or outrun). First recognizer whose `TryRecognize` returns non-null wins; runs each skipped recognizer inside try/catch, converting exceptions to `Diagnostic` entries (`code: "recognizer_exception"`, recognizer name in message) and continuing. Never throws to caller for any input, including null-adjacent garbage handled by `PromptInput` normalization (control chars preserved in RawText, stripped in NormalizedText except `\n`).
4. Oversize: `MaxPromptLength = 64_000` const on `PromptParser`; inputs longer yield envelope with `RawText` truncated at 64,000 chars + `Diagnostic` `code: "prompt_truncated"` with original length in message; Kind = Fallback unless an earlier recognizer matches the truncated text.
5. omp keyword matching (PARSE-02 "omp's documented matching rules"): lowercase standalone prose words only — a word matches when its lowercase form equals the keyword and it is delimited by whitespace/string bounds; fenced code, inline code, HTML-ignored regions never match. `jevify` is included (verify omp's spelling from its slash-command list if reachable: `get_available_commands` fixture `rpc-out.ndjson` is the source of truth; the four keywords above are locked in REQUIREMENTS).
6. `ServiceCollectionExtensions.AddOmpParser(this IServiceCollection)` registers recognizers (Orders: SlashCommand 10, Mention 20, Directive 30, Magic 40, Steer 50, FollowUp 60; Fallback registered with Order int.MaxValue but parser appends it regardless) and `PromptParser` singleton.
7. New test project `tests/OmpOS.Parser.Tests` (copy csproj shape from `tests/OmpOS.Contracts.Tests`, reference Parser + Contracts), register in `OmpOS.slnx` AND `OmpOS.Linux.slnf` (mirror existing entry style).

## Tests (tests/OmpOS.Parser.Tests)

- `PromptParserTests`: empty string, whitespace-only, 64,001-char string (truncation diagnostic + original length), `\r\n`/`\r`/mixed newlines, emoji/unicode, C0 control chars, injection-style `"; drop table --`, slash command in fence → Chat/Fallback not SlashCommand, `@file` + mentions → Resources, directive block, each magic keyword standalone + inside fence/inline-code/HTML ignored, lowercasing ("ULTRATHINK" does not match — omp rule is lowercase standalone), steer/follow-up context kinds.
- `RecognizerOrderingTests`: custom `IPromptRecognizer` registered via DI with Order 5 wins over built-ins (PARSE-04); removing Fallback registration still yields Fallback envelope; Fallback with Order 0 still runs last; recognizer throwing inside TryRecognize produces diagnostic, pipeline continues; exactly one envelope per input (property-style loop over the corpus).
