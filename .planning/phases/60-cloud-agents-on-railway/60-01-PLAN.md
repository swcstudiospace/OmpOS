## Decisions the units recorded

- The worker is an Autonogrammer-owned bridge (route `/acp`, session is the token subject, duplicate subject answers 409 before the upgrade); omp itself has no remote endpoint (ADR-0020, OQ-97).
- Secrets are Railway service variables of that session's service (ADR-0020 D7); the control plane resolves them, the worker never calls out; names only on the wire to the heads. A create with secret references is refused on the static pool.
- `deploymentStop` is documented by Railway but not used: a stopped deployment is not Railway's Serverless sleep and is not woken by traffic (ADR-0020 D6).
- Caps (5 agents, 2 running by default) are enforced atomically in the store; an optional per-agent compute cap sets `limit_reached`.
- The control plane keeps the transcript as an ordinary session (`cloud-<guid>`); the Railway and static clients have no volume file API and throw Unsupported from `AppendVolumeFile` and `ReadVolumeFile`.
- `docker` is not named in any new file other than the registry host and the Compose key `dockerfile:`; the `agents` compose profile written by the first commit is no longer in `deploy/compose.yaml` (removed by `3171ee8`; the header of `deploy/worker.Containerfile` has the podman commands).
