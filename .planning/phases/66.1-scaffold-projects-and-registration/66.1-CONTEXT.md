## Existing Code Insights

### Reusable Assets
- `ProjectGraphChecker` (`ReadEdges`, `ReadProjectNames`, `FindViolations`) validates the csproj graph with no build output; `ArchUnitLayerTests` needs every assembly built.
- Smallest csproj exemplar and the `Remote` and `Coordination.Tests` shapes above; `Autonogrammer.Contracts/AssemblyMarker.cs` as the marker shape.

### Established Patterns
- A project absent from `LayerMap` is reported "not in LayerMap"; a same-layer edge without a tuple is a violation; upward edges fail `ProjectGraph_RejectsUpwardReference`; nothing may reference `Autonogrammer.Api`; Web never references a process-spawning assembly (`ProjectGraphTests.cs:14-41`).
- `NuGetAuditMode all` plus warnings-as-errors: any advisory on a new package fails the build (`Directory.Build.props:30-31`; report 09 s.2 row 8 [INFERENCE]); CI forces locked restore (`Directory.Build.props:38`).

### Integration Points
- All 40 new projects are created by this phase (none exists: `ls src` shows 36 projects, none of the 21). Everything in phases 67 to 76 builds on them; ArchitectureTests, the Linux slnf, bootstrap and CI see them only through these registrations.
- Android restores on its own (not in the slnf) and is not buildable here: its `apps/Autonogrammer.Android/packages.lock.json` embeds project entries, so the new `Dispatch.Client` reference needs a relock that this host may not be able to run [INFERENCE]; the CI `android` job (`.github/workflows/ci.yml:157`) is where it is checked.
