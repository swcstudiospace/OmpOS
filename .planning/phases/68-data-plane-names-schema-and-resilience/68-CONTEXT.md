## Implementation Decisions

### Physical names
- **D-01:** Dragonfly key and channel prefix is the code constant `autonogrammer:v1:` (`v1` lets a later key shape change without a scan); never configuration. (ADR-0031 D1)
- **D-02:** PostgreSQL: own database `autonogrammer` (extension `timescaledb` created once in it by the bootstrap, never by the application); schema `autonogrammer` with search path `autonogrammer,public` and every new statement schema-qualified; roles (cluster-global) `autonogrammer_owner` (NOLOGIN), `autonogrammer_migrator`, `autonogrammer_app`, `autonogrammer_ro`. (ADR-0031 D1, D4)
- **D-03:** One advisory lock string `autonogrammer.schema.migrations` replaces `autonogrammer.sessions.schema` and `autonogrammer.cloud-agents.schema`; session locks keep the raw session id, and a test asserts generated session ids never contain `.`. (ADR-0031 D1, D5)
- **D-04:** Test and local names: containers `autonogrammer-test-postgres`, `autonogrammer-test-dragonfly`, `autonogrammer-test-pg-<guid>`, DB `autonogrammer_test`, user `autonogrammer`, variables `AUTONOGRAMMER_TEST_*`, `AUTONOGRAMMER_POSTGRES_*`, `AUTONOGRAMMER_DRAGONFLY_PASSWORD`, compose containers `autonogrammer-*`; test schemas stay `t_<guid>`, never `autonogrammer` itself. (ADR-0031 D1, D11; AG-68-3, 13)
- **D-05:** OTel source and meter `Autonogrammer.Api` (`ApiTelemetry.SourceName`); instruments `autonogrammer.sessions.count`, `.stream.latency`, `.parser.fallback.rate`, `.sandbox.provision.time`, `autonogrammer.cloud.*`. GreptimeDB database `public` becomes `autonogrammer` (`X-Greptime-DB-Name=autonogrammer`). (ADR-0031 D1, D6; AG-68-7)
- **D-06:** Config keys without a product token stay (`Sessions:Store`, `Sessions:Postgres:ConnectionString`, `Coordination:Store`, `Coordination:Dragonfly:ConnectionString`, `Otel:Exporter`, `OTEL_EXPORTER_OTLP_*`) and gain siblings; option sections follow R11: `DataPlane:*`. (ADR-0031 D1; R11)
- **D-07:** The rename tool does textual renames of identifiers, namespaces and file names; this phase only changes the physical constants and the test and deploy names above, then runs the guard tests. A local dev database needs one operator `ALTER SCHEMA ... RENAME` before the first migrate (M0001 and M0002 adopt the renamed tables); no hosted step. (ADR-0031 D1)
- **D-08:** Namespaces are disjoint from `plugins/gsd-core-omp` and `plugins/autonogrammer-hooks-omp` (grep run: no data-store use), omp (`~/.omp`, `OMP_*`, `models.yml`) and Substrate (ledger database `public`, index database, Dragonfly prefix unknown); decisions never rely on Substrate's prefix; the maintainer re-checks before the first deploy (OQ-340). (ADR-0031 D2)

### Dragonfly
- **D-09:** Autonogrammer runs its own service `autonogrammer-dragonfly` (own container locally) with its own `DFLY_requirepass`, image `docker.io/dragonflydb/dragonfly:v1.27.1@sha256:385cb73078f4dabe43d536766842eab444f3d791b0fcf86951decdcbcda37917`, no volume, an explicit `--maxmemory` (flag and value verified in a throwaway container), eviction off (no `--cache_mode`). An ACL user is defence in depth only after `DragonflyAclTests` passes (OQ-341), never the boundary. (ADR-0031 D3; AG-68-2)
- **D-10:** One helper, `DragonflyKeyspace` (renamed from `DragonflyKeys`), builds every key and channel: `autonogrammer:v1:<domain>:<tenant>:<entity>[:<id>]`, `<tenant>` 32 lowercase hex; domains `lease`, `idem`, `presence`, `rl`, `auth`, `sig`. (ADR-0031 D3; AG-68-1)
- **D-11:** Domain table (key; TTL; fail mode): `lease` `...lease:run:{sessionId}`, 30 s renewed every 10 s, closed (503 `data_plane_unavailable`, a run without the lease can double-execute); `idem` `...idem:{sha256hex(scope\nkey)}`, pending 60 s, completed 24 h, closed for prompt and command POSTs (503 with `Retry-After`); `presence` `...presence:{tenant}:{deviceId}`, 45 s with 15 s heartbeat, open (presence "unknown"); `rl` `...rl:{policy}:{tenant}:{window}`, window plus 5 s, degrades to the replica's in-process limiter, never unlimited; `auth` `...auth:nonce:{sha256hex}`, 10 min, closed (hello refused); channels `...sig:session`, `...sig:dispatch` with an id-only payload, open (the poll is the safety net). (ADR-0031 D3; AG-68-9)
- **D-12:** Helper rules plus a guard test: every write carries its TTL in the same command (`SET ... PX`, never `SET` then `EXPIRE`); TTL above 24 h or none is `ArgumentOutOfRangeException`; every Lua script declares each touched key in `KEYS`; never `FLUSHDB`, `FLUSHALL`, `KEYS` or `SELECT` as isolation; the only scan is `SCAN MATCH autonogrammer:v1:*:<tenant>:*` for account erasure. Dragonfly holds only reconstructible state. (ADR-0031 D3, D11)
- **D-13:** `<tenant>` is the first 16 bytes of HMAC-SHA256 keyed with secret `DataPlane:TenantHashPepper` over the account id (never an email or token), exposed as `ITenantHasher` in `Autonogrammer.Coordination`; `Coordination:Dragonfly:ConnectionString` now points at the dedicated service, no second connection string. Pepper rotation is not built (OQ-350). (ADR-0031 D3; brief U2)

### PostgreSQL and TimescaleDB
- **D-14:** One `NpgsqlDataSource` per role (runtime `autonogrammer_app`, migration `autonogrammer_migrator`, optional `autonogrammer_ro`). Roles and extension are created by the operator-run `deploy/data-plane/bootstrap.sql` (database, `timescaledb` in `public`, roles, `REVOKE CONNECT ON DATABASE autonogrammer FROM PUBLIC`, schema grants, `ALTER DEFAULT PRIVILEGES`), passwords from psql variables, never from the file. (ADR-0031 D4)
- **D-15:** The runtime role has DML only, no DDL; append-only `dispatch_audit` grants it INSERT and SELECT only; roles may `CONNECT` to databases that grant PUBLIC but hold no object privilege there (checked by `has_database_privilege` and a cross-schema query in the role test). (ADR-0031 D4; AG-68-5)
- **D-16:** No row-level security in v0.16.0 (artifact tables included): every store method scopes by owner, a foreign row reads as 404, and a contract test per method proves it. (ADR-0031 D4; R3; OQ-342)
- **D-17:** Existing tables keep their names (`sessions`, `session_events`, `session_tool_approvals`, `cloud_agents`); new tables use one flat naming scheme (no `acct_`/`dp_`/`cw_` prefixes). Hypertables are marked H below. (ADR-0031 D4; R3)
- **D-18:** The migration list is closed at M0001 to M0010; the runner applies every step up to the compiled head. Ownership: phase 68 U3 authors M0001 to M0009; phase 74 U2 authors M0010 `dispatch_device_state` and registers it in the runner list; no other phase writes a migration. (ADR-0031 D4; R2; manifest section 3 last row)
- **D-19:** M0001 `session_store`: `sessions`, H `session_events` (`occurred_at`, 1-day chunks, PK `(session_id, seq, occurred_at)`), `session_tool_approvals`, the current DDL moved unchanged. M0002 `cloud_agents`: the table and its four indexes unchanged. (ADR-0031 D4)
- **D-20:** M0003 `session_surface_owner`: `sessions.surface text NOT NULL DEFAULT 'code'` (values of `SessionSurface`, validated by the API, no CHECK), `sessions.closed_at timestamptz NULL`, index `sessions_owner_updated_idx (owner_id, updated_at DESC)`. (ADR-0031 D4; AG-68-6)
- **D-21:** M0004 `accounts(id text PK = Supabase sub, created_at, last_seen_at, status text, deleted_at, feed_seq bigint NOT NULL DEFAULT 0)`; no email, no profile data; M0004 wins over any older accounts DDL (`AccountResponse.email` comes from the token). (ADR-0031 D4; R5)
- **D-22:** M0005 `dispatch`: `dispatch_devices(id, account_id, name, platform, public_key, created_at, last_seen_at, revoked_at, command_seq bigint)`; `dispatch_commands(id, device_id, account_id, seq, op, state, idempotency_key, expires_at, body jsonb, body_purged_at, result jsonb, created_at, updated_at)` unique `(device_id, seq)` and unique `(account_id, device_id, idempotency_key)`, a regular table (state machine updates rows); H `dispatch_events(account_id, id, occurred_at, kind, ref, payload)` PK `(account_id, id, occurred_at)`; H `dispatch_audit(account_id_hash, id, occurred_at, device_id, command_id, op, outcome, corr)`. (ADR-0031 D4)
- **D-23:** M0006 `cowork`: H `cowork_events(account_id, session_id, seq, occurred_at, kind text, payload jsonb, blob_ref text NULL)` PK `(session_id, seq, occurred_at)`, payload at most 64 KiB; flat `artifacts(id text PK, account_id, title, kind, derived_from, latest_number int, created_at, updated_at)` index `(account_id, updated_at DESC)`; `artifact_versions(artifact_id REFERENCES artifacts ON DELETE CASCADE, version int, session_id, account_id, content_sha256, size_bytes, media_type, parent_number, parent_content_sha256, author, change_note, permissions jsonb DEFAULT '[]', created_at, content bytea NULL)` PK `(artifact_id, version)` with `CHECK (octet_length(content) <= 5242880)` (the per-kind limits of ADR-0033 D9 are the API's); `artifact_grants(artifact_id, version, account_id, content_sha256, origins jsonb, scope, device, granted_at)` PK `(artifact_id, version, scope, device)`, FK `(artifact_id, version)` ON DELETE CASCADE. Cowork conversation events stay in `session_events` (a Cowork session is a `sessions` row with `surface='cowork'`). (ADR-0031 D4; R3)
- **D-24:** `cowork_events.kind` is the closed list `artifact.created`, `artifact.updated`, `artifact.grant`, `artifact.revoke`, `schedule.run`, `schedule.late`, `schedule.waiting_for_approval`, validated by the writer (no CHECK, so a new kind is additive); browser and computer-use events stay local; the Cowork tool audit is the desktop's local hash-chained `FileCoworkToolAudit`, nothing from it goes to `cowork_events` or the ledger. Artifact bodies are written only when the owner turned artifact sync on (default off, OQ-343), otherwise metadata only. (ADR-0031 M0006; R15, R4)
- **D-25:** M0007 `ledger_outbox(id, audit_id, payload_digest, attempts, next_attempt_at, sent_at)`. M0008 `retention`: `add_retention_policy` on `dispatch_events` (30 d) and `dispatch_audit` (400 d). (ADR-0031 D4)
- **D-26:** M0009 `cowork_projects_memory` (user-content tables, owner-scoped by `account_id` in every query, no RLS): `cowork_projects(id PK, account_id, name, description, instructions, context_urls jsonb DEFAULT '[]', use_account_memory bool DEFAULT false, archived_at, created_at, updated_at)` index `(account_id, archived_at, updated_at DESC)`; `cowork_instructions(account_id PK, body, updated_at)`; `cowork_memory_entries(id PK, account_id, project_id NULL REFERENCES cowork_projects ON DELETE CASCADE, topic, content, category, source_session NULL, created_at, updated_at)` index `(account_id, project_id, updated_at DESC)` and GIN `to_tsvector('simple', coalesce(topic,'') || ' ' || coalesce(content,''))`; `cowork_memory_settings(account_id PK, enabled, paused, include_sensitive)`. (ADR-0031 M0009; R2)
- **D-27:** M0010 `dispatch_device_state` (not written here): `dispatch_devices` gains `credential_jti`, `credential_expires_at`, `capabilities`, `app_version`, `protocol`, `revoke_reason`, `paired_session_id`, `last_source_prefix` and a unique `(id, account_id)`, additive `ADD COLUMN IF NOT EXISTS` with constant defaults. AG-68-4 reads "migrations up to the compiled head". (ADR-0031 M0010; R2)
- **D-28:** Sequences are assigned under a row lock: per-device `seq` under the `dispatch_devices` row, per-account feed `id` under the `accounts` row (`feed_seq`), so a reader resuming from `id > last` never skips a late commit. (ADR-0031 D4)
- **D-29:** `ISessionRepository` gains `ListByOwnerAsync(string ownerId, SessionSurface surface, bool includeClosed, int limit, SessionCursor? cursor, CancellationToken cancellationToken)` (surface required and non-nullable, keyset on `(updated_at, id)`) and `SetClosedAsync(string sessionId, bool closed, CancellationToken cancellationToken)` (true when the flag changed), in the in-memory twin and `PostgresSessionRepository`; `Session` carries `Surface` and `ClosedAt` (amended by D-62: `Surface` is not `required`); `SessionSurface { Code, Cowork }` is created in `Autonogrammer.Contracts.Sessions` here and reused everywhere (never `SessionKind`). Phase 67 only calls them and deletes `SessionRegistry` and `SessionLifecycleStore`. (ADR-0031 D4; index section 2; AG-68-6)
- **D-30:** Retention: `dispatch_events` 30 days, `dispatch_audit` 400 days (`DataPlane:Retention:*`, audit floor 90 days validated), command bodies nulled 7 days after a terminal state (`body_purged_at`), `ledger_outbox` rows 7 days after `sent_at`. User content (`session_events`, `cowork_events`, `artifact_versions`, `artifact_grants`) has no automatic limit (OQ-344). (ADR-0031 D4)
- **D-31:** Erasure is one batched transaction per table family keyed by owner: dispatch tables, `cowork_events`, the memory family (`cowork_memory_entries`, `cowork_memory_settings`, `cowork_instructions`, `cowork_projects`, in that order), `artifact_grants`, `artifact_versions`, `artifacts`, `session_events` through the owner's session ids, `sessions`, `cloud_agents`, then `accounts`; the tenant's Dragonfly keys are deleted by the scan. Hard deletes; `dispatch_audit` keeps only `account_id_hash` (the tenant hash). (ADR-0031 D4 and addendum; AG-68-14)
- **D-32:** `add_retention_policy` is a Timescale License feature at 2.13.1: M0008 checks `current_setting('timescaledb.license')` and fails with the named error `retention_requires_timescale_license` unless it is `timescale`; if the Railway template is the Apache edition, retention runs from a one-shot `Autonogrammer.Api retention` with the migrator role (OQ-345). No compression in v0.16.0. (ADR-0031 D4)

### Migration runner
- **D-33:** No new package: a hand-written runner (about 300 lines). `autonogrammer.schema_migrations(version int PK, name, checksum, applied_at timestamptz, applied_by)`; checksum is SHA-256 of the step's up SQL and a mismatch stops the run (`MigrationChecksumMismatch`); `IMigrationStep { Version, Name, UpSql, DownSql }` as C# raw strings; each step in one transaction under `pg_advisory_xact_lock`. (ADR-0031 D5; AG-68-4)
- **D-34:** Up steps contain only `CREATE ... IF NOT EXISTS` and `ADD COLUMN IF NOT EXISTS`; never `DROP`, `ALTER ... TYPE`, `CREATE EXTENSION`, `DROP SCHEMA` (guard test scans step sources); `NOT NULL` only with a constant default. Every step ships a down step dropping only what it created, run by `Autonogrammer.Api migrate --down <version>`, never automatically nor in the release that shipped the up step; contract steps ship one release after the code stopped using the object. (ADR-0031 D5)
- **D-35:** Runner: a Railway one-shot service `autonogrammer-migrate` (the API image, `dotnet Autonogrammer.Api.dll migrate`, restart never) alone holds `Sessions:Postgres:MigratorConnectionString`; a pre-deploy command is rejected (it sees the API's variables). The API waits up to `DataPlane:Postgres:SchemaWaitSeconds` (default 120) for the compiled head, then fails fast naming the key; a newer schema is accepted and reported `SchemaAhead`. (ADR-0031 D5) Amended 2026-10-29: where the wait runs is D-58, where the `migrate` verb branches and how the image forwards its arguments is D-59.
- **D-36:** Development and tests: `Sessions:Postgres:AutoMigrate=true` runs the same runner with the runtime connection string; default false; the validator refuses it in Production. `PostgresSessionSchema` and `PostgresCloudAgentSchema` `EnsureCreated` classes are deleted. (ADR-0031 D5; Consequences) Amended 2026-10-29: the complete caller list and the test-database rules are D-60.

### Telemetry
- **D-37:** Existing OpenTelemetry SDK 1.20.0 and `OpenTelemetry.Exporter.OpenTelemetryProtocol` 1.20.0 over `http/protobuf`, no GreptimeDB client, no new package. Endpoint `OTEL_EXPORTER_OTLP_ENDPOINT=http://greptimedb.railway.internal:4000/v1/otlp`; `OTEL_EXPORTER_OTLP_HEADERS=X-Greptime-DB-Name=autonogrammer,X-Greptime-Pipeline-Name=greptime_trace_v1,X-Greptime-Trace-Table-Name=autonogrammer_traces` all in the general variable; `Authorization` Basic only in the hosting environment. `scripts/data-plane/bootstrap-greptime.sh` runs `CREATE DATABASE IF NOT EXISTS autonogrammer WITH (ttl='30d')` and never touches `public`. (ADR-0031 D6)
- **D-38:** New instruments `autonogrammer.dataplane.call.duration` (ms), `.retry.count`, `.breaker.transitions`, `.bulkhead.rejected`, `.dependency.state` (observable gauge) and `autonogrammer.ledger.outbox.depth`; tags are the bounded enumerations `component`, `operation_class`, `result`, `reason`, never an account id, email, device name, session id or command body. Feature instruments are named by their ADRs under the same rule. (ADR-0031 D6)
- **D-39:** Delivery never blocks a request (SDK batch processor drops oldest). Export state comes from an `EventListener` on the exporter's event source (name verified in the unit) and a 30 s `GET /health` probe with a 2 s timeout; "reachable and not failing", not "accepted". The Greptime database is a namespace, not an access boundary until static users are checked on v1.1.4 (OQ-346). (ADR-0031 D6)

### Resilience (`Autonogrammer.Resilience`)
- **D-40:** New L1 library (BCL plus `Microsoft.Extensions.Logging.Abstractions`, no package): a deadline wrapper (`CancelAfter` on a linked token), retry with decorrelated jitter on an injected `Random`, a consecutive-and-ratio circuit breaker, a semaphore bulkhead, all on an injected `TimeProvider`; plus `DependencyState` and `DataPlaneTimeoutException`. Polly is rejected for now (superseding ADR if hedging is ever needed). Only `Coordination.Dragonfly` and `Sessions.Postgres` (L2) and `Api` (L3) reference it; `Coordination` (L1) never does. (ADR-0031 D7; brief U1; R14)
- **D-41:** Defaults are options records with validators naming keys (`DataPlane:*`): PostgreSQL connect 5 s, command 5 s interactive and 30 s background, 2 retries only for reads and idempotent statements when `NpgsqlException.IsTransient`, delay 100 ms to 2 s, 8 s budget, writes never retried unless guarded by a unique key (one retry of a whole transaction on serialisation failure), pools `interactive` 16 and `background` 4 inside `Maximum Pool Size=20`; Dragonfly 250 ms per op, 2 s connect, 1 retry with 20 to 80 ms jitter for reads and idempotent scripts only, `SET NX` claims never retried after a reply, `interactive` 64 in flight; ledger 10 s, 8 attempts from 5 s doubling to 10 min, 2 in flight. Breaker: 5 consecutive failures or 50 % of the last 20 calls within 30 s; open 15 s (Postgres), 10 s (Dragonfly), 60 s (ledger); one half-open probe. The retry budget may not exceed twice the command timeout. (ADR-0031 D7; AG-68-8)
- **D-42:** Cancellation is never swallowed: the caller's `OperationCanceledException` passes through; a deadline expiry becomes `DataPlaneTimeoutException` with the component, never the connection string. (ADR-0031 D7)

### Health, status and degraded states
- **D-43:** `GET /health/live` stays anonymous and data-plane free; `GET /health/ready` stays anonymous and boolean: unhealthy when PostgreSQL is unreachable, the schema is behind the head, or Dragonfly is unreachable while `Coordination:Store=Dragonfly`. (ADR-0031 D8) Amended 2026-10-29 (D-56): Railway's health path is `/health/ready`, not `/health/live`, and the PostgreSQL and Dragonfly clauses are already carried by existing `ready` checks.
- **D-44:** New authenticated `GET /status/data-plane` returns `DataPlaneStatus` (`Autonogrammer.Contracts.DataPlane`): one row per component {Postgres, Dragonfly, Telemetry, Ledger}, `State` {Healthy, Degraded, Unavailable, Disabled}, closed `Reason` {None, CircuitOpen, Timeout, AuthFailed, NotConfigured, SchemaBehind, SchemaAhead, RetentionUnsupported, ExporterFailing, LedgerBacklog}; no host, port, version or message text. (ADR-0031 D8; AG-68-10)
- **D-45:** The only 503 problem type for a store outage is `data_plane_unavailable` (`component`, `reason`, `retryAfterSeconds`); a refused run, a refused idempotent POST, PostgreSQL, Dragonfly and schema-behind all use it; `coordination_unavailable` does not exist. (ADR-0031 D3, D8; R13; AG-68-9)
- **D-46:** Degraded behaviour by situation: PostgreSQL down: Code mode unaffected, cached lists marked stale, account/Cowork/Dispatch show "Your account service is not reachable. Code mode is unaffected. Retrying." with the retry time, no new Cowork chat or Dispatch command; Dragonfly down: reads and stored sessions work, runs and command POSTs 503 with `Retry-After`, "Starting work is paused while the coordination service recovers", presence "unknown" never "offline"; schema behind: "The service is being updated" with retry; telemetry and ledger states visible only in the operator view. Text plus icon, never colour alone, a live region for changes, focusable retry controls; copy is owned by ADR-0032 UX. (ADR-0031 D8; brief degraded table)

### Secrets and reachability
- **D-47:** Hosted traffic only over `*.railway.internal` (PostgreSQL also `SSL Mode=Require`); no TCP proxy or public domain for `autonogrammer-dragonfly` or the new database; credentials only as variables of the owning service (`autonogrammer_app` password in `autonogrammer-api`, `autonogrammer_migrator` in `autonogrammer-migrate` only, `DataPlane:TenantHashPepper` in `autonogrammer-api`); the template superuser is used once by the operator and no longer referenced by the API. No head, client build or log holds a credential, connection string or pepper; validators name the key, never the value. Desktop and mobile never speak PostgreSQL, Redis or GreptimeDB protocols. (ADR-0031 D9; AG-68-12; OQ-347)

### Ledger sink (default off)
- **D-48:** The only write path is Substrate's `POST /events` through `SubstrateGateway.EmitEventAsync` under its endpoint rules (https or loopback http, 10 s, 1 MiB, no redirects, bearer in the header only); Autonogrammer never holds a Solana key, sends a transaction, configures an RPC URL or writes to the ledger's database. `DataPlane:Ledger:Enabled=false` by default and then `ledger_outbox` stays empty. (ADR-0031 D10; AG-68-11)
- **D-49:** Source of truth stays PostgreSQL (`dispatch_audit` and account audit rows are written in the same transaction as the state change); the ledger is a notarisation copy fed by `ledger_outbox` and the hosted `LedgerOutboxPump` with the D-40 pipeline; a ledger failure never fails or delays a user request. (ADR-0031 D10)
