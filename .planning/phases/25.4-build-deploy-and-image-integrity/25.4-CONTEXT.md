## Decisions

- D1 (H-4, vercel.ts installCommand): stop executing the unverified dot.net script. Download the SDK tarball that bootstrap.sh already pins (the same URL and version, dotnet-sdk-10.0.402-linux-x64.tar.gz), verify its SHA-512 with the value bootstrap.sh pins (bootstrap.sh:22), and extract it into ./.dotnet. Reason: reuses an artifact the repo already trusts; no third-party script runs.
- D2 (M-27, CI actions): every `uses:` line in .github/workflows/ci.yml is pinned to a full 40-character commit SHA, with the tag in a trailing comment. The SHA is the peeled commit of the tag, resolved with `git ls-remote <repo> refs/tags/<tag>^{}`.
- D3 (M-28, runners): `runs-on: ubuntu-latest` becomes `ubuntu-24.04` in both jobs. Reason: the image that CI expects is named, so a runner-image change needs a commit.
- D4 (M-29, apt podman): `podman` is installed at the exact version the Ubuntu noble archive provides, with `--no-install-recommends`. The version is read from the archive at implementation time and recorded in a comment. Re-pinning is required when the archive version is withdrawn; that cost is recorded in the phase summary.
- D5 (M-30, Android workload) and D6 (M-31, global.json roll-forward): handled by the lead, not by the subagent, because the check needs `dotnet`.
- D7 (M-32, M-33, digests): every image reference in deploy/compose.yaml and scripts/test-services.sh is written as `repo:tag@sha256:<digest>`. Digests are resolved from the registry at implementation time. The tag stays for readability.
- D8 (M-34, axe-core): run-smoke verifies the axe-core package's `axe.min.js` with `sha256sum -c` against a committed file, `scripts/web-smoke/axe-core-4.14.0.sha256`, and exits non-zero on mismatch. The committed hash is computed from the npm tarball for axe-core 4.14.0. The existing evidence file written per run is kept.
- D9 (Low, PodmanDriverSection.cs:20,24): the `:latest` defaults become concrete tags with digests, resolved from the registry. Any golden test output that records the old text is updated in the same change.
- D10 (permanent checks, criterion 2 and 3): two repository tests in tests/OmpOS.ArchitectureTests: every `uses:` line is a full SHA and no `runs-on` uses `-latest`; every image reference in the compose file and the test-services script carries an `@sha256:` digest. These follow the RepoHygieneTests pattern and check repository configuration, not source text.
- Deferred: M-35 (caller-supplied image policy) stays deferred, as the register recorded.
