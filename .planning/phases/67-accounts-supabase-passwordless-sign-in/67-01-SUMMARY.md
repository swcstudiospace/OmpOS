After a failed store write that made the manager adopt its own long-consumed token and end the session. The manager now tracks the token it last wrote or read and adopts only a stored token that differs from both.

## Known limits

- A sign-out racing an in-flight refresh is guarded by an epoch counter: the late refresh result is discarded and never brings the session back, but the rotated token it returned is not revoked on the service (it dies with the session when the sign-out's `scope=local` request ends it, because both belong to one session id).
- `GetAccessTokenAsync` returns a not-yet-expired token when the refresh fails (the person is offline), and a failure only when it has expired.
- The offline retry loop runs for 15 minutes after the last failure, then stops until the next `GetAccessTokenAsync` call.
