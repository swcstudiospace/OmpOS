# Plan 67-05 summary: account module, board cutover, registry deletion

## What changed

- Prerequisite gate passed: `SessionSurface`, `ListByOwnerAsync`, `SetClosedAsync`, `Session.ClosedAt`, M0003 and M0004 are on disk. There is no separate accounts repository type from phase 68; the API module owns `IAccountStore` (in-memory twin, PostgreSQL upsert of `last_seen_at` only, no email column).
- `GET /auth/config` still returns mode, authority and audience (JSON nulls preserved) through `Contracts.Accounts.AuthConfigResponse`. In OIDC mode, with the development principal off and `Api:Auth:Client.HasAny`, it adds the client block and `Cache-Control: public, max-age=300`. Otherwise it stays `no-store`. The internal `Security/AuthConfigResponse` is deleted.
- New `Accounts` module: options default 120 (`Accounts:RequestsPerMinute`), policy `accounts` partitioned by `RateLimitPartitionKey.For`, enrollment middleware after `UseAuthorization` (10-minute per-sub cache, skips owner-token, the development principal and anonymous requests, never blocks on a store failure), four owner-scoped routes. Cowork is the only feature registered here.
- `GET /board` is gone. `GET /account/board` serves Code rows. Web client `GetBoardAsync` calls `account/board`. Demo, `ClientRouteSurface`, the service worker and OpenAPI moved in the same change. `GetAccountAsync` reads `GET /account`.
- `SessionRegistry` and `SessionLifecycleStore` are deleted. Catalog, steering, cloud agents and the change detector use `ListByOwnerAsync` (Code for the catalog and board; both surfaces for account sessions) and `SetClosedAsync`.
