<domain>
## Phase Boundary

Milestone v0.16.0. Requirements AG-71-1 to AG-71-24. Cowork shows what the agent makes (Markdown, Code, Html, Svg, Mermaid, Csv, Image) in a panel beside the chat as immutable, hash-chained versions the user can diff, copy, edit, export and list from any signed-in head. Generated content is untrusted: it renders only in-process through renderers that cannot execute it, or in an isolated surface (restrictive CSP, no network by default, no navigation, no bridge). Record: `docs/decisions/ADR-0033-cowork-artifacts.md` (Proposed 2026-10-28).

Work units (brief 71; order U1, then U2 U3 U4 in parallel, then U5 U6): U1 contracts and core (AG-71-1 to 7, 9, 22); U2 safe content pipeline (10 to 14, 23); U3 stores and sync (4, 19); U4 tool provider and API (8, 17, 20, 24); U5 Presentation and desktop (15, 17, 18, 21); U6 web head (16, 18, 21).

Depends on (index phase table): 67 (account gate, `SessionSurface`), 68 (M0006 tables, `cowork_events.kind` list), 70 (`Cowork.Abstractions`, `ToolUpdateImage`/`ImageBlock` from 70 U5), 69 U3 (`CoworkDockHost`, `IDockPanel`), ADR-0009, ADR-0010 (gateway route unverified). Phases 71 to 73 start after 70 unit 1 and need `Cowork.Abstractions` only (index section 1).

Must NOT do: no live artifacts, sharing or publishing, no persistent storage for artifact scripts, no CDN scripts, no HTML sanitiser or SVG renderer package, no migration (M0006 belongs to 68 U3), no project or registry registration beyond rows the scaffold manifest marks "per phase" (R17), no edit of `ContractVersion.Current` (R9), no run of the rename tool (phase 66).

<decisions>
## Implementation Decisions

### The one rule and the model
- **D-01:** Artifact content never becomes markup or a control of the application unless it passed a renderer that cannot execute it; everything that can execute (Html, scripts, Mermaid) runs only in an isolated surface; where the host cannot isolate, the artifact shows as source with a named reason, never "rendered anyway". (ADR-0033 D1)
- **D-02:** `ArtifactId` is `Guid.CreateVersion7()` text generated by the host; `Kind` is one of `Markdown`, `Code`, `Html`, `Svg`, `Mermaid`, `Csv`, `Image`, fixed at creation; `SessionId` is optional and deleting a session does not delete its artifacts; copy sets `DerivedFrom` (source artifact, version, hash). (ADR-0033 D2; brief 71 AG-71-1)
- **D-03:** `Title` is 1 to 120 characters; control characters, bidi controls (U+202A to U+202E, U+2066 to U+2069) and lone surrogates are rejected, not stripped; `Language` (Code only) is 1 to 32 characters of `[A-Za-z0-9+#._-]`; `MediaType` is derived from the kind, `Image` takes `image/png|jpeg|gif|webp` and the bytes must start with the matching magic number. (ADR-0033 D2)
- **D-04:** A version is `(ArtifactId, Number)` from 1 by exactly 1, write-once, storing bytes, `ContentSha256` (lowercase hex of the stored bytes), `Bytes`, `ParentNumber`, `ParentContentSha256`, `Author` (`Agent` or `User`, set by the host, never from tool arguments), `SessionId`, `CreatedAt` (injected `TimeProvider`), `ChangeNote` (at most 280) and the requested permissions; deleting an artifact hard-deletes all versions and grants. (ADR-0033 D3)
- **D-05:** `Update` requires `BaseVersion`; a stale base fails `StaleBase` with the latest number; bytes equal to the latest version's hash create no version and return the existing one (idempotent retry, no separate key). (ADR-0033 D3; AG-71-3)
- **D-06:** Every read recomputes the hash and checks the parent link; a mismatch raises `ArtifactIntegrityException`, nothing is rendered and the panel shows the integrity state; the server recomputes the hash of every uploaded version. A user edit (text kinds) saves `Author = User`, a stale save is refused with reload or "save as a copy", no merge. (ADR-0033 D3; AG-71-4, 5)
- **D-07:** Kinds not built: Word, PowerPoint, Excel, PDF (files in the storage folder, shown as chips by ADR-0032); notebooks, React/JSX, LaTeX; Slides/Design/Dashboard/Motion templates and MP4; audio, video, 3D; TSV (Csv only, RFC 4180 comma). (ADR-0033 D2)

### Tool family `artifact`
- **D-08:** Provider `ProviderId` `artifact` implements `ICoworkToolProvider` (`Autonogrammer.Cowork.Abstractions`, L1); descriptors `artifact_create`, `artifact_update`, `artifact_read`, `artifact_list` (omp shows `mcp__cowork_artifact_create` ...); `read` and `list` are `ReadOnly`, `create` and `update` are `Actuating` with approval `ByPolicy`; nothing is `Destructive`; `Results` is `Text`; host-built metadata has `IsUntrusted = false`, the content text of `read` is wrapped untrusted. (ADR-0033 D4)
- **D-09:** Arguments: `create` takes `title`, `kind`, `language?`, exactly one of `content` (text, base64 for Image) or `from_file` (absolute path), `media_type?`, `change_note?`, `permissions?` (`network`: up to 5 origins with a `reason` each) and returns `artifact_id`, `version`, `content_sha256`, `bytes`, `warnings[]`; `update` takes `artifact_id`, `base_version`, exactly one of `content`, `from_file`, `edits` (`{old,new}` exact-match, text kinds, each `old` must match exactly once), `title?`, `change_note?`, `permissions?` and returns the same or `stale_base` with `latest_version`; `read` takes `artifact_id`, `version?`, `max_bytes?` (Image: metadata only); `list` takes `session_id?`, `kind?`, `limit` (at most 50), `cursor?`. Errors are tool results with a stable `code`, validated before any work. (ADR-0033 D4)
- **D-10:** `content` is bounded below the gateway's 1 MiB body cap (`McpGatewayServer.MaxBodyBytes`); larger images use `from_file`, resolved under `CoworkSessionContext.TrustedFolders` and the Storage folder (not `ICoworkGrantStore`, which holds tool grants); a path outside a granted folder, a leaving symlink or a non-regular file is `file_not_allowed`; the same path is the user's "create artifact from file" action. (ADR-0033 D4 and Open risks; index 4.1; brief 71 AG-71-8)
- **D-11:** `artifact_create` and `artifact_update` return `Preview.Grant = ("artifact.write", "cowork")`: Manual asks once, "Allow always" persists the grant, a tainted session still asks, the prompt shows host-observed title, kind and size. Writes are limited by `Cowork:Artifacts:MaxWritesPerMinutePerSession` (default 20) with `rate_limited` and retry-after; nothing in the family can delete, share or publish. (ADR-0033 D4; R6)
- **D-12:** `warnings` carries what the renderer will do to the content (removed SVG elements, Html asking for network); the model learns the constraint from the call that caused it. (ADR-0033 D4)

### In-process renderers
- **D-13:** Markdown uses the existing Markdig 1.4.2 `DisableHtml()` pipeline unchanged (links open only on explicit action with the full URL shown; images only inline raster `data:`; `artifact:` and relative links are plain text); Code uses AvaloniaEdit 12.0.0 read-only with TextMate by exact language tag (web: escaped `<pre><code>`). (ADR-0033 D5, D6)
- **D-14:** CSV uses an in-house RFC 4180 reader (quotes, embedded newlines, BOM) capped at 2,000 rows, 50 columns, 2,000 characters per cell, 1 MiB input, saying "Showing the first N rows"; cells are text; a cell starting `=`, `+`, `-`, `@`, tab or CR is marked "formula-like"; desktop `Avalonia.Controls.DataGrid` 12.1.2, web `<table>` with caption and headers. (ADR-0033 D5, D6)
- **D-15:** Image is validated from the container header without decoding: magic number vs declared type, width and height each at most 8,192 and at most 50 megapixels, size at most `Cowork:Artifacts:MaxImageBytes`; an Image is never SVG. (ADR-0033 D6)
- **D-16:** The SVG sanitiser is pure BCL XML: `DtdProcessing = Prohibit`, `XmlResolver = null`, `MaxCharactersInDocument = 262,144`, `MaxCharactersFromEntities = 0`, depth at most 64, elements at most 5,000, attribute value at most 64 KiB; output written by `XmlWriter` from an allowlist walk (element and attribute lists exactly as ADR-0033 D6); `on*` dropped; `href` keeps only `#fragment` plus `data:` raster on `image`; CSS passes a conservative check or is dropped whole; every removal is a finding, a `warnings` entry and a panel notice; a rejected document renders as source. (ADR-0033 D6; AG-71-11)
- **D-17:** No `HtmlSanitizer` (parser mismatch, two packages) and no `Svg.Skia` (SkiaSharp 4.148.0 vs Avalonia.Skia 3.119.4); desktop SVG goes through the isolated surface and falls back to source; Html is not sanitised at all. (ADR-0033 D6)

### Isolated surface
- **D-18:** `IArtifactSurface` (Presentation) has states `Idle`, `Loading`, `Running`, `Stopped`, `NavigationBlocked`, `Unavailable(reason)`; the document is built by the host from stored bytes plus `ArtifactDocumentPolicy`, the only place a CSP is written, unit-tested as strings. (ADR-0033 D7.1)
- **D-19:** Html with scripts on: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; connect-src 'none'; frame-src 'none'; worker-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; manifest-src 'none'`; no `'unsafe-eval'`; scripts off gives `script-src 'none'`; SVG and Image documents use `default-src 'none'; img-src data:`; approved origins go to `connect-src`, `img-src`, `font-src`, `media-src` only, never `script-src`; no CDN scripts. (ADR-0033 D7.2)
- **D-20:** No bridge: the surface subscribes to no message event, never calls `postMessage`; desktop `NativeWebView` has the post-message bridge option off, a private non-persistent store, devtools and context menus off; a test asserts no subscription and a live probe page looks for `invokeCSharpAction`, `window.chrome.webview`, `window.webkit.messageHandlers`, `window.external`. (ADR-0033 D7.3; AG-71-15)
- **D-21:** Navigation is allowed once (to the host-built document); later navigation, new window, `meta refresh`, form submit or `base` change is cancelled and the state becomes `NavigationBlocked`; web iframe `sandbox` has no `allow-popups`, `allow-top-navigation`, `allow-forms`, `allow-modals`, `allow-downloads`, `allow-pointer-lock`, `allow-presentation`; a second `load` event destroys the frame. (ADR-0033 D7.4)
- **D-22:** The surface exists only while the panel shows it (hide, stop, close, sign-out destroy it; state is not preserved); the chrome labels the region "Generated content, not part of Autonogrammer" and shows a status line `Running in a sandbox. No network.` or the approved hosts. (ADR-0033 D7.5, D7.6)
- **D-23:** Three implementations: desktop `NativeWebView` (`Avalonia.Controls.WebView` 12.1.1, `NavigateToString`, meta CSP first, for Html, Mermaid, Svg); web ticketed render `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" allow="">` on `GET {api}/cowork/artifact-render/{ticket}` (Html); web `srcdoc` (Mermaid, static Html, fallback "static view" because the page CSP is inherited, CSP3 7.8). (ADR-0033 D7 table)
- **D-24:** Render tickets: `POST /cowork/artifacts/{id}/versions/{n}/render-tickets` (bearer, owner-scoped) returns a URL whose last path segment is an HMAC-SHA256 over account id, artifact id, version, content hash and an expiry of at most 60 s; keys `Cowork:Artifacts:RenderTicketKeys` (two, each at least 32 random bytes, validated at startup, failures name the key never the value); the anonymous render route re-reads the version, re-checks hash and grants, and answers with the D-19 policy, `sandbox allow-scripts` as a CSP directive, `frame-ancestors <web origin>`, `nosniff`, `no-referrer`, `no-store`, a `Permissions-Policy` denying every feature; the ticket path segment is redacted from logs. (ADR-0033 D7; R10)
- **D-25:** Mermaid 12.2.0 `dist/mermaid.min.js` (5.2 MB, SHA-256 `a8a6a6f805b074a8261a2825c86f99c8054acb3b35f50bb7e24a4f9f2c3c3b9f`) is vendored unmodified once under `src/Autonogrammer.UI/wwwroot/lib/mermaid/` with `VERSION.txt` and `LICENSE` in the `lib/xterm/VERSION.txt` format, linked as an embedded resource on desktop; a test hashes the embedded bytes; host script uses `securityLevel: 'strict'`, `startOnLoad: false`, `maxTextSize` 50000, `maxEdges` 500 (key names confirmed by hostile fixtures); desktop CSP carries `script-src` hashes for bundle and host script and no `'unsafe-inline'`; missing or hash-failing bundle is `Unavailable(MermaidAssetMissing)` and shows source; the asset sits behind `IMermaidAssetProvider`. (ADR-0033 D7; OQ-400)

### Network and storage approval
- **D-26:** Default is no network and no storage. Declared origins are requests only: `https`, host name only (no IP literal, `localhost`, private, link-local or metadata address, user info, wildcard or non-default port), at most 5, others rejected at write time. The panel shows a banner and "Review access"; the dialog shows ASCII (punycode) and decoded forms, marks mixed script, labels the reason "Written by the agent", offers "Allow for this session", "Allow for this version", "Deny" (focus on Deny, Escape denies, never by timeout). (ADR-0033 D8; AG-71-17)
- **D-27:** A grant is bound to `(ArtifactId, Number, ContentSha256, origins, scope, device, time)`; a new version asks again; "this session" is in memory; approved hosts change the policy and the desktop resource-request allowlist; "Access" revokes and rebuilds the surface. `permissions.storage` accepts `none` only (notice and `warnings` entry otherwise). (ADR-0033 D8)

### Persistence, API and limits
- **D-28:** Local store (desktop, authoritative): `<stateRoot>/cowork/artifacts/<account tenant>/<ArtifactId>/` with `artifact.json`, per version `v0001.json` and `v0001.bin`; `<account tenant>` is the lowercase hex of the first 16 bytes of SHA-256 of the account id; `FileMode.CreateNew`, temp file mode 0600 in a 0700 folder then rename (the `FileSettingsStore` pattern), one lock per artifact, head derived from the highest version file. (ADR-0033 D9)
- **D-29:** Account store tables `artifacts`, `artifact_versions`, `artifact_grants` live in migration M0006 `cowork` (phase 68 U3) with `CHECK (octet_length(content) <= 5242880)`; flat names, no RLS, every query filters `account_id`, content `bytea`, regular tables; U3 writes `PostgresArtifactStore` over an `NpgsqlDataSource` from the host and no migration. (ADR-0033 D9; R3, R14)
- **D-30:** Sync is one setting, off by default (R4, OQ-343): until enabled only metadata (id, title, kind, version count, timestamps, hashes) reaches the account store; `PUT /cowork/artifacts/{id}/versions/{n}` is idempotent by hash (same bytes 200, different bytes for an existing number 409; the desktop keeps its copy as a new artifact); the web head shows "sync is off"; signed out means no artifacts. (ADR-0033 D9; brief 71 AG-71-19)
- **D-31:** Routes live in module `Api/Cowork/Artifacts`, owner-scoped (another owner's id is the same 404, the `FindOwnedSessionAsync` pattern), use the `cowork_disabled` pattern, and are `GET /cowork/artifacts`, `GET /cowork/artifacts/{id}`, `GET .../versions/{n}`, `GET .../versions/{n}/content`, `PUT .../versions/{n}`, `DELETE /cowork/artifacts/{id}`, `POST .../render-tickets`, `GET` and `PUT .../grants`, anonymous `GET /cowork/artifact-render/{ticket}`; `.../content` always answers `application/octet-stream`, `attachment`, `nosniff`; the OpenAPI transformer lists the render route `security: []` with its own limiter partition. (ADR-0033 D9; R10)
- **D-32:** Limits are validated options naming the key: text kinds 512 KiB per version, Image 5 MiB, Mermaid 128 KiB, Svg 256 KiB, 200 versions per artifact, 500 artifacts and 256 MiB per account, title 120, change note 280; PUT body 6 MiB for images, 1 MiB otherwise; failures are typed `too_large` or `quota_exceeded`, never truncation. (ADR-0033 D9; OQ-407)
- **D-33:** Counter `autonogrammer.cowork.artifact.count` tagged `kind` and `result` (`created`, `updated`, `rejected`, `conflict`); logging with `LoggerMessage.Define`, EventId block 7100 to 7199 (proposed), artifact id only; audit events `artifact.created`, `artifact.updated`, `artifact.grant`, `artifact.revoke` (closed `cowork_events.kind` list from 68 U3) carry hashes and origins, never content, titles or account ids. (ADR-0033 D9, D8; R15)

### Export, diff, copy, accessibility, transcript
- **D-34:** Export writes a version as a file or an artifact as a deterministic zip (`System.IO.Compression`: `manifest.json`, `v0001/<name>.<ext>`, fixed entry timestamps from `CreatedAt`, sanitised names of at most 80 characters, de-duplicated, total size capped; no import, so no zip-slip); defaults are safe: Svg sanitised, Csv formula cells neutralised with a leading apostrophe, Html with the panel's meta policy first and a leading DOCTYPE dropped, others as stored; "Original" is a second choice with a risk note. (ADR-0033 D10; AG-71-6)
- **D-35:** Diff of text kinds uses DiffPlex 1.9.0 (`InlineDiffBuilder`, `SideBySideDiffBuilder`) capped at 20,000 lines and 512 KiB per side, off the UI thread, cancellable; over the cap counts only; binary kinds diff as metadata. Copy is duplicate-artifact plus user-initiated clipboard copy of a text version. (ADR-0033 D10)
- **D-36:** The panel is a labelled region ("Artifact: title, version 3 of 5") in the F6 cycle with a toolbar (version picker, Diff, Copy, Export, Edit, Access, Stop, Close), every control at least `Autonogrammer.Size.TargetMin` with an `AutomationProperties.Name`; frame `title="Generated content: {title} ({kind}), sandboxed"`, "Skip generated content" link before and "Return to chat" after; one polite live region; a new version never moves focus; first artifact opens the panel (`Cowork:Artifacts:AutoOpen`); diff lines carry "Added"/"Removed" text and `+`/`-` in addition to `DiffAdded`/`DiffRemoved`; no new colour role; dialogs trap and restore focus. (ADR-0033 D11; AG-71-21)
- **D-37:** `ArtifactBlock` (kind `artifact`; `ArtifactId`, `Version`, `Title`, `ArtifactKind`, `Action` Created or Updated) is an additive block that renders a card opening the panel, never content inline; old readers get `UnknownBlock`; the scaffold step bumps `ContractVersion` 1.5.0 to 1.6.0 once and this phase edits no `ContractVersion.Current`. (ADR-0033 D13; R9)

### Layout, options, registry
- **D-38:** Options section is `Cowork:Artifacts` (`Surface` `Auto`, `Scripts` `OnOpen`, `AutoOpen`, `MaxImageBytes`, `MaxWritesPerMinutePerSession`, `RenderTicketKeys`, limits) with a validator. The artifact panel is `IDockPanel` content registered with `CoworkDockHost` (tab strip beside Browser). (ADR-0033 D5, D7, D9; R7, R11)
- **D-39:** `Cowork.Artifacts` (L2, pure, no I/O, web-safe) and `Cowork.Artifacts.Stores` (L2) are created and registered by the scaffold step; same-layer tuples `Stores -> Artifacts` and `UI -> Artifacts` only; Presentation stays on `Contracts/Artifacts` types; this phase adds code and edits only rows the manifest marks "per phase" (`docs/api/openapi.json`, `scripts/web-smoke/*`, `vercel.ts` and CSP scripts, Demo fixtures, notices when Mermaid is admitted). (brief 71; R14, R17)

## Specific Ideas

- Source product reference: Anthropic Cowork artifacts opened beside the chat with export to Word, PDF, Markdown, HTML and zip (report 06 C19, line 80); live artifacts are deprecated (C20, line 81) and omitted.

No network.`, "static view", "sync is off", "This version of Autonogrammer cannot display this kind", "Anything you type into this artifact can be sent to these hosts.
