# Phase 45 Context: Agent Loop Stage Sources

Milestone v0.14.0. Requirements AL-05 to AL-08. Depends on Phase 44. Decision record: `docs/decisions/ADR-0012-agent-loop-plugins.md`. Design: `docs/plans/agent-loop/agent-loop-design.md` and the dossiers beside it. Guide: `docs/plugins.md`.

This context was written after the work (2026-10-26). It records the decisions found in the code, the tests and the commit `a2b4407` feat(45-01), not decisions taken in a discussion. Where a decision is read from code, the file is named.

## What this phase does

It turns what the four plugins write and serve into stage events and task context, and keeps sessions in a catalog that survives a restart. Every plugin that is missing or failing gives a Degraded or Unavailable event with a plain-text reason, never an exception.

Success criteria are in `.planning/ROADMAP.md` (Phase 45, criteria 1 to 6). The criteria table with status is in `45-SUMMARY.md`.

## Decisions found in the code

| ID | Decision | Where it is in the code and tests |
|----|----------|-----------------------------------|
| D45-1 | Stage events are data from `Autonogrammer.Contracts.Agents` (`StageEvent`, `StageSource`, `StageStatus`). Each source implements `IStageSource` and returns an async sequence for a `StageObservationScope` (one session). Nothing is added to `StreamEvent`. | `src/Autonogrammer.Harness.AgentLoop/Stages/*`, `Substrate/*`, `Gsd/*` |
| D45-2 | Observers poll side channels and never throw into the caller. A read failure is a Degraded event; an unusable source is Unavailable; cancellation ends the sequence quietly. | `CompositeStageSourceTests.ThrowingChildBecomesOneDegradedStageWhileTheOthersKeepRunning`, `CancellationCompletesQuietlyAndDisposesEveryChildEnumerator`; per-observer cancellation tests |
| D45-3 | `CompositeStageSource` merges the children into one sequence, keeps each child's order, emits an unchanged event for one key only once (`StageEventDeduper`), and holds the producer back through a bounded channel of 256 events instead of dropping events. A child that keeps failing yields exactly one Degraded event. | `CompositeStageSource.ChannelCapacity`, `CompositeStageSourceTests.SlowConsumerHoldsTheProducerBackWithoutLosingOrReorderingEvents`, `ChildThatKeepsFailingProducesExactlyOneDegradedEvent`, `UnchangedEventsForOneKeyAreEmittedOnlyOnce` |
| D45-4 | Text from plugin files is never trusted. `StageText` replaces control and format characters, trims and caps text at 200 characters without splitting a surrogate pair. Free error text from a swarm file is never shown, only an error code. | `StageText.MaxDetailLength`, `StageTextTests`, `SwarmRunTableTests.OnlyAnErrorCodeIsShownNeverFreeErrorText`, `SwarmLiveObserverTests.NoFreeTextFromTheFilesReachesAnEvent` |
| D45-5 | Ultrathink has no live progress (D9 of ADR-0012). The observer reads the planner's session file from `<session>/ultrathink/sessions/` every 500 ms. The stage is Pending until the record exists, then Succeeded with node, wave and clarification counts and the graph id; a fallback record is Degraded; a partial tracking status adds a Degraded tracking stage. Files over 2 MiB are Degraded without being parsed. Planning switched off is Skipped and nothing is read. | `UltrathinkStateObserver`, `UltrathinkPlanParser.MaxFileBytes`, `UltrathinkStateObserverTests`, `UltrathinkPlanParserTests` |
| D45-6 | Swarm state comes from `<SWARM_DIR>/.swarm/live.json` (schema `swarm.live.v1`, at most 1 MiB) and the tail of `events.jsonl`, polled every 500 ms. The tail reads at most one 256 KiB chunk per poll, skips lines over 64 KiB, waits for a line terminator, and re-reads from the start when the file shrank. A run never moves backwards; a retry is a new run; at most 256 runs are kept (finished runs are dropped first). All runs finished without failure is Succeeded; with a failure the parent is Degraded. | `SwarmLiveObserver`, `SwarmEventTail`, `SwarmRunTable`, and their tests |
| D45-7 | The Substrate gateway is the only Substrate client in the host. It accepts an https address or a loopback http address, refuses redirects and responses from another origin, caps a response at 1 MiB, times out at 10 s, reads the bearer token for every request (so a rotated token is used) and never puts it in a message, log line or exception. A query without a scope is refused before anything is sent. | `SubstrateGateway`, `SubstrateEndpoint`, `SubstrateGatewayTests` (for example `ARedirectIsRefusedNeverFollowedAndItsTargetIsNotReported`, `TheTokenNeverAppearsInAnExceptionOrAnyLogLineOnAnyFailurePath`, `QueryRefusesAnUnscopedOrUnboundedQueryBeforeSendingAnything`) |
| D45-8 | The Substrate observer emits health, brief, lease and ledger stages. It polls every 2 s, backs off by doubling up to 30 s when the server is unhealthy and recovers by itself, refreshes the brief at most every 30 s, and reads the ledger only for the session's graph (or the session), never unscoped. It never shows ledger `summary` or `payload` text, only timestamp, surface, kind, actor and the payload action, item and outcome. A lease of another holder is shown only as holder surface and expiry. | `SubstrateStageObserver`, `SubstrateStageObserverTests` |
| D45-9 | Task context merges the GSD phase (from `gsd-tools` `roadmap.analyze`) with the Substrate brief, shared memory and lessons. The Substrate title wins. Substrate entries of another scope are discarded with a warning; a graph id or repository name that could inject another scope is never queried. Notes are one line of plain text capped at 500 characters. A part that fails is one warning and the rest of the context is still returned. | `GsdTaskContextSource`, `SubstrateContextReader`, `GsdTaskContextSourceTests`, `SubstrateContextReaderTests` |
| D45-10 | GSD tools run as `node <gsd-tools.cjs> query ...` without a shell, with stdin closed, a 10 s timeout and a 4 MiB output limit; a timeout or cancellation kills the whole process tree. The result is cached until a `.planning` file changes or 60 s pass. The tools are located by an explicit setting, then `GSD_CORE_HOME`, then the Kimi layout locations. A workspace without `.planning` is Unavailable and spawns nothing; the phase poll is every 5 s and emits only changes. | `GsdProcessRunner`, `GsdToolsClient`, `GsdToolsLocator`, `GsdStateObserver`, and their tests |
| D45-11 | The session registry is one JSON file (schema version 1, at most 1 MiB, at most 200 sessions). It is written through a temporary file and a rename, with owner-only permissions; a temporary file left by a crash is ignored; an unusable, oversized or unknown-version file is renamed `<file>.quarantined-<utc timestamp>` and the registry starts empty; unknown members are skipped and unusable entries dropped. After a restart, a session that was Running becomes Lost, and a Running session whose heartbeat is older than 45 s is marked Lost too. A `Touch` updates memory always but writes at most once per second. The native resume reference is stored and never printed, logged or put in a summary. | `AgentSessionRegistry`, `AgentSessionStateFile`, `AgentSessionRegistryTests` (for example `RecoverAfterRestartMarksOnlyRunningSessionsAsLostAndPersistsIt`, `UnusableFileIsQuarantinedWithTheExactNameAndTheRegistryStartsEmpty`, `ResumeReferenceIsNeverPrintedLoggedOrExposedInSummariesButIsPersisted`) |
| D45-12 | Closing a session removes its record but keeps its state directory; deleting a state directory is a separate call that refuses an id that is not one safe path segment and never follows a link. Session ids are lowercase base32 names. | `AgentSessionRegistryTests.CloseRemovesTheRecordButKeepsTheStateDirectory`, `DeleteStateDirectory*` |
| D45-13 | A session never reads another session's directory, workspace or Substrate scope. | `UltrathinkStateObserverTests.ASessionNeverReadsAnotherSessionsDirectory`, `SwarmLiveObserverTests.ASessionNeverReadsAnotherSessionsSwarmDirectory`, `GsdStateObserverTests.EachSessionObservesOnlyItsOwnWorkspace`, `GsdTaskContextSourceTests.EachScopeGetsItsOwnWorkspacePhaseAndTheReaderSeesTheSameScope`, `SubstrateContextReaderTests.OnlyTheSessionsOwnGraphAndRepositoryAreEverQueriedAndEveryQueryNamesItsScope` |
| D45-14 | A steering action is recorded in the Substrate ledger as an `events_emit` event of kind `note` with `payload.action` `steer`. The operator text is never sent, only its length and a 12-hex digest prefix. An unreachable server is a Skipped result with a reason, any other problem is Failed, and the recorder never throws. Substrate does not deliver the steer, and no text in Autonogrammer says it did. | `SubstrateSteeringRecorder`, `SubstrateSteeringRecorderTests` |

## Later changes to this phase's code

- Phase 48 added a session kind (chat or omp terminal) to the registry file without a schema version bump: a file written before the kind existed loads every session as a chat (`AgentSessionKindTests.AFileWrittenBeforeSessionsHadAKindLoadsEverySessionAsAChatWithoutQuarantine`), and `UltrathinkStateObserver` gained a mode for terminal sessions that have no ACP session id.
- Phase 48 added the plugin connection stage source and the steering channel beside these sources (`Connection/`, `Steering/`).

## Not in scope

The panel that renders these events is Phase 46. The delivery of a steering message into a running turn is Phase 49. Live Ultrathink progress does not exist upstream (OQ-67). Substrate live delivery is unmerged upstream (OQ-66).
