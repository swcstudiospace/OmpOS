## Decisions applied (CONTEXT D1 to D4)

- D1: one shared reader for the ACP and remote line paths; the cap is characters, the RPC precedent's unit is bytes.
- D2: the same reader and the same 1 MiB cap for remote frame data; the transport-drop `break` at `RemoteEngineHost.cs` is unchanged (Phase 25.5).
- D3: the probe mirrors the launcher's 4096-character limit and kill-on-overflow.
- D4: 4 MiB for vendor bodies; a separate helper in `Autonogrammer.Sandbox.Abstractions`, not shared with the web head (see gaps).

## Deviations and corrections, stated

- The reader reads one character at a time. A `TextReader` cannot push back, so a chunked read would consume bytes after the newline. Cost: one async read per character over a buffered reader. Not benchmarked.
- Line endings narrowed: only `\n` ends a line, and one `\r` before it is stripped. A lone `\r` is no longer a terminator. JSON frames cannot contain a raw CR outside strings, and SSE already stripped a trailing CR, so no real frame changes. This is a behaviour change, stated here.
- The version probe's first two drafts failed the analyzer. CA2025 flagged a pipe-read task that could outlive the process disposal. The final shape awaits both pipe reads in a `finally` inside a helper that the caller awaits inline, and reports overflow as a value. No suppression.
- Two bounded-content tests were written against the default `SandboxProviderOptions`, which fail closed on per-sandbox credentials. They exercised the credential refusal, not the body read. They now pass `PerSandboxCredentials = false`, the documented non-credential path. One assertion pinned the wording "exceeds"; it now asserts the limit value.
- Gate failures along the way, all fixed in code or tests: CA2016 (token not forwarded), CA2000 (test responses), CA2025 (probe), CA1802 (constant), IDE0005 (unused using), CA2007 and MA0004 (missing ConfigureAwait).
