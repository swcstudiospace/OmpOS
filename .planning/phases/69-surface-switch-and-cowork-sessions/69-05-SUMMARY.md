# Phase 69 Plan 05 Summary

**Cowork summary routes are owner-scoped and the Kanban list reads only Code rows through CodeBoardSource.**

## Accomplishments

- PUT `/cowork/sessions/{id}` stores an empty-message session with `SessionSurface.Cowork` and the token owner. DELETE closes that row. A foreign row and an absent row share the session-not-found 404. The 201st open summary is 409. Titles are capped at 200 characters. The `cowork-sessions` limiter answers 429 with Retry-After.
- `CodeBoardSource` is the Code listing for `GET /sessions`, `GET /account/board` and `CatalogChangeDetector`.
- `docs/api/openapi.json` was regenerated by the API build and includes PUT and DELETE `/cowork/sessions/{id}`.
- The published service worker leaves `/cowork/` to the network.

## Verification

- CoworkSessionEndpointsTests: 10 passed.
- CodeBoardSourceTests: 1 passed.
- AccountBoardSurfaceTests: 2 passed (in-memory and throwaway PostgreSQL).
- ServiceWorkerRulesTests: 9 passed.
- `python3 scripts/ci/check-openapi-breaking.py --base HEAD` exited 0. The default base `origin/main` still reports `/board` removed; that removal predates this plan.

## Gaps

- `ISessionRepository` has no delete. DELETE closes the row. `GET /account/sessions` includes closed rows, so a deleted summary can still appear there until a real delete exists.
- Title, project id and device id are not columns on `sessions`. They are returned on PUT and kept in the process cache.
- Official `ag-dotnet test` of the API project currently fails to build `Autonogrammer.Cowork.Artifacts.Stores` (sibling, not this plan). Tests above were run with `BuildProjectReferences=false` against the last built stores assembly.

## Open items

GET /account/sessions exists and lists labelled rows. No deferral.
