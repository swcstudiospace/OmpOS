# Phase 25.2 Context: Web Head Trust and Stream Bounds (fix F-A)

Source: 25.1-FINDINGS.md section 4 (H-1, H-3), section 5 (M-11, M-14), section 6 (ApiSessionClient.cs:37). The owner accepted all eight fix phases on 2026-10-26; F-A runs first.

## Decisions

- D1 (H-1): the `?apiBaseUrl=` query override is honoured only when its host is loopback (http or https). A non-loopback override throws InvalidOperationException naming the query parameter. The configured `Api:BaseUrl` keeps its current validation (https, or loopback http). Reason: the owner accepted the fix, not the choice between keeping and removing the override; keeping it for loopback preserves the local-development use stated in the resolver's doc comment. Conservative default, recorded.
- D2 (H-3): the SSE reconnect budget counts consecutive connections without progress. A connection that yields at least one event resets the budget to zero.
- D3 (M-14): SSE line length is capped at 1 MiB characters and frame data at 4 MiB characters. Exceeding either throws ApiClientException with a bounded message, so the stream fails loudly instead of growing without limit.
- D4 (ApiSessionClient.cs:37 and error bodies): API success bodies are capped at 16 MiB (transcripts can be large); error bodies at 1 MiB. The check uses Content-Length first, then counts bytes while reading.

## Assumptions

- Subagents edit files only; the gate runs once per phase from the lead, and it is the only build, test, and format run.
- Existing tests that pin the non-loopback override (ApiBaseUrlResolverTests lines 14 and 108 at the time of reading) change with the deliberate contract change, and each changed test states the new contract.
