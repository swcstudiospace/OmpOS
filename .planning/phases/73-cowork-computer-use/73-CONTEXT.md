# Phase 73: Cowork Computer Use - Context
Source: docs/plans/v0.16.0-research/briefs/73-computer-use.md
**Gathered:** 2026-10-28
**Status:** Ready for planning

<domain>
## Phase Boundary

Milestone v0.16.0. Requirements AG-73-1 to AG-73-24. Cowork can look at and operate the user's own desktop (X11 verified here; Windows and macOS compile-checked) through 15 `computer_*` tools behind one policy gate, with per-application grants, local approval, a kill switch, an always-visible indicator and a local audit log. Off by default, never in Code mode, never in the cloud, never remotely approvable. Record: `docs/decisions/ADR-0035-cowork-computer-use.md` (Proposed 2026-10-28).

Work units (brief 73, file-disjoint): U1 contracts and options (AG-73-1, 3, 10, 18 states); U2 gate, grants, catalogue, executor (AG-73-2, 4 to 9, 11, 12); U3 frames, audit, tools (AG-73-13, 14, 15); U4 X11 backend and hotkey (AG-73-16, 17, 18); U5 Windows and macOS backends (AG-73-19, 20, 21 sources); U6 UI (AG-73-8, 12, 21, 22 UI side, 23, 24).

Depends on (index phase table): 67 (sign-in gate, `SessionSurface`), 70 (`Cowork.Abstractions`, tool host, overlay), 74 (relay refusals, capability flag `computer_use`), 72 optional (shared approval service only if ADR-0032 defines one). Note: the index also lists 73 among 74's dependencies (tool classes, `AllowDispatchSessions`); only the AG-73-22 UI side touches that seam, the rest of this phase needs 67 and 70 only [INFERENCE].

Must NOT do: no new service or NuGet package; no `computer.*` Dispatch operation and no `computer.task` (R1); no relay primitive that reaches a backend; no remote approval; no Computer Use in Code mode, the API, the web head, the cloud worker, Android or iOS; no Wayland backend; no use of omp's native `computer` prelude; no Cua Driver; no registration of projects beyond rows the scaffold manifest marks "per phase" (R17); no ledger or `cowork_events` write (R15); no Mac App Store distribution.

</domain>

<decisions>
## Implementation Decisions

### Placement, layers, default state
- **D-01:** Computer Use runs only in the desktop head's process; the API, web head and cloud worker never load it (`Autonogrammer.Web` may not reference process-spawning assemblies). Five plain `net10.0` projects (so Windows and macOS code compiles on Linux): `Autonogrammer.Harness.ComputerUse.Abstractions` (L1: `IComputerUseBackend`, `IComputerActionGate`, ports, records, enums, denial codes, `CoordinateMap`, `ComputerUseOptions`, no process, no I/O), `Autonogrammer.Harness.ComputerUse` (L2: gate, grants, catalogue, sensitivity classifier, rate limiter, kill-switch coordinator, executor, frame pipeline, audit log, provider, `FakeComputerUseBackend`, DI; references no OS backend), `.X11`, `.Windows`, `.MacOS` (L2). `ComputerUse` references `Cowork.Abstractions` (L1), so no `SameLayerAllowed` tuple. (ADR-0035 D1; manifest rows 3, 10 to 13)
- **D-02:** `ComputerUseOptions` (section `Cowork:ComputerUse`, R11) defaults `Enabled=false`, uses `ValidateOnStart` and a validator that names keys never values (as `CloudOptionsValidator`); the feature also needs an account session (ADR-0030) and Cowork mode, and with any of the three missing the `computer` provider is `Unavailable` and no `computer_*` tool is offered. (ADR-0035 D1; R11; AG-73-10)
- **D-03:** The Android, iOS, web, API and cloud-worker heads register `NullComputerUseBackend` (availability `UnsupportedPlatform`, message id `computer.unavailable.platform`); `computer_*` is not registered there and `computer_status` and settings say why. Typed states: `Available`, `Disabled`, `UnsupportedPlatform`, `WaylandUnsupported`, `NoDisplay`, `PermissionMissing(kind)`, `InputInjectionUnavailable`, `KillSwitchUnavailable`, `IndicatorUnavailable`, `AuditUnavailable`, `SecureDesktop`, each with one `Remediation` id resolved to text in Presentation. (ADR-0035 D10 "Elsewhere"; AG-73-18)

### Backend interface
- **D-04:** `IComputerUseBackend` has `Platform`, `Capabilities`, `GetAvailabilityAsync`, `GetPermissionStatusAsync`, `RequestPermissionAsync`, `ListDisplaysAsync`, `ListWindowsAsync` (bottom-to-top z-order: id, pid, `AppIdentity`, title, bounds, minimized, focused, `isOwnProcess`), `GetPointerAsync`, `CaptureAsync` (native BGRA), `InjectAsync(InputPrimitive)` (PointerMove, PointerButton down/up, Scroll, Key down/up, TypeText), `ReleaseAllInputAsync`, `ReadClipboardTextAsync`, `WriteClipboardTextAsync`; every I/O member is `ValueTask`, ends in `Async`, takes `CancellationToken` last with no default; coordinates crossing it are native virtual-desktop pixels; clipboard goes through a head-provided `IClipboardTextPort`; failures are `ComputerBackendException` with a `ComputerFailure` category (`PermissionMissing`, `Unavailable`, `TargetGone`, `Elevated`, `SecureDesktop`, `Timeout`) and a message free of titles and text; the semantics of click, drag and chord belong to the executor; a backend never decides policy. (ADR-0035 D2; AG-73-1)

### The gate
- **D-05:** `IComputerActionGate.AuthorizeAsync(ComputerActionRequest)` returns `Allowed(ComputerActionTicket)` or `Denied(DenialCode, UserMessageId)`; `ComputerActionExecutor` (internal to `ComputerUse`) is the only type that calls the backend except for status reads; injection needs the single-use ticket bound to the action hash, valid 2 s; `ComputerUseBoundaryTests` in the architecture project fails the build if any other type references `IComputerUseBackend` or `InjectAsync`; time comes from an injected `TimeProvider`; an exception in `AuthorizeAsync` is `Denied(InternalError)`. (ADR-0035 D3; AG-73-2)
- **D-06:** Evaluation order, first failing step wins, stable `DenialCode` each: (1) enabled, signed in, opted in (`Disabled`, `NotOptedIn`), kill-switch trip or revocation (`Revoked`); (2) platform and permissions (`PlatformUnavailable`, `PermissionMissing`), kill switch registered and indicator visible (`KillSwitchUnavailable`, `IndicatorUnavailable`); (3) frame valid, `frame_id` is the session's latest and layout unchanged (`StaleFrame`), coordinates inside (`OutOfBounds`); (4) host-observed target from `ListWindows` at decision time, never from the model; (5) denylist and own windows (`DeniedApplication`, `OwnWindow`), grant lookup (`NoGrant`), tier (`TierTooLow`), forbidden chords (`ForbiddenChord`), `ElevatedTarget`, `SecureDesktop`; (6) rate and step limit (`RateLimited`, `StepLimit`), `UserTookOver`, `ImageBudget`; (7) sensitivity, then `IComputerApprovalPrompt` (`ApprovalDenied`, `ApprovalTimeout`, `NoLocalApprover`); (8) write-ahead audit record (`AuditUnavailable` on failure), inject, outcome record. Every denial has a message id. (ADR-0035 D3; AG-73-3)
- **D-07:** One process-wide lock serialises actions, so no injection happens while an approval prompt is open. (ADR-0035 D3, D5)

### Grants, catalogue, sensitivity, approval
- **D-08:** A grant is (session, `AppIdentity`, tier, origin, expiry, `AutoApproveTyping`); `AppIdentity` is bundle id (macOS), executable file name plus signer where available (Windows), `WM_CLASS` plus the basename of `/proc/<pid>/exe` (X11); tiers `ViewOnly` (screenshot, zoom, window listing), `ClickOnly` (plus pointer move, click, drag, scroll; no keyboard, no clipboard), `Full` (plus type, chords, clipboard); the model cannot create a grant, `computer_request_access` only shows the user a request labelled as an agent statement. (ADR-0035 D4; AG-73-4)
- **D-09:** Default tier comes from a data catalogue `computer-use-apps.json` (source-generated JSON, rows as data like ADR-0019): browsers `ViewOnly` (Browser Use is the browser path), IDEs and editors `ClickOnly`, mail and messaging `ViewOnly` (raised: every click and key asks), everything else `Full` after the grant dialog. The built-in denylist (terminals and shells, password managers and keychains, OS settings and policy prompts, trading and wallet applications, the Autonogrammer process) has no override in v0.16.0; users may add entries, never remove; deny wins over grant; a grant ends with the session, after 8 hours, or when the application's window set changes identity; `computer_list_windows` returns titles only for granted applications, others appear as category counts. (ADR-0035 D4; AG-73-5, 6; OQ-393)
- **D-10:** Hard-denied chords: Win+R, Win+X, Alt+F2, Ctrl+Alt+T, Cmd+Space, Ctrl+Alt+Del, Ctrl+Alt+Backspace, virtual-terminal switches and the kill chord. (ADR-0035 D4)
- **D-11:** Sensitivity is computed from host-observed facts only (window title, application category, key chord, action kind); no backend reports focused-element traits (`FocusedElementInspection` off, OQ-384), so credential fields are detected by title patterns in the catalogue (sign in, log in, password, passcode, one-time code, token, secret, unlock; English first) and by policy: typing asks unless the user ticked "allow typing in this application for this session"; credential-titled windows always ask. Always confirmed: file deletion, purchase windows (checkout, payment, pay now, order, subscribe, billing), mail or messaging raised above `ViewOnly`, any clipboard read or write, every first action per application, every action whose grant has Dispatch origin. (ADR-0035 D5; AG-73-7)
- **D-12:** `IComputerApprovalPrompt` is the only UI port; the dialog shows host-observed facts (application name and identity, window title sanitised and quoted at 80 characters, the action in host words, a 160 by 120 crop with crosshair or the character count plus first 40 sanitised characters labelled "agent text", origin Local or Dispatch with device name, the user's security phrase); choices Deny (default focus), Allow once, Allow for this session; no timer ever allows and it times out to deny after 120 s. Own-process windows are hard-denied as targets (re-resolve after the move and before button-down, abort on change or `isOwnProcess`) and masked in every model frame; a remote approval is accepted from no channel; the dialog and indicator are keyboard operable, named, use text and shape as well as colour. Trusted-input provenance cannot be provided and is recorded as an open risk. (ADR-0035 D5; AG-73-8, 9)

### Limits, kill switch, indicator, takeover
- **D-13:** Options: 60 actuating actions per minute (token bucket, burst 10), 300 actions per session then a "continue" prompt adding 100, 5 consecutive failures pause the loop, `computer_wait` at most 5 s, `type` at most 2000 characters per call sent in runs of 16 with a token check and foreground-window re-check between runs. (ADR-0035 D6; AG-73-10)
- **D-14:** Kill switch default Ctrl+Alt+Shift+Escape (validator: at least two modifiers, not in the forbidden list; OQ-386); each backend implements `IGlobalHotkeyRegistrar` on its own thread and OS connection; registration is confirmed before the first actuating action of a session (else `KillSwitchUnavailable`, refuse to arm); a trip cancels the revocation token, calls `ReleaseAllInputAsync`, sets `Revoked` (denies everything until the user re-arms), cancels the Cowork turn, updates the indicator and writes an audit record; the executor checks the token between primitives; the trip is also reachable from the indicator's Stop, the Cowork session Stop and the tray menu. (ADR-0035 D6; AG-73-11)
- **D-15:** The indicator is a top-most, non-focusable window on every display edge: "Autonogrammer is controlling this computer" with session name and kill chord, an "armed, idle" label and "Remote (Dispatch): <device>" for Dispatch origin; before each action the gate confirms it is in the window list and not minimised, else `IndicatorUnavailable`. User takeover: a pointer displacement over 24 px (option) since the executor left it pauses with `UserTookOver` until the user resumes. (ADR-0035 D6; AG-73-12)

### Audit
- **D-16:** `ComputerAuditLog` writes JSON Lines under `computer-use/audit/YYYY-MM-DD.jsonl` in the state directory, owner-only (0600 or owner ACL), append-only with `FileShare.Read`, flushed per record; each record has `seq`, UTC time, session id, tool, host-built action summary, `AppIdentity`, title truncated to 80, decision and denial code, approval origin, outcome, frame SHA-256 and `prev` (SHA-256 of the previous line); a record is written before injection and one after, and a failed write denies. Typed text is length and SHA-256 only (`Audit:TypedText=Off`), clipboard contents never, thumbnails default off (`Audit:Thumbnails`, 320 px PNG, `AuditView` redaction); retention 30 days, rotated daily, deletion logged. The log never leaves the device and nothing goes to `cowork_events` or the ledger. (ADR-0035 D7; R15; AG-73-13)
- **D-17:** Every call is also written to `ICoworkToolAudit` (no arguments, no bytes) whose desktop sink is the local owner-only hash-chained JSONL `FileCoworkToolAudit`, in addition to the more detailed log of D-16. (ADR-0035 D8; R15)

### Tool family
- **D-18:** One provider `ProviderId = "computer"` registered with `CoworkToolHost` only when D-02 conditions hold; tools `computer_status`, `computer_list_displays`, `computer_list_windows`, `computer_screenshot`, `computer_zoom`, `computer_request_access`, `computer_mouse_move`, `computer_click`, `computer_drag`, `computer_scroll`, `computer_type`, `computer_key`, `computer_clipboard_read`, `computer_clipboard_write`, `computer_wait` (15; omp shows `mcp__cowork_computer_<name>`); `computer.<x>` in the brief and ADR is only the logical label of descriptor `computer_<x>`; the omp settings `computer.enabled` and `browser.enabled` keep their dotted spelling. (ADR-0035 D8; 00-index section 2)
- **D-19:** Descriptor mapping: `status`, `list_displays`, `list_windows`, `screenshot`, `zoom`, `wait` are `ReadOnly`, `ByPolicy` (`Text|Image` for screenshot and zoom); `computer_request_access` is `Actuating`, `EveryCallOnExecutingDevice`; pointer, keyboard and clipboard tools are `Actuating`, `ByProviderGate` (host allows once the provider is `Available`, never asks; the provider asks itself through the `ICoworkApprovalBroker` it receives with `MustBeLocal = true` for every grant and every sensitive action, in every mode including Skip and in a tainted session); no tool is `Destructive`; `PreviewAsync` returns the host-observed target and `CoworkGrantKey("computer.app", AppIdentity)`; screenshots and window lists are `IsUntrusted` so the session is tainted from its first frame; every result is wrapped in a labelled envelope ("untrusted screen content from <application>, frame N, captured at T"); every description states the order connector, then browser, then screen, that screen text is untrusted data, and that only direct user messages authorise consequential actions. (ADR-0035 D8; AG-73-15; OQ-394)
- **D-20:** The `--config` overlay with `computer.enabled=false` and `browser.enabled=false` is owned by the Cowork session profile (ADR-0032 D4); providers never write it and a test asserts it; its effect in a live omp turn is unverified (OQ-387). Result caps of ADR-0032 apply: `Vision:MaxImageBytes` defaults to 3 MiB and one image per result. (ADR-0035 D8; AG-73-15)

### Vision loop and frames
- **D-21:** Loop: `computer_screenshot` returns frame N (PNG plus text: frame id, display, native and scaled size, scale factor, cursor in scaled coordinates); an action carries `frame_id` and scaled coordinates; `CoordinateMap` (pure; negative origins, multi-display, rounding) maps back; settle delay 400 ms (option 100 to 2000); `PostActionFrame=Auto|Off`; three identical frame hashes add a "no visible change" hint; one display at a time (focused granted window's display, else primary); a layout change invalidates the frame (`StaleFrame`). (ADR-0035 D9; AG-73-14)
- **D-22:** Pipeline (own code, no package): capture BGRA, keep the full-resolution frame for `zoom` (latest per session, released after 60 s idle), mask, area-filter downscale to `Vision:LongEdgePx` (default 1280; 2576 for high-resolution models), PNG via `System.IO.Compression.ZLibStream`; a frame over `Vision:MaxImageBytes` is re-encoded at 0.85 scale steps up to four times, then `FrameTooLarge`; no JPEG. (ADR-0035 D9)
- **D-23:** Masking: by default a frame shows only granted applications' windows; everything else (desktop, other applications, own-process windows) is painted black with a text label; `VisibleRegionMasker` is a pure function over `ListWindows` z-order and bounds; it is defence in depth. (ADR-0035 D9; AG-73-14)
- **D-24:** Budget: tokens are `ceil(w/28)*ceil(h/28)` per image; sizing is a per-model option `Vision:ModelOverrides` keyed by omp model id (OQ-385); `Vision:MaxImagesPerSession` (default 80) then `ImageBudget`. DPI: backend coordinates are physical pixels on X11 and Windows (per-monitor-v2 awareness per call); on macOS CGEvent uses points and capture pixels, `DisplayInfo.ScaleFactor` carries the ratio; `CoordinateMap` is the only place scale is applied. (ADR-0035 D9)

### Backends
- **D-25:** X11 (decided, verifiable here) calls system `libX11.so.6`, `libXtst.so.6`, `libXrandr.so.2` through `DllImport` with `DefaultDllImportSearchPaths` and `Marshal` (no unsafe blocks), loaded from the system, never bundled; `ScreenCapture.NET.X11` (LGPL-2.1-only) and SharpHook (unresolved native licence) are rejected. One `X11Connection` owns a dedicated thread and command queue; `XOpenDisplay` uses `X11BackendOptions.DisplayName` (null reads `DISPLAY`) so tests pass a private display. (ADR-0035 D10; AG-73-16)
- **D-26:** X11 capture is `XGetImage` on the root window (ZPixmap, all planes) per display rectangle (`XRRGetMonitors`, fallback `XDisplayWidth`/`XDisplayHeight`), window captures are crops of the root capture; input is `XTestFakeMotionEvent`, `XTestFakeButtonEvent` (buttons 1 to 3, scroll 4 to 7), `XTestFakeKeyEvent`, checked with `XTestQueryExtension` (absent: `InputInjectionUnavailable`); text maps char to keysym (`XStringToKeysym`, Unicode keysyms `0x01000000 | cp`) to keycode and shift level, and a character with no mapping uses a scratch keycode remapped with `XChangeKeyboardMapping` and restored after `XSync` (a failed restore is logged and reported); pointer motion is stepped in at most 8 moves. Windows: `_NET_CLIENT_LIST_STACKING`, `_NET_WM_NAME`, `_NET_WM_PID`, `WM_CLASS`, `XGetWindowAttributes` plus `XTranslateCoordinates`; bare Xvfb falls back to `XQueryTree` with `stackingSource=XQueryTree` reported. Hotkey: a second connection and thread with `XGrabKey` over the lock-modifier combinations, an error handler turning `BadAccess` into `KillSwitchUnavailable`. `DISPLAY` unset or `XOpenDisplay` failing is `NoDisplay`. (ADR-0035 D10; AG-73-16, 17)
- **D-27:** Wayland is unavailable: a session is Wayland when `XDG_SESSION_TYPE=wayland` or `WAYLAND_DISPLAY` is set even if `DISPLAY` points at XWayland; the backend reports `ComputerAvailability.WaylandUnsupported` with message id `computer.unavailable.wayland` ("Computer Use needs an X11 session. You are signed in to a Wayland session. Sign out and choose the Xorg (X11) session on the login screen.") and registers no tool; the portal route is deferred (OQ-380). (ADR-0035 D10; AG-73-18)
- **D-28:** Windows (compile-checked only): `SendInput` with `MOUSEEVENTF_ABSOLUTE | MOUSEEVENTF_VIRTUALDESK` (pure normalisation to 0 to 65535), `KEYEVENTF_UNICODE` text, scan codes for chords; UIPI check by `OpenProcess` `PROCESS_QUERY_LIMITED_INFORMATION` plus `GetTokenInformation` `TokenElevation` gives `ElevatedTarget`, a failed `OpenInputDesktop` gives `SecureDesktop`; capture is GDI `BitBlt` with `SRCCOPY | CAPTUREBLT` (no `Windows.Graphics.Capture`, no `ScreenCapture.NET.DX11`); windows via `EnumWindows`, `GetWindowTextW`, `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`, `EnumDisplayMonitors`, `GetDpiForMonitor`; hotkey `RegisterHotKey` on a message-only thread. (ADR-0035 D10; AG-73-19; OQ-381)
- **D-29:** macOS (compile-checked only): `CGEventCreateMouseEvent`, `CGEventCreateKeyboardEvent`, `CGEventKeyboardSetUnicodeString`, `CGEventCreateScrollWheelEvent2` posted with `CGEventPost` (`kCGHIDEventTap`) via `DllImport` to `ApplicationServices`; windows via `CGWindowListCopyWindowInfo` with a minimal CoreFoundation marshaller; capture is the system `screencapture -x -t png` run through the harness process abstraction (attribution of the Screen Recording grant is [INFERENCE], OQ-382); hotkey Carbon `RegisterEventHotKey` [INFERENCE: no Input Monitoring permission]; direct distribution only. (ADR-0035 D10; AG-73-20)
- **D-30:** `IComputerPermissionAdvisor` (Presentation) turns status into a guidance panel: macOS Screen Recording and Accessibility with "Open System Settings", polling every second for at most 5 minutes while the panel is open and a note that a restart may be needed; Windows `ElevatedTarget` and `SecureDesktop` texts; X11 `NoDisplay`, `InputInjectionUnavailable`; a missing permission never falls back to another mechanism. (ADR-0035 D11; AG-73-21)

### Remote use from Dispatch (R1)
- **D-31:** No relay operation reaches the executor or a backend primitive: ADR-0036's closed operation set has no `computer.*` operation and `computer.task` is gone; `computer_use` is a tool class named in `cowork.task.payload.toolClasses`; a `cowork.task` naming it, on a desktop with `Cowork:ComputerUse:Enabled` and `Cowork:ComputerUse:AllowDispatchSessions` (default false; the capability `enabled` flag of ADR-0036 D2) both on, registers `computer_*`; every other session registers none and `code.prompt` never does. (ADR-0035 D12.1, D12.2; R1; AG-73-22)
- **D-32:** Approvals can only be answered on the desktop (ADR-0036 refuses `approval.decide` for Computer Use; the in-session grant and sensitive prompts have no remote channel); the command-level approval (every `cowork.task` naming `computer_use`, no stored allow, `Dispatch:CommandApprovalTimeout` default 5 minutes) is separate from the per-application and per-action prompts (120 s) and both happen; with no local user the answer is `NoLocalApprover` and the controller sees "waiting for approval on the desktop"; a queued task follows the 5 minute offline expiry. (ADR-0035 D12.3, D12.6; R16)
- **D-33:** Grants made in a Dispatch-origin session have origin `Dispatch`, end with the command and in any case after 30 minutes, never carry `AutoApproveTyping`, and every sensitive class asks again; revoking the device or pausing Dispatch withdraws them at once; the indicator shows the controller device name; frames never leave the desktop except to the user's configured model provider (named with residency in the opt-in dialog); a controller thumbnail only with "show progress thumbnails on my other devices" (default off, OQ-389). (ADR-0035 D12.4, D12.5)

### UI and reuse
- **D-34:** Presentation hosts the approval, indicator and grants view models under `Computer/`, Native.Views the views; a Computer Use settings page and opt-in dialog cover provider disclosure, grants, denylist additions, kill chord, security phrase, audit and an indicator test; tests run under `Avalonia.Headless` 12.1.4 (`ApprovalDialogViewTests`, `IndicatorWindowViewTests`, `ComputerUseSettingsPageTests`, `PermissionAdvisorTests`, `DispatchOriginTests`); Deny has default focus, controls have names, no colour literals in views; a new colour role needs Light and Dark values and a `ThemeContrastTests` classification. (ADR-0035 D5, Consequences; AG-73-23; report 02 finding 5)
- **D-35:** Default is own code: Cua Driver (MIT, nightly-only, second signed app on macOS) and omp's native `computer` prelude (disabled in Cowork sessions) are not adopted; a future `CuaDriverBackend` stays possible behind `IComputerUseBackend` (OQ-383). (ADR-0035 D13)

## Specific Ideas

- Degraded and error states, each with one remediation id and no raw titles or typed text: `Disabled`, `UnsupportedPlatform`, `WaylandUnsupported`, `NoDisplay`, `PermissionMissing(ScreenRecording|Accessibility)`, `InputInjectionUnavailable`, `KillSwitchUnavailable`, `IndicatorUnavailable`, `AuditUnavailable`, `ElevatedTarget`, `SecureDesktop`, `StaleFrame`, `FrameTooLarge`, `ImageBudget`, `RateLimited`, `StepLimit`, `UserTookOver`, `ApprovalTimeout`, `NoLocalApprover`, `Revoked`.
- X11 live proof under a private Xvfb (`Xvfb -displayfd 3 -nolisten tcp -screen 0 1280x800x24`, never the session `DISPLAY`): `xdotool` moves the pointer and the backend reads it; the backend clicks a fixture and `xev` logs the event; `type` of `Hello, ünï` reaches `xev` as the same keysyms; `scrot` and backend frames of a fixed `xterm` agree within a per-channel tolerance; the hotkey fires on `xdotool key ctrl+alt+shift+Escape`; a second grab reports `KillSwitchUnavailable`; a bare Xvfb lists windows through `XQueryTree`.
- Reference product: Anthropic Computer Use (report 06 C17, line 78): per-app permission, View/Click/Full tiers, blocklist, "no sandbox between Claude and your applications".
