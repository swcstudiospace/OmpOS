# Phase 25.7 Context: UI Head Accessibility (fix F-F)

Source: 25.1-FINDINGS.md section 5 (M-22, M-25, M-26), section 6 (F-F: autonogrammer.css:10, index.html:26, app.css:90, focus-ring coverage R-5), and `lens-5-accessibility.md`. The owner accepted all eight fix phases on 2026-10-26; F-F runs sixth. M-23 (OQ-34, no platform reader for reduced motion on the desktop head) and M-24 (OQ-39, AT-SPI2 live regions) stay deferred.

## Decisions

- D1 (M-22, Android reduced motion): `MainView` takes a required `MotionPreference` in its public constructor, so a head cannot build the shared view without deciding motion. `Reduced` puts the class `reduced-motion` (`MainView.ReducedMotionClass`) on the view itself. The Android application has no `Window`, so its style `.reduced-motion Button` removes the 120 ms Button background transition; the native head keeps its `Window.reduced-motion` styles and also passes the setting to `MainView`. The Android head reads the one setting Android exposes, the animator duration scale (`Settings.Global.AnimatorDurationScale`, 0 when the user chose "Remove animations"), in `AndroidMotion`. The decision from the number lives in `Autonogrammer.Presentation.MotionPreferenceResolver`, which has unit tests, so the untestable Android call is a one-line read.
- D2 (M-22 coverage): `HeadMotionTests` (ArchitectureTests) fails when a head builds `MainView` without a motion argument, and fails when a head's application XAML declares a transition with no empty-`Transitions` override under a `reduced-motion` selector for the same control type. Self-tests prove each scan reports a violation. `ReducedMotionTests` checks the class on `MainView` under each preference.
- D3 (M-25, A2UI image alt): the fallback is `A2uiSurfaceCatalog.ResolveImageAlt` with `DefaultImageAlt = "Image"`, in Autonogrammer.GenUi, the single place both heads read. A missing, empty or white-space alt becomes the default; a supplied alt is kept. `A2uiSurfaceView.razor` and the Avalonia `A2uiSurfaceView` use it (the Avalonia view had a private copy of the same rule, now removed). `SurfaceComponent.Alt` stays the raw payload value, because search and export index what the agent wrote. The remote-image fallback link text also treats a white-space alt as missing.
- D4 (M-26, error banner): in `index.html` the container is `role="alert"` and the dismiss is `<button type="button" class="dismiss" aria-label="Dismiss error">`, with the glyph in an `aria-hidden` span. The class `dismiss` is kept, so Blazor's own dismiss binding still finds it. `app.css` resets the button chrome, gives it a 24 px minimum target and a 2 px `:focus-visible` outline (`#0b5cad`) on the light-yellow banner. Enter and Space are the native button behaviour.
- D5 (app.css:90): the loading-ring `stroke-dasharray` transition gets a `prefers-reduced-motion: reduce` override, `transition: none`.
- D6 (smoke and static gates for M-26): `scripts/web-smoke/smoke.mjs` gains step 7 and the assertion `errorBannerAnnouncesAndDismissesByKeyboard` (role, button, name, Tab from Reload reaches it, visible outline, one Enter and one Space raise two click events, zero axe violations while shown). Blazor binds its dismiss handler only when it shows the banner, so the smoke counts click events instead of exercising the framework handler. `WebShellAccessibilityTests` (ArchitectureTests) holds the same shell and stylesheet facts without a browser. The runbook names the step.
- D7 (R-5, focus ring contrast): `AccessibilityTests` (UI.Tests) adds the focus ring on `--autonogrammer-bg` and on `--autonogrammer-surface` at 3:1 (WCAG 1.4.11), the two filled-control text pairs at 4.5:1, a check that a `:focus-visible` rule draws its outline from `--autonogrammer-focus-ring`, and a check that each ratio written in an `autonogrammer.css` comment equals the computed ratio. The stale comments (`~5.9:1`, `~7:1`) now state the computed values from the audit: 5.13:1 and 6.54:1; the two text pairs read 17.40:1 and 15.83:1; the ring reads 5.13:1 and 4.67:1.
