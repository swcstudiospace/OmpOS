## 7. Gaps (criterion 3)

- No runtime evidence. No build, test, analyzer, formatter, or restore ran (phase rule). Flakiness, timing, and vacuous-pass claims come from source and are not reproduced.
- Dead code. No analyzer or repository reference check exists; not measured (gap accepted in Phase 25).
- Lock freshness. Only presence of each lock file was checked; `dotnet restore` was not run.
- SDK roll-forward. Whether `rollForward: latestPatch` resolves above 10.0.402 on the runner is not observed (M-31 is a possibility, not an observed failure).
- Contrast. Ratios are computed from token values, not rendered. Native text pairs are covered by `ThemeContrastTests` (16 pairs per variant; minimum 5.15 light, 4.85 dark, lens 5). Web CSS pairs are covered by no test.
- Live regions. AT-SPI2 reach for the 20 `LiveSetting` uses is not confirmed (OQ-39).
- Reduced motion. The native app never sets `MotionPreference.Reduced` (OQ-34 open).
- Conventions without a written rule. Logging, time, HTTP, and namespace drift are judgements from uniformity (lens 4). No tracked document sets them, so a fix cannot be checked against a rule until the owner decides each convention.
- Runtime listeners. A Trace listener added outside tracked files cannot be checked read-only (lens 4 assumes none).
- Test scan is structural: attribute and brace matching. Helper-based assertions were followed to the end only for the AutomationGuard cases; bUnit `VerifyInvoke` cases were not read to the end (lens 1).
