# Phase 25.1: Codebase Quality Audit, Plan 01

Goal: measure the tracked codebase against the QUALITY_BAR and record every finding with file and line evidence. No product code changes (criterion 4).

## Tasks

### T1. File inventory and command record
- Run `git ls-files` for the audit scope (src/, apps/, tests/, scripts/, .github/, bootstrap.sh), excluding apps/OmpOS.Web/wwwroot/lib and build output. Count files per area.
- Verifies criterion 1: the register lists the commands and counts used.
- Verify: the inventory counts are written in 25.1-FINDINGS.md.

### T2. Six read-only lens scans, in parallel
Each lens writes one file in this directory, with a table of findings (file:line, QUALITY_BAR item, severity, disposition, evidence), the grep patterns it used with hit counts, and a gap list.
1. lens-1-correctness-tests.md: error handling, fire-and-forget tasks, sync-over-async, test quality.
2. lens-2-boundaries-security.md: external input, paths, process spawn, TLS, deserialization, secrets, command or query assembly.
3. lens-3-maintainability-observability.md: markers, suppressions, skips, commented-out code, mutable statics, logging of values.
4. lens-4-pattern-fidelity.md: mixed conventions for logging, time, HTTP clients, sync and async style, duplicated helpers.
5. lens-5-accessibility.md: names, focus, keyboard, colour literals, motion, web alternatives.
6. lens-6-compatibility-reproducibility.md: floating versions, lock files, SDK pins, unpinned downloads, action pins.
- Verifies criteria 1 and 2 for each lens.
- Verify: each lens file exists, is non-empty, and lists its patterns with hit counts.

### T3. Consolidate the register
- Write 25.1-FINDINGS.md: the inventory, a summary count per lens and severity, links to the six lens files, and the gap list (criterion 3).
- Verify: every finding in the lens files appears in the summary count, and every gap has a reason.

### T4. Propose fix phases from the register
- Group the High and Medium findings by area. Each proposed fix phase lists its goal, its criteria, and the findings it closes.
- Verify (criterion 5): each proposal has an acceptance state of "awaiting owner".

### T5. No product change
- Run `git diff --stat -- src apps tests scripts .github bootstrap.sh` and record that it is empty.
- Verify (criterion 4): the phase's diff touches only .planning paths.

### T6. Phase record
- Write 25.1-01-SUMMARY.md: the changed-file list (planning only), the commands run, the gate reference (59e9dd1), and the QUALITY_BAR checklist for this phase (each item N/A with reason, because this phase writes no product code).
- Verify: the SUMMARY names this phase and holds the checklist.
