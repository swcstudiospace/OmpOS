## Kanban runtime status mapping (VX-04, criterion 3)

| Runtime signal kind | Sets status | Status meaning |
|---------------------|-------------|----------------|
| `RunQueued` | `Queued` | Accepted and not yet started |
| `RunStarted` | `Running` | Executing a prompt |
| `InputRequested` | `AwaitingInput` | Waiting for the user's next message |
| `ApprovalRequested` | `NeedsAttention` | Waiting for a decision that is not a message reply, such as a tool approval |
| `RunPaused` | `Paused` | Paused by the runtime or the user |
| `RunCompleted` | `Completed` | Finished successfully |
| `RunFailed` | `Failed` | Finished with a failure |
| `SessionUnreachable` | `Unreachable` | Session cannot be reached |

Stale flag: not a status. Set only by `WithStale`. A heartbeat change never changes status, and a signal never changes the flag. An undefined kind throws `UnmappedRuntimeSignalException` and leaves the card unchanged. No default status is applied.
