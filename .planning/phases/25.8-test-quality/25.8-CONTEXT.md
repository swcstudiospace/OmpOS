Source: 25.1-FINDINGS.md section 5 (M-8, M-9, M-10) and section 6 (F-G Low rows: lens 1 test methods with no direct assertion, `InMemorySessionSignalsTests.cs:71`, `RailwaySwarmProviderTests.cs:204`). The owner accepted all eight fix phases on 2026-10-26; F-G runs seventh. Tests and test helpers only; no production code changes.

## Decisions

- D1 (M-8, `Timeout_IsHonoured`): the contract gains an abstract `ArrangeProvisionTimeout(provider, request)` hook, so each provider is put in its own deterministic expired-deadline state, with no clock and no wait. The test asserts `ProvisionTimeoutException` and nothing else, so a provider that ignores the timeout fails it. Fake: a non-positive timeout (the fake has no clock; its documented deadline check). Podman: the secret-create call succeeds and compose `up` reports `TimedOut`. The old swallow-all catch of `NotAvailableException` is gone: no contract provider is a stub. The podman subclass also asserts the request timeout reaches the compose `up` spec.
- D2 (M-9, `StatusTransitions_CoverEnum`): `SandboxStatus` is not observable through `ISandboxProvider`. The status lives in `SandboxLifecycle`'s registry entry (and in private provider records). The contract test is removed and replaced by `SandboxLifecycleTests.StatusTransitions_FollowTheLifecycle` (Ready, Attached, TearingDown during teardown, Failed, Destroyed) and `EveryStatusIsEitherReachedByTheLifecycleOrRecordedAsNeverAssigned` (the enum is partitioned into assigned and never-assigned, so a new value fails until classified). `Provisioning` and `Degraded` are never assigned by any code path today; this is recorded in the test, not hidden, and reported as an observation (no production change).
- D3 (M-10, settlement sleep): the fixed 200 ms sleep is replaced by a positive signal followed by a flush. `RunControlsHarness.FlushAsync` makes thread-pool round trips with a dispatcher flush after each. `UntilAsync` no longer sleeps; it yields and pumps the dispatcher, under a 10 s loud `TimeoutException`. A second test drives the late settlement as a fault, where the row's trace line is a positive signal that the continuation ran.
- D4 (RailwaySwarmProvider:204): the unconfigured provider has no HTTP client, so a handler cannot count requests. The test asserts the teardown task is already completed when the call returns, which a started request cannot satisfy.
- D5 (lens 1 no-assertion rows, 9 real): each test gets an assertion of its claimed behaviour (see the summary table). `InMemorySessionSignalsTests.cs:71` was "accept" in the findings; the strengthening was trivial (no replay to a later subscriber), so it is done.
