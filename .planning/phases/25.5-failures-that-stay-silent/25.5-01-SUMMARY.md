## Open items

- RESOLVED, M-4 detached path (follow-up H1). Isolated from the code, outcome (b): production does not drop the fault. `Decide` passes `CancellationToken.None`, so removing the approval cancels nothing. The coordinator awaits with `ConfigureAwait(true)` and rethrows the bridge fault into the task that `Decide` follows. The continuation then runs on `TaskScheduler.Default` and calls `Trace.TraceError` before `PostWhileAttached` checks the cancelled attachment, so detaching cannot reach the trace call. The earlier test therefore had a setup defect, most likely its listener (the first test used `ApprovalRemove` and a listener the app's startup could replace; `InstallStderrTraceListener` removes any earlier `StderrTraceListener`). The cause of that earlier miss was not reproduced; the removed test is not available to re-run. The new test uses the detach that `DetachedSettlementTests` already proves (`Approvals.Remove`, then asserts no row remains), adds a plain `TraceListener` (not a `StderrTraceListener`) on the UI thread after the session started, faults the bridge only after the detach, and waits on a `TaskCompletionSource` with a timeout as an upper bound only. A build that drops the trace never completes it, and the test fails by timeout. No fixed sleep. New test: `ToolApprovalRowTraceTests.ADecisionFaultAfterTheRowDetachedIsTraced`. Not run.
- RESOLVED, desktop logger gap (follow-up H1). Owner decision applied: the desktop composition root passes an `ILoggerFactory` whose provider forwards to `Trace`, so the app's `StderrTraceListener` receives the services' output. `apps/OmpOS.Native/Logging/TraceLoggerProvider.cs` maps Warning to `Trace.TraceWarning`, Error and Critical to `Trace.TraceError`, other levels to `Trace.WriteLine`, and disables `LogLevel.None` with no work before the enabled check. `apps/OmpOS.Native/Logging/DesktopLogging.cs` builds the factory (Information and above). `Program.ComposeProductionEngine` passes `DesktopLogging.Factory` to `EngineComposition.Compose`, which passes it to `InProcessEngineHost.ForAcp`, then `OmpAcpClient`, which creates the `ILogger<AcpAgentSession>` and `ILogger<AcpStdioTransport>`. Before this change `OmpAcpClient` created sessions with no logger, in every host. Scope: the desktop composes only the ACP host. It composes no Herdr, Dragonfly or remote host service, so M-2, M-3 and M-17 output has no desktop composition site; M-19 (pump fault, Error) and D10 (stderr drain, Debug, filtered out by the Information minimum) are the desktop-reachable sites. New package reference: `Microsoft.Extensions.Logging` (already pinned at 10.0.13) in `apps/OmpOS.Native/OmpOS.Native.csproj`; lock files need regeneration. New tests (`tests/OmpOS.Native.Tests/Logging/DesktopLoggingTests.cs`, not run): `WarningAndErrorEntriesReachATraceListenerAtTheirTraceLevels`, `InformationIsWrittenAsAPlainLineAndDebugIsDropped`, `TheProviderLoggerIsDisabledForNoneOnly`, `AComposedSessionsPumpFaultReachesATraceListenerAsAnError`. No desktop-composed service logs at Warning, so the Warning mapping is proven through the factory's logger, and the composed-service proof is the Error pump fault. ADR-0011 is amended to match.
- Not tested: D10 (the stderr drain failure, Debug log). The stderr pipe failure cannot be forced deterministically from a real child.
- Not closed: D4 scope. A compensation failure that is neither `HerdrSessionException` nor `OperationCanceledException` still escapes and replaces the original persist failure, as before. Widening the catch was not in the accepted criteria.
- Chosen: D9 exemption. A session-initiated close does not log an error when the pump exits, so normal disposal stays quiet.
