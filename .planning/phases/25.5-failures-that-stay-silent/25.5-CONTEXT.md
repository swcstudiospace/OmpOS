# Phase 25.5 Context: Failures That Stay Silent (fix F-D)

Source: 25.1-FINDINGS.md section 5 (M-2, M-3, M-4, M-12, M-17, M-18, M-19, M-21), section 6 (AcpStdioTransport.cs:209; Index.razor:89,105,159,184; RemoteEngineHost.cs:345). The owner accepted all eight fix phases on 2026-10-26; F-D runs fourth.

## Decisions

- D1 (logging split, M-21): services and harness layers (Harness.*, EngineHost, Coordination.*, Sessions, Workflows, Api) log through ILogger. The native Avalonia head (src/OmpOS.Native.Views, apps/OmpOS.Native) keeps Trace and attaches a stderr trace listener at startup. The Blazor web head (apps/OmpOS.Web) uses ILogger, because it has DI and the browser console provider. The split is recorded in docs/decisions/0005-logging-split.md (next free ADR number). Conservative default: the owner decided "one mechanism per layer, decision recorded" in the accepted scope, not which mechanism; this split follows the code that already exists.
- D2 (constructors): a new logger is an optional constructor parameter `ILogger<T>? logger = null`, stored as `logger ?? NullLogger<T>.Instance`. Existing constructor callers and tests keep compiling. DI-constructed services receive the real logger.
- D3 (M-2, RemoteEngineHost transport drop): the drop is logged at Warning. If the stream ends without a terminal event or error, SubmitPromptAsync surfaces it as an error to its caller instead of ending silently. The reconnect contract (ReconnectAsync resumes from the cursor) is kept.
- D4 (M-3, HerdrSessionService): a failed compensating TerminateAsync is logged at Error with the session identifier, and the original failure is still the one thrown.
- D5 (M-4, ToolApprovalRowView): a decision fault after detach is written to Trace.TraceError with the request identifier, and the row's status text shows the failure if the row is still attached.
- D6 (M-12, CodeBlockView.razor): a clipboard failure is logged through ILogger and does not invoke OnCopy; the caller is not told the copy succeeded.
- D7 (M-17, DragonflySessionSignals): handler failures are logged at Warning with the channel name.
- D8 (M-18, MainView close faults): App startup (apps/OmpOS.Native) adds a stderr TraceListener, so close faults reach an operator in the shipped app. A test shows the listener receives the close fault.
- D9 (M-19, AcpAgentSession pump fault): the pump fault is logged at Error and surfaces through the existing session-failure path.
- D10 (Low rows): AcpStdioTransport.cs:209 logs the stderr drain failure at Debug; Index.razor catch sites log the exception through ILogger and keep the existing user message.

## Assumptions

- Phase 25.4 is partial and stays partial; its residuals do not block this phase.
- Subagents edit files only; the lead runs the one gate.
