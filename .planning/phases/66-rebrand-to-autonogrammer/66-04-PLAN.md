<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| legacy user directory to new directory | Untrusted bytes move once; damaged files are carried as-is, never executed or parsed by the migrator |
| lock file sibling in the parent root | Cross-process mutual exclusion over a shared directory |
| unreadable legacy directory | Permission failure must not fail startup nor leak path contents |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-66-04-01 | Tampering | UserDataDirectory.EnsureCurrent | medium | mitigate | Check-then-migrate under an exclusive FileShare.None lock file; atomic Directory.Move is the arbiter (second mover gets IOException and re-checks); marker file records completion; post-migration code never reads the legacy path. |
| T-66-04-02 | Denial of Service | Unreadable legacy directory | low | mitigate | UnauthorizedAccessException/IOException during enumerate or move yields the new directory plus a warning; startup never throws for a legacy permission failure. |
| T-66-04-03 | Information Disclosure | Migration warning text | low | mitigate | Warnings carry directory names only, never file contents; logged via ILogger/Trace, never Console; record type carries no secrets. |
| T-66-04-04 | Tampering | packages.lock.json relock | medium | mitigate | Locks written only by --force-evaluate restore (never text-edited); verified per project with restore --locked-mode; dependent set enumerated from git status. |
</threat_model>
