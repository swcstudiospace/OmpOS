# OmpOS brand

OmpOS is an open agent workspace on the omp engine. The identity is White and Purple: a white working surface, one purple accent, quiet geometry. Everything here is built from the repository's own fonts and colour tokens, and every asset is regenerated by one script.

## Mark

A rounded purple tile holding a white **O** ring with a prompt inside it: a chevron and an underscore cursor. The ring is the "O" of OmpOS, the prompt is the agent. Two cuts exist:

| Cut | Source | Use |
|---|---|---|
| Full mark | `assets/brand/src/mark.svg` | 24 px and larger: app icons, About dialog, headers, README |
| Small cut | `assets/brand/src/mark-small.svg` | below 24 px: favicons, 16/24/32 px icon frames, the web favicon. Thicker ring, chevron only, geometry snapped to the 16 px grid |
| Dark mark | `assets/brand/src/mark-dark.svg` | on `#181818` surfaces: lavender tile (`#c4b5fd` to `#a78bfa`) with a `#181818` glyph |

The tile gradient runs diagonally from `#7c3aed` to `#5b21b6` (white glyph contrast 5.7:1 to 9.0:1). It is the only gradient in the identity; banners and backgrounds are flat.

## Logo

* `ompos-logo.svg` horizontal lockup for light surfaces: mark, then **Omp** in `#1c1c1a` and **OS** in `#6d28d9`, Anybody SemiBold, outlined.
* `ompos-logo-dark.svg` the same for dark surfaces (`#ececec` and `#a78bfa`, dark mark).
* `ompos-logo-stacked.svg` mark above the wordmark, for square spaces.

Published SVGs contain no `<text>` and no font reference: they render identically without the fonts installed.

### Clear space and minimum size

* **Clear space** on all four sides: 25 percent of the mark height (for the 96 px tall horizontal lockup, 24 px). Nothing else (text, edges, other logos) enters it.
* **Minimum size**: full mark 24 px, small cut 16 px; horizontal lockup 120 px wide; stacked lockup 80 px wide. Below 120 px wide use the mark alone.
* The tile is never recoloured, rotated, outlined, stretched, drop-shadowed or animated in its resting state.

## Type roles

| Role | Family | Rule |
|---|---|---|
| Body, UI, taglines | DM Sans (Regular 400, Medium 500, SemiBold 600) | default for everything readable |
| Display, wordmark | Anybody SemiBold (600) | 20 px and larger only; never for body copy or small labels |
| Code, paths, URLs | Space Mono (Regular, Bold) | monospaced content only |

The fonts are SIL OFL 1.1 and live in `src/OmpOS.Native.Views/Assets/Fonts` (one `OFL.txt` per family). Anybody has only the SemiBold weight bundled, and GitBook custom fonts accept only `.woff`/`.woff2`, so Anybody appears in images, not in the docs body font.

## Do and don't

Do:

* Use the horizontal lockup first, the stacked lockup for square spaces, the mark alone below 120 px.
* Keep "OS" in the accent colour and "Omp" in the text colour; use the dark variants on dark surfaces.
* Leave generous white space; the identity depends on it.

Don't:

* Retype the wordmark in another font or set Anybody below 20 px.
* Place the white-glyph tile on a purple or photographic background; use the dark mark on dark surfaces.
* Add gradients other than the tile, shadows, outlines, emoji or stock photography to brand images.
* Edit generated files by hand; edit `assets/brand/src` and rebuild.

## Rebuild and verify

```bash
scripts/brand/build-brand.sh      # regenerates every asset above from assets/brand/src
scripts/ci/check-brand.sh         # exits non-zero if a file is missing or mis-sized
```

Prerequisites: `google-chrome` (headless), `pdftocairo` (poppler-utils), `optipng`, ImageMagick `convert` (PNG to ICO only), and `python3` with `cairosvg` and `Pillow`. No font tooling is needed: Chrome shapes and kerns the bundled TTFs through `@font-face`, prints the SVG to PDF, and `pdftocairo` converts the PDF to glyph outlines that the build places back into the SVG. If the system Python lacks the modules:

```bash
python3 -m venv /tmp/ompos-brand-venv && /tmp/ompos-brand-venv/bin/pip install cairosvg pillow
OMPOS_BRAND_PYTHON=/tmp/ompos-brand-venv/bin/python scripts/brand/build-brand.sh
```

The build is idempotent: unchanged files are not rewritten.

Not verifiable on the Linux build host: how `ompos.icns` renders in Finder (the file is structurally validated by `check-brand.sh`) and how the Android adaptive icon renders on device launchers.
