# Cursor desktop Settings window: sections, options, and Autonogrammer mapping

Research date: 2026-10-22. Every "opened" entry below was read with the read or grep tool on that date. Forum posts are vendor-staff or user posts, not documentation; they are marked secondary and do not support any row marked verified.

## Verdict

No single primary Cursor page enumerates the desktop Settings window, so its section list is assembled from the primary pages I could open. Those pages place these under Cursor Settings (Cmd/Ctrl+Shift+J): Models (provider API-key fields for OpenAI, Anthropic, Google, Azure OpenAI and AWS Bedrock, plus a default model); Agents, with Approvals & Execution (Run Mode, Read Access, sandbox network mode) and Context and Tools (Sync Skills for Cloud Agents); Tab; Network (Run Diagnostics, HTTP Compatibility Mode); General (Privacy Mode); Keyboard Shortcuts; and editor appearance (theme, font size, font family). Rules, skills, subagents, commands, MCP servers, hooks and plugins sit on the Customize sidebar page, not in Settings. Team, cloud-agent, spending and admin controls sit in web dashboards. Indexing & Docs, Beta, the OpenAI and Anthropic base-URL override fields, and the @Docs sunset are reported only in forum threads or source-code examples; they are unverified against primary documentation. Of 34 rows, 30 cite an opened primary page (some partially read) and 4 are unverified. Against Autonogrammer, 22 rows map to a ROADMAP phase or ADE-plan row (fully or partly), and 12 rows are new with no phase; the only existing code path cited is the API permission resolver (`services/Autonogrammer.Api/Harness/SessionPermissionResolver.cs`, named in the ADE plan §4) together with completed ROADMAP Phase 10 (direct approvals).

## Owner decisions

1. Which Settings-window surfaces should Autonogrammer build in-app? Options: (a) a Cursor-shaped Settings window (Models, Agents, Tab, Network, General, Keyboard, Appearance); (b) only the surfaces the ADE plan already names (approvals, terminal, MCP, rules and skills, search, theme tokens); (c) none, with configuration kept in files and the omp CLI.
2. How should model providers be configured? Options: (a) per-provider API-key fields as in Cursor's Models section (OpenAI, Anthropic, Google, Azure OpenAI, AWS Bedrock); (b) provider configuration only through omp's own configuration, not in the app; (c) hosted-only model access, gated on OD-03.
3. Should base-URL overrides be supported? The primary Cursor page does not document them. Options: (a) a base-URL field per provider protocol; (b) one global override; (c) exclude until a primary Cursor source documents them.
4. Which Run Mode is the default for Autonogrammer? Options: (a) an Auto-review-style classifier mode, which needs a configured classifier model (Cursor's default since 3.6); (b) Allowlist as the default, with Run Everything hidden; (c) ask-every-time only, matching ADE-14's auto-run-off default.
5. What search does Autonogrammer ship beyond text and regex (ADE-18)? Options: (a) text and regex only, as ADE-18 is written; (b) a local, git-tied index for faster search added in Phase 28; (c) a semantic index in a later milestone.
6. Should Autonogrammer offer a curated documentation corpus (Cursor's @Docs, reported sunset)? Options: (a) add a docs-indexing feature in a later milestone; (b) rely on web search and fetch only; (c) defer until a primary Cursor page confirms the current behaviour.
7. Should cloud-agent environment and network policy be settings in Autonogrammer? Options: (a) implement network modes and team follow-up policy in Phase 26, behind OD-03; (b) defer to Phase 30 (ADE-22 admin controls); (c) omit.
8. Should Autonogrammer have a Beta section for feature toggles? Cursor's Beta contents are not documented in a primary page. Options: (a) create an Autonogrammer Beta section; (b) no Beta section; (c) hold until Cursor's Beta contents are verified.
9. Should Autonogrammer expose a privacy or data-use toggle (Cursor's Privacy Mode)? Options: (a) add an equivalent in-app setting; (b) rely on the hosted-API data policy, gated on OD-03; (c) defer.
10. How far should keyboard remapping go? Options: (a) Phase 20 contract only (commands and key bindings as plugin contributions); (b) a remap screen in the Phase 21 parity surface; (c) fixed defaults with no remap in v0.11.0.
