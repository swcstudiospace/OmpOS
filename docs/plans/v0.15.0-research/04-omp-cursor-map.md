### B5. Alternative control surface: RPC (`omp --mode rpc`)
Same engine, richer command set (`SRC/modes/rpc/rpc-types.ts`; `omp://rpc.md`): `prompt/steer/follow_up/abort/abort_and_prompt`, `new_session/open_session/switch_session/branch/fork/get_tree/get_entries/get_messages_page`, `get_state`, `get_available_commands`, `get_subagents/get_subagent_messages/cancel_subagent/steer_subagent/set_subagent_subscription`, `set_event_filter`, `set_todos`, `set_host_tools`, `set_host_uri_schemes`, `goal`, `bash/abort_bash`, `compact`, `handoff`, `set_auto_retry/abort_retry`, `get_login_providers/login/logout`, `btw`, `live_*`, `negotiate_protocol` (v1/v2). It is single-session per process and not JSON-RPC 2.0. Pick RPC if Autonogrammer needs subagent rosters, queue editing, branch/rewind or login; ACP if editor-style interoperability is the goal [INFERENCE: design choice].
