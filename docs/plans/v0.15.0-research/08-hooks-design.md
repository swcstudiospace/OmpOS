## 1. Event map: every Cursor hook event to its OmpOS firing point

Mechanism codes: **H** = OmpOS host action (head code before or after it talks ACP, no omp cooperation needed, works with any omp); **A** = ACP traffic the client already sees (session/update, session/request_permission, fs/*); **B** = omp extension event delivered by a new OmpOS-owned bridge extension (plugins/ompos-hooks-omp, loaded with -e, calls the host over loopback HTTP, see section 3). Blocking = can OmpOS stop or alter the action. Cloud = does Cursor run it in cloud agents (S1). Rule: where two mechanisms exist, B is the primary for anything that must block a tool, because ACP never shows a tool call before it runs and request_permission is skipped under yolo and for read-tier tools; A is the degraded fallback when the bridge is absent (and for the `observe` events it is enough).

## 2. The hooks.json format OmpOS accepts

### 2.1 File locations, scopes and merge order

Load order = run order = priority (highest first). All sources run, none replaces another.

| Order | Scope | Path | Hook cwd | Notes |
|---|---|---|---|---|
| 1 | managed (Cursor "Enterprise") | Linux `/etc/ompos/hooks.json`; macOS `/Library/Application Support/OmpOS/hooks.json`; Windows `C:\ProgramData\OmpOS\hooks.json` | the directory of the file | OmpOS-specific path. Do NOT read Cursor's enterprise paths (they are Cursor-managed). Accept only when the file is owned by root/Administrators and not group- or world-writable [INFERENCE, security hardening]. Counts as pre-consented only under that check. |
| 2 | team | none | n/a | Cursor team hooks come from a paid dashboard (S1); OmpOS has no team backend. Document as not supported, not as a stub. |
| 3 | project | `<root>/.ompos/hooks.json`, then `<root>/.cursor/hooks.json` | the workspace root that contains the file (each root of a multi-root workspace has its own; workspace_roots lists all) | Same project hook written for Cursor runs unchanged. Identical (event, command, cwd) triples found in both files run once. |
| 4 | user | `~/.ompos/hooks.json`, then `~/.cursor/hooks.json` | the directory that holds the file (`~/.ompos/` or `~/.cursor/`), as in Cursor | Not available in remote/cloud runs (Cursor parity). |
| 5 | claude-local | `<root>/.claude/settings.local.json` | workspace root | read the `hooks` key only; Claude nested format. Toggle "Include third-party configs", default ON like Cursor, but consent still applies (ON means "discover", not "trust"). |
| 6 | claude-project | `<root>/.claude/settings.json` | workspace root | same |
| 7 | claude-user | `~/.claude/settings.json` | `~/.claude/` [INFERENCE: S2 gives no cwd] | same |
| 8 | plugin | hooks declared by harness plugin manifests (existing `PluginHost`) | plugin install dir (`OMPOS_PLUGIN_ROOT` and `CURSOR_PLUGIN_ROOT` both set) | command hooks only. Existing triggers map: sessionStart to sessionStart, beforeAction to preToolUse (Blocking), afterAction to postToolUse, sessionEnd to sessionEnd. |

Order inside a source: array order. Execution: sequential in priority then array order (the current HookRunner is sequential; Cursor does not document concurrency, [INFERENCE] sequential is safe and deterministic). Reload: file watcher on every discovered path, debounce, atomic swap of the effective set; a changed command hash needs new consent. Merge of responses (per event invocation): permission = deny > ask > allow over all hooks that produced a decision; user_message and agent_message concatenated with a newline in run order; updated_input, updated_mcp_tool_output, additional_context (concatenate), followup_message, env: for scalar fields the LAST responding hook in run order wins, which per S1 means a lower-priority source overrides a higher-priority one (S1 wording). Contradicted by S2, owner decision O3.

### 2.2 Accepted JSON (superset of Cursor)

```json
{
  "$schema": "https://ompos.dev/schemas/hooks.v1.json",
  "version": 1,
  "hooks": {
    "beforeShellExecution": [
      { "command": ".cursor/hooks/approve-network.sh", "timeout": 30, "matcher": "curl|wget|nc ", "failClosed": true }
    ],
    "stop": [ { "command": "bun run .cursor/hooks/track-stop.ts --stop", "loop_limit": 10 } ],
    "preToolUse": [
      { "type": "prompt", "prompt": "Only allow read-only operations. $ARGUMENTS", "model": "optional-model-id", "timeout": 10 }
    ],
    "afterFileEdit": [
      { "args": ["prettier", "--write", "${file_path}"], "id": "fmt", "enabled": true, "description": "format", "runsIn": ["local", "remote"], "env": { "FOO": "bar" } }
    ]
  },
  "omp": {
    "tool_call": [ { "command": "./hooks/omp-guard.sh", "matcher": "^(bash|write)$" } ],
    "session_before_compact": [ { "command": "./hooks/keep-notes.sh" } ]
  }
}
```

| Key | Type | Origin | Rule |
|---|---|---|---|
| `version` | integer | Cursor | required, 1. Reject others with a clear error naming the file. |
| `hooks.<event>` | array | Cursor | event name must be one of the 21 camelCase names in section 1. An unknown event name is kept and shown on the Hooks page as "unknown event" (Cursor may add events; do not fail the whole file). |
| `command` | string | Cursor | shell string, absolute or relative path. POSIX: `/bin/sh -c`; Windows: PowerShell with the JSON piped in (S1). Relative paths resolve against the hook cwd of its scope (2.1). |
| `type` | command / prompt | Cursor | default command. `prompt` uses `prompt`, optional `model`; returns {ok, reason?}. |
| `timeout` | number (seconds) | Cursor | default 30 (existing HookRunnerOptions default, Cursor does not state its own); hard max 600 [INFERENCE]. |
| `loop_limit` | integer or null | Cursor | stop and subagentStop only; default 5. |
| `failClosed` | bool | Cursor | default false. |
| `matcher` | regex string | Cursor | .NET regex, anchored? Cursor does not say. Use unanchored `IsMatch` (the doc examples `curl\|wget\|nc ` and `explore\|shell` only work unanchored). Empty or `*` matches all. Per-event matched value: section A. |
| `args` | string[] | OmpOS | argv form, run without a shell (keeps the ADR-0013 decision 4 path for people who want it). `command` and `args` are mutually exclusive. |
| `id`, `enabled`, `description` | string, bool, string | OmpOS | `id` stable key for the UI and consent state; default `<scope>:<event>:<index>`. `enabled:false` = listed, never run. |
| `env` | object | OmpOS | extra variables for this hook only; values are literal (no expansion). Part of the consent hash. |
| `runsIn` | [local, remote] | OmpOS | default both. Lets a hook opt out of cloud runs. |
| `blocking` | bool | OmpOS (existing manifest field) | derived default: true for the 6 permission events, false otherwise. Only meaningful for "stop later hooks on failure" legacy semantics; keep for plugin manifests, ignore in hooks.json unless set. |
| `omp` | object | OmpOS | omp-native section: key = omp extension event name (allow-list below), same entry shape. Input JSON = the omp event object plus the common fields; output = the omp result object for that event (tool_call: {block, reason, input}; input: {handled, text}; session_stop: {continue, context}; before_subagent_spawn: {block, reason, model}; session_before_compact: {cancel}; tool_result: {content, isError}). Allow-list: tool_call, tool_result, input, session_stop, before_subagent_spawn, session_before_compact, auto_compaction_start, session_start, session_shutdown, agent_end, turn_end, message_end, tool_approval_requested, tool_approval_resolved. This is how omp-only abilities (cancel compaction, rewrite tool results) stay reachable without Cursor naming. Needs bridge B. |

Claude-format files (`.claude/settings*.json`) are parsed with the nested layout {hooks:{PreToolUse:[{matcher, hooks:[{type, command, timeout}]}]}} and mapped PreToolUse to preToolUse, PostToolUse to postToolUse, UserPromptSubmit to beforeSubmitPrompt, Stop to stop, SubagentStop to subagentStop; Notification and PermissionRequest are ignored (S2 says unsupported); tool names Bash to Shell, Edit to Write; Glob: no match. Response parser accepts both flat and nested `hookSpecificOutput` forms (S2). `loop_limit` default is null for Claude-sourced hooks (S1).

Parser rules (reusing PluginManifestParser limits): UTF-8 JSON, 64 KiB cap, depth 16, no comments; tolerate unknown top-level keys and unknown per-hook keys (Cursor will add some) but surface each as a warning row; reject a duplicated key; reject duplicate `id` within a file.

### 2.3 Process contract (what a hook sees and returns)

- **stdin**: one JSON object (common fields + event fields from S1) followed by close. Needs a change in `SystemHookProcessRunner` (today stdin is closed at once). Payloads can be large (afterShellExecution output, beforeReadFile content): write stdin on a separate task, tolerate a hook that exits without reading (broken pipe), cap at 8 MiB and set `truncated` fields [INFERENCE].
- **stdout**: one JSON object (flat or Claude nested). Keep the bound at 16 KiB for the PARSED response? Too small for additional_context; raise `HookOutput.MaxBytes` for hook-protocol stdout to 256 KiB and keep 16 KiB for the stored log excerpt [INFERENCE].
- **stderr**: log only; on exit 2 stderr is used as agent_message when stdout carries none (Claude convention, S1 does not specify) [INFERENCE].
- **exit**: 0 use stdout; 2 deny (permission events) ; other = failure, fail-open unless `failClosed`. For permission events invalid JSON or a schema mismatch denies (S1). Empty stdout with exit 0 on a permission event = schema mismatch = deny? S1 says "invalid JSON" blocks; treat empty stdout as invalid for permission events [INFERENCE] and document it.
- **env**: CURSOR_PROJECT_DIR, CLAUDE_PROJECT_DIR, OMPOS_PROJECT_DIR (workspace root), CURSOR_VERSION (set to a fixed compatibility string, plus OMPOS_VERSION), CURSOR_USER_EMAIL (when signed in), CURSOR_TRANSCRIPT_PATH / `transcript_path` (omp session jsonl path if the host knows it, else absent), CURSOR_CODE_REMOTE=true for remote and cloud sessions, CURSOR_PLUGIN_ROOT and OMPOS_PLUGIN_ROOT for plugin hooks, OMPOS_HOOK_EVENT, OMPOS_SESSION_ID, plus sessionStart `env`. Base environment: owner decision O2 (ADR-0013 risk 1): default allow-list (PATH, HOME, USERPROFILE, LANG, TERM, TMPDIR, SYSTEMROOT, SHELL, locale) not the full inherited environment, with a setting "hooks.inheritEnvironment" to restore Cursor-like inheritance.
- **Input mapping**: conversation_id = ACP sessionId; generation_id = new GUID per user prompt (host) and reused by every hook of that prompt; model/model_id/model_params from the session's `model` config option (AcpAgentSession keeps ModelOptionId "model"); cursor_version = "ompos-<version>"; workspace_roots from the session cwd list; user_email from sign-in when present else null; tool_use_id = omp toolCallId (= ACP tool call id, so preToolUse and shell hooks correlate like Cursor 3.24); tool_name mapped omp to Cursor: bash to Shell, read to Read, edit/write/ast_edit to Write, grep/ast_grep/find/glob to Grep, delete or move to Delete [INFERENCE: omp has no delete tool in BUILTIN_TOOLS, deletion is an edit patch], task to Task, web_search to WebSearch, mcp__s_t to MCP:t, everything else passes through under its omp name.

### 3.3 Consent, isolation and trust (ADR-0013)

- Tier 2 rules stay: trigger match, enabled, not quarantined, consent hash match, in that order, before any spawn (decision 2). Blocking denial reasons stay `ConsentMissing`, `PluginQuarantined`, `ExitCodeTwo`; add `InvalidResponse`, `FailClosedFailure`, `Timeout` (for failClosed).
- A hooks.json hook has no plugin; synthesise a pseudo plugin id per source file (`cursor-project:<root-hash>`, `ompos-user`, `managed`, `claude-project:<root-hash>`) so quarantine (runner fault) and the UI group correctly.
- Consent hash v2 = SHA-256 of canonical JSON of (hash-version, event, scope, command string or argv, shell kind, cwd RELATIVE to the scope root (not absolute, so the same repo consents the same on a laptop and in a sandbox), env, type, prompt text, failClosed). Matcher and timeout are NOT in the hash (changing a filter does not widen what code runs; hmm, a widened matcher does run the same code on more events: owner decision O6). Old v1 consents (absolute cwd) stay valid for plugin-manifest hooks.
- First sight of a project hooks file: Hooks page shows each command verbatim with "Consent" and "Trust all hooks in this folder" (records hashes at that moment; later edits re-prompt). Never auto-consent from the mere presence of `.cursor/hooks.json`: a freshly cloned repository must not execute code (Cursor loads project hooks only in a trusted workspace, S1). A blocking hook without consent denies the action (ADR rule), which is safe but surprising; mitigate with a one-time modal at the first blocked action ("Hook X guards this action and has no consent") rather than silent denial.
- Remote / cloud: the run request carries `consentedHashes` (snapshot of the consent store for hooks found in that repo, computed with the relative-cwd identity) and `trustProjectHooks` per environment definition. The remote dispatcher accepts a hook only if its recomputed hash is in the snapshot, else applies the ADR rule (blocking denies, non-blocking skipped). This keeps the consent decision with the human on the desktop. Cursor cloud agents auto-run project hooks; OmpOS deliberately does not unless the environment owner set `trustProjectHooks` [design choice, differs from Cursor].
- Process isolation: no shell for `args`; shell string uses `sh -c` / PowerShell with stdin payload; tree kill on timeout/cancel (existing); environment allow-list (O2); working directory must be inside the scope root unless the hook is managed (ADR-0013 risk 3, O2); stdout/stderr bounded. Hooks can still do anything the user can: state this in the consent text. Path-swap between consent and spawn (ADR risk 8) remains: mitigate by also hashing the content of the executable when the command's first token resolves to a file inside the scope root [INFERENCE, optional].
- The bridge extension and HookBridgeServer are untrusted-input endpoints: loopback only, per-session random token compared in constant time, body cap 8 MiB, JSON depth cap, one request per tool call (no streaming), reject when session closed. omp plugins have the privileges of omp (tier 1); treating the bridge's payloads as untrusted (it relays model-controlled tool input) is required, e.g. never interpolate `${file_path}`-style args into a shell string: only pass them in `args` form or via stdin.

Actions already in `IHooksSource`: enable/disable, move (within a source only; cross-scope order is fixed by priority), grant consent; add: trust folder, open file, reload, lift quarantine (PluginHost.LiftQuarantineAsync needs a reason text box).

### 3.5 Failure policy

| Case | Permission event (6) | Observe / output event |
|---|---|---|
| exit 0, valid JSON | use decision | use fields |
| exit 0, invalid JSON or schema mismatch | DENY (S1) | log Failed, ignore output, continue |
| exit 2 | DENY, agent_message = stdout JSON message else stderr text | log Denied-style Failed, continue |
| other exit code, crash, spawn failure | allow, log Failed; DENY if failClosed (S1) | continue; failClosed has no effect |
| timeout | kill process tree, allow, log TimedOut; DENY if failClosed | continue |
| no consent | DENY with ConsentMissing + page prompt (ADR rule) | skip, log Skipped |
| plugin / pseudo plugin quarantined | DENY with PluginQuarantined | skip |
| runner fault (cannot start at all, not a hook's own failure) | quarantine the source, log Faulted, then as quarantine | same |
| host dispatcher unreachable from the bridge | bridge fails OPEN for hooks that are not failClosed and fails CLOSED when the effective set contains any failClosed or managed permission hook for that event (the host writes `failClosedEvents` into the bridge's startup file) [INFERENCE] | fail open |
| prompt hook LLM error or no answer | treated as crash (fail-open unless failClosed) | n/a |
| loop limit reached (stop/subagentStop) | n/a | stop follow-ups; log "loop limit" |
| recursion (hook output triggers a prompt that fires hooks) | n/a | loop_limit plus a global depth guard of 1 for prompt hooks (their LLM call runs with hooks disabled) |

## 5. Risks and gaps

| # | Risk | Evidence / consequence | Mitigation |
|---|---|---|---|
| R1 | ACP alone cannot enforce preToolUse | omp sends session/request_permission only when policy says prompt; under yolo or for read-tier tools nothing reaches the client; `session/update tool_call` is announced for display [S7 approval-mode.md, REPO AcpApprovalPolicy] | bridge extension (U6) is required for parity; document "degraded mode" when the bridge fails to load; show it on the connection row |
