# Agent Loop and Agent Panel design (milestone v0.14.0), authoritative for all implementers

Read local://program-brief.md first. Evidence lives in local://dossier-*.md (ultrathink, swarm, substrate, gsd-omp, autonogrammer-seams, git-ci, omp-loading when it exists). Where this design and a dossier disagree, the dossier's cited source wins: report the conflict, do not guess.

## 1. Settled decisions
- D1 Plugins run INSIDE omp (they are omp plugins). Autonogrammer (a) resolves them from pinned submodules under `plugins/`, (b) launches `omp acp` with explicit loading flags and a hermetic env (nothing from the user's global omp config), (c) OBSERVES them through side channels (files, HTTP) and projects stage events, (d) renders them. No sibling source is copied or edited.
- D2 Layout: `plugins/claude-ultrathink`, `plugins/agent-swarm`, `plugins/agent-substrate` are git submodules (remote https URLs, pinned to verified remote default-branch tips: ultrathink 7cfd054, swarm c900a51, substrate 754c51a; `branch = main` in .gitmodules). `plugins/gsd-core-omp` is a tracked Autonogrammer-owned thin plugin (GSD-Core upstream has no omp runtime; see dossier-gsd-omp.md section 3).
- D3 Steering is Autonogrammer-owned: operator text is queued over ACP with the existing RunInputScheduler (queue-after-turn, owner decision F3). Substrate on main has NO live delivery (Phase 53 unmerged), so Autonogrammer only RECORDS a steering action to Substrate through `events_emit {kind:"note", payload:{action:"steer", ...}}` when reachable (event kinds and surfaces are frozen; new `payload.action` values are allowed). Never claim Substrate delivered a steer.
- D4 Stage events are data in `Autonogrammer.Contracts.Agents` (no StreamEvent kind, no ContractVersion bump): Option A of dossier-autonogrammer-seams.md section 2.4.
- D5 One `omp acp` child per session (`InProcessEngineHost` binds one session). `SessionEngineSet` in the native head owns N engines.
- D6 Substrate is reached (a) by the omp child through an HTTP entry in `session/new.mcpServers` and (b) by the host through `SubstrateGateway` (HTTP `GET /healthz`, `POST /brief`, `POST /mcp`, `POST /events/query`). Health-check first: omp FAILS `session/new` if any MCP server is unreachable, so an unhealthy Substrate is omitted and surfaced as a Degraded stage. Tokens only via env var NAMES (`SUBSTRATE_TOKEN_OMP`, `SUBSTRATE_TOKEN_FILE`, `SUBSTRATE_TOKENS_DIR`); never in argv, logs, persisted state or exceptions. NEVER point tests at the live 127.0.0.1:7410 server on this host: use fakes.
- D7 Launch and hermeticity (CONFIRMED by the live probe, local://dossier-omp-loading.md). Argument order after `omp acp`: `--no-extensions` first, then `-e <path>` once per extension in composition order: the claude-ultrathink package directory, the agent-swarm `omp/` directory, the two substrate projector files (`substrate-status.ts`, `substrate-skills.ts` under `packages/projector/omp`) and the `plugins/gsd-core-omp` directory. Use `-e` ONLY: `--plugin-dir` gives Claude-layout skills and agents but no extension code, and `-e` plus `--plugin-dir` on the same package double-registers commands. Nonexistent `-e`/`--plugin-dir` paths are silently ignored by omp, so Autonogrammer validates every path itself (the guard) and never relies on omp to complain; unknown flags are silently ignored too, so tests assert exact argv. Per-session environment from `SessionStateLayout`: `ULTRATHINK_STATE_DIR`, `SWARM_DIR`, `SWARM_GSD_STATE_FILE=` (empty), `SWARM_CLAUDE_STATE_DIR`, `SUBSTRATE_OMP_PENDING_DIR` (REQUIRED: its default is a hard-coded real-home path), `SUBSTRATE_TOKENS_DIR` only when configured; `ULTRATHINK_UPLIFT=0` only when planning is disabled; `SUBSTRATE_URL` only when Substrate is enabled and healthy (when it is unset the substrate-status extension still polls 127.0.0.1:7410, so a disabled or unhealthy Substrate means NO substrate `-e` at all); never `SWARM_AGENT` or `SWARM_TASK_ID`. Real runs inherit HOME and PI_CODING_AGENT_DIR (the user's omp credentials live there); only tests and an explicit `IsolatedHomeDirectory` setting add `HOME` and `PI_CODING_AGENT_DIR`. `AgentLoopSettings.Profile` is `Inherit` (default: the user's own ultrathink/Linear/Notion configuration applies, as it does in the omp TUI) or `Isolated` (adds the neutralising variables listed in dossier-ultrathink.md section 8 and dossier-omp-loading.md). Under `omp acp` extensions see mode "rpc" and hasUI true, widgets and notify are no-ops, so every stage is projected from files and HTTP, never from widgets.
- D8 Degradation (each is a stage event with Status Degraded/Unavailable plus a plain-text reason; none crashes the panel or the run): Ultrathink off/failed -> the original prompt flows unplanned; Swarm missing/failed -> single-agent run; Substrate unavailable -> no steering record, no shared memory, indicated in UI; GSD tools missing -> task context shows phase unknown; uninitialized submodule -> typed `SubmoduleNotInitializedException` whose message names the plugin, path and the exact fix `git submodule update --init --recursive plugins/<name>`.
- D9 Panel facts the UI must not invent: no live Ultrathink progress exists (SessionRecord is written once planning finishes), so the Ultrathink stage is Running from prompt send until its session file appears, then Succeeded with the graph; Swarm state comes from `<SWARM_DIR>/.swarm/live.json` and `events.jsonl`; substrate panels must not show ledger `summary`/`payload` text (docs/panel-event-contract.md), only ts, surface, kind, actor, payload.action/item/outcome; memory/lesson note bodies are untrusted plain text, length capped, never markup.

## 4. AgentLoop library `src/Autonogrammer.Harness.AgentLoop` (L2, may use Process; refs Autonogrammer.Contracts and Autonogrammer.Harness.Abstractions only; tests in `tests/Autonogrammer.Harness.AgentLoop.Tests`). The orchestrator creates both csproj files and registers them (slnx, slnf, LayerMap, ArchitectureTests ref, locks); implementers only add .cs files in their own folders.
Folders and owners:
- `Plugins/` (task CAT): `OmpPluginDescriptor` (Id, DisplayName, Role {PromptPlanner, SubagentOrchestrator, SessionSubstrate, WorkflowEngine}, RelativeDirectory, Loading {Extension, PluginDirectory}, EntryRelativePaths, Required), `OmpPluginCatalog.BuiltIn` (ultrathink, swarm, substrate, gsd; order = composition order Ultrathink, Swarm, Substrate, Gsd), `OmpPluginResolver.Resolve(pluginsRoot, descriptor)` -> `ResolvedPlugin` with `PluginHealth {Ready, SubmoduleNotInitialized, EntryMissing, ManifestInvalid}` (reads package.json omp.extensions / pi.extensions without executing anything), `SubmoduleNotInitializedException`.
- `Launch/` (task CAT): `AgentLoopSettings` (PluginsRoot, StateRoot, UltrathinkEnabled, SwarmEnabled, SubstrateEnabled, GsdEnabled, SubstrateEndpoint?, SubstrateTokenEnvName), `OmpLaunchPlan` (ExtraArguments, Environment, McpServers, WorkingDirectory, ConfigOverlayPath?; `ToString()` never prints env values), `AgentMcpServerSpec` (Http only), `OmpLaunchPlanner.Plan(...)` (pure: no IO; takes resolved plugins + health result), `ConfigOverlayWriter` (owner-only per-session file, deleted on dispose; use the pattern of `src/Autonogrammer.Sandbox/OwnerOnlyFiles.cs` but do not reference Sandbox: re-implement with `UnixFileMode`).
- `Stages/` (task OBS-A): `UltrathinkStateObserver`, `SwarmLiveObserver` implementing `IStageSource` (read dossier-ultrathink.md sections 3 and 5, dossier-swarm.md section 4). Pure parsing helpers are separate internal types so tests feed fixtures. Unknown/extra vendor fields are ignored; a malformed file yields a Degraded stage event, never an exception.
- `Substrate/` and `Gsd/` (task OBS-B): `SubstrateGateway` (HttpClient injected; health, brief, tool call, events emit/query; bounded response size; no redirect to other origins; bearer from env var name), `SubstrateStageObserver : IStageSource`, `SubstrateTaskContext`, `GsdToolsClient` (runs `node <gsd-core>/bin/gsd-tools.cjs query ... --project-dir`, JSON on stdout, bounded output, kill on cancel, cached by .planning mtime), `GsdStateObserver : IStageSource`, `GsdTaskContextSource : ITaskContextSource` (merges GSD phase + Substrate brief/lessons, each part optional).
- `Sessions/` and `Composite` (task REG): `AgentSessionRecord` + `AgentSessionRegistry : ISessionCatalog` (N sessions; versioned JSON via a source-generated context; atomic temp+rename; corrupt/unknown-version file is quarantined (renamed `*.quarantined-<utc>`) and treated as empty; never throws on load; per-session `Touch`, `SetGraphId`, `SetLifecycle`; `Lost` detection when a Running session's heartbeat is stale via injected `TimeProvider`), `CompositeStageSource : IStageSource` (merges sources, isolates one source's fault into a Degraded StageEvent for that source, bounded channel, honours cancellation, disposes children).
Rules: all public/internal types sealed with XML docs; `ConfigureAwait(false)`; `TimeProvider` injected, never `DateTime.UtcNow`; no `Task.Result`; JSON via source-generated contexts only (`JsonSerializerIsReflectionEnabledByDefault=false`); file reads capped (use a 1 MiB cap helper local to the project); child process output capped (4 MiB) and killed on cancel; no static mutable state.

## 5. ACP plumbing (task P0, `src/Autonogrammer.Harness.Acp`, tests `tests/Autonogrammer.Harness.Acp.Tests`)
Add to `AcpClientOptions`: `ExtraArguments` (IReadOnlyList<string>, appended after `acp`), `EnvironmentVariables` (IReadOnlyDictionary<string,string>), `McpServers` (IReadOnlyList<AcpMcpServer>; abstract record with `AcpStdioMcpServer(Name, Command, Args, Env)` and `AcpHttpMcpServer(Name, Url, Headers)`). `AcpStdioTransport` gets an overload `(ompPath, workingDirectory, arguments, environment, logger)` and applies them (`ArgumentList.Add` per arg, `startInfo.Environment[k]=v`; the child still inherits the parent environment unless a key is overridden). `AcpFrames.NewSessionParams` and `LoadSessionParams` carry typed MCP server DTOs (env/headers as `[{name,value}]`; `type` only for http/sse; stdio has `command` and no `type`), through the source-generated `AcpJsonContext`. `OmpAcpClient.SpawnOmpAcp` passes options through. Tests: a `FakeOmp`-style script that echoes `"$@"` and selected env names to a file asserts the exact argv order and env; `session/new` params contain the MCP specs; a rejected `session/new` surfaces `AcpRequestFailedHarnessException`. Keep `AcpApprovalPolicy`, handshake and logging behaviour untouched.

## 6. Presentation (task PRES, `src/Autonogrammer.Presentation/AgentPanel/`, namespace `Autonogrammer.Presentation.AgentPanel`, tests `tests/Autonogrammer.Presentation.Tests/AgentPanel/`). Framework-neutral (no Avalonia), `ObservableModel` base, reference only Contracts, GenUi, Parser.
Types: `StageTimelineModel` (folds `StageEvent` into ordered stage rows grouped by Source in pipeline order, children by `ParentStageId`; unknown Source/Status degrade to a generic row; announces stage transitions through a `StatusAnnouncement` string for the live region, not per token), `SessionCatalogModel` (wraps `ISessionCatalog`; rows with title, `RuntimeStatus` mapping via existing `RuntimeStatusMap`/Kanban types, relative last-activity text from an injected `TimeProvider`, stale/long-running flags, filter, selection), `TaskContextModel` (loads `ITaskContextSource` for the selected session; states Loading/Ready/Partial/Unavailable; notes capped and plain text), `SteeringInputModel` (wraps the existing `RunInputScheduler`: Steer vs Follow-up while a run is active, count of held messages, cap message shown when refused, optional `ISteeringRecorder` callback, which the head binds to the Substrate record), `AgentSessionViewModel` (composes the existing `SessionViewModel`, `ComposerViewModel`, run controls models, timeline, context, steering), `AgentPanelViewModel` (sessions, selected session, panel state `Empty | Loading | Ready | Error`, banner text with retry command, `NewSessionCommand`, `SelectSession`, `CloseSession`). Read the existing types first (`src/Autonogrammer.Presentation/State`, `Runs`, `Kanban`, `Agents`, `Chats`, `Approvals`) and reuse them; do not duplicate.

## 8. Composition (task SHELL, `apps/Autonogrammer.Native/Engine/*`, `Program.cs`, `App.axaml.cs`, `MainWindow.axaml.cs`)
`SessionEngineSet` creates one `InProcessEngineHost` (via `EngineComposition`) per session from a per-session `OmpLaunchPlan`; `EngineComposition.Compose` accepts the plan, sets `AcpClientOptions.WorkingDirectory`/`ExtraArguments`/`EnvironmentVariables`/`McpServers` (keeps the in-flight ILoggerFactory wiring). Plugins root resolution: `AUTONOGRAMMER_PLUGINS_ROOT` env name, else `plugins/` next to the repository root discovered from the executable or current directory; if the plugins are not initialized the panel still opens, the plugin stages show Unavailable with the fix text, and sessions run as plain omp.

## 9. Tests (every implementer)
Behaviour tests only: degraded paths (each plugin missing/failing), cancellation leaves no child process, bounded reads, corrupt state quarantined, scope isolation (a registry or observer never reads another session's directory), concurrency (N sessions keep independent state), argv/env exactness, secret redaction (tokens never appear in `ToString`, logs, persisted files), a11y walk of the opened panel. Use `FakeTimeProvider`, temp dirs, `FakeOmp`, scripted ACP transports (see dossier-autonogrammer-seams.md section 7). No fixed sleeps.

## 10. Cross-task signatures (exact; tasks code against these without waiting for each other)
Namespaces: `Autonogrammer.Harness.AgentLoop.Launch`, `.Plugins`, `.Stages`, `.Substrate`, `.Gsd`, `.Sessions`. All types public sealed unless stated.

`Launch/SessionStateLayout.cs` (task CAT) static class, every method validates its inputs (`ArgumentException.ThrowIfNullOrWhiteSpace`; a session id must match `^[A-Za-z0-9_.-]{1,120}$` and must not be `.` or `..`, else `ArgumentException`):
`SessionDirectory(string stateRoot, string sessionId)` = `<stateRoot>/sessions/<sessionId>`; `UltrathinkDirectory(string sessionStateDirectory)` = `<dir>/ultrathink` (value of ULTRATHINK_STATE_DIR); `UltrathinkSessionFile(string sessionStateDirectory, string acpSessionId)` = `<dir>/ultrathink/sessions/<acpSessionId>.json` (id kept verbatim when it matches `^[a-z0-9_.-]{1,120}$`, otherwise slug + `~` + first 16 hex of SHA-256, exactly as dossier-ultrathink.md section 0/2 says: `src/claude/state.ts:139-153`); `SwarmDirectory(dir)` = `<dir>/swarm` (value of SWARM_DIR); `SwarmLiveFile(dir)` = `<dir>/swarm/.swarm/live.json`; `SwarmEventsFile(dir)` = `<dir>/swarm/.swarm/events.jsonl`; `ClaudeStateDirectory(dir)` = `<dir>/claude-state`; `SubstratePendingDirectory(dir)` = `<dir>/substrate-pending`.
