### Auth model (config.ts 297-345, 721-830; server.ts 793-819)
- Identity = bearer token -> **surface** (`SURFACES` in types.ts:45-62): `claude-code, cursor, hermes, omp, muse, grok-build, grok-bot, codex, opencode, pi, rivet-agentos`, 30 `swarm-a01-orch .. swarm-a30-custody`, `substrate` (host jobs). **`omp` is a first-class surface.**
- Server config: `SUBSTRATE_TOKEN_<SURFACE>` (surface upper-cased, `-`->`_`), each a comma/space-separated LIST of bearer values (e.g. `SUBSTRATE_TOKEN_OMP=abc,def`, `SUBSTRATE_TOKEN_SWARM_A05_BE=..`).
- **Operator** = a surface token value that is ALSO listed in `SUBSTRATE_OPERATOR_TOKENS` (comma list). Operators may `graph_release/graph_complete force:true`, `memory_search include_expired`, `skills_approve`, `skills_list state!=approved`. No `swarm-*`/`substrate` surface can be operator (fail closed + boot warning). Memory review (release of `global`, `human-confirmed`) uses `SUBSTRATE_MEMORY_REVIEW_TOKENS`.
- `SUBSTRATE_ALLOW_ANONYMOUS`: unset => anonymous accepted ONLY when no `SUBSTRATE_TOKEN_*` configured (bare local run); `1` => anonymous bridge (tokens recognised, untokened callers still accepted, but may not emit/claim as a surface that has a token; `coord_handoff` refused for untokened); `0` => bearer required always.
- Unknown/unmapped bearer -> 401 even in anonymous mode. Public-edge header `x-substrate-edge` (set only by nginx vhost) forces bearer for everything but /healthz.
- Surface-bound tokens: swarm and `substrate` tokens cannot name another surface (403). Other tokens: body-declared `surface` for events (attribution-by-declaration, panel-event-contract R17), but `memory_write` writer always = token surface (anonymous writes as `unknown`, which holds no grants).
- Client token resolution (CLI + omp extensions): `SUBSTRATE_TOKEN` env, else file `SUBSTRATE_TOKEN_FILE`, else file `<SUBSTRATE_TOKENS_DIR or /etc/substrate/tokens>/<surface>` (first line). Sent only as `Authorization: Bearer`.
- Handoff signing key `SUBSTRATE_HANDOFF_KEY` (+`_ID`, `_PREV`, `_PREV_ID`); absent => packets recorded UNSIGNED (`signed:false`).

## 7. Isolation model (memory/lessons/leases/events)
- Scope strings: `graph:<id> | repo:<owner/name> | global | agent:<surface> | person:<name>`. Writes are default-deny RBAC on surface x scope-class x kind (`memory-policy.ts`; grants `graph-any`, `repo-working`, `agent-self`, `global-standing`; widen only via `SUBSTRATE_MEMORY_GRANTS`; no narrowing var). `global` writes are proposals needing a reviewer token. Quarantine pass rejects secrets/PII/speculation.
- **Reads are NOT access-controlled by scope** (docs/memory-governance.md:475-476: "Scope is the caller's filter, not an authorisation: reads carry no per-scope RBAC"). `memory_search` without `scope` searches every scope in the one shared index; any authenticated surface can read `repo:` and `graph:` memories of every project. Exceptions: `agent:` rows only to the same surface AND only when caller passes the matching `repo` (rows without repo are read by nobody); quarantined/unreviewed never returned. `graph_get`, `events_query`, `docs_search`(shared corpus, `repo_id` is a cache tag only) are all cross-project readable by any surface token. `memory_brief` composes per repo/graph but also lists "other open graphs" and recent agent actions.
- **A host that must guarantee no cross-project leakage cannot rely on substrate**; it must (1) always pass explicit `scope` (`repo:<owner/name>`) and `repo` on every call and reject model-supplied overrides in its own proxy, (2) not hand raw substrate tokens/MCP endpoints to agents, or (3) run a separate substrate (separate PG/Greptime) per trust domain. UNKNOWN: whether per-repo token scoping exists (none seen in config.ts; `grep -n repoScope packages/mcp-server/src/config.ts`).
- Redaction (docs/redaction.md, `redact.ts`, 39 named rules: PEM, Bearer, password/assignment `*_TOKEN|*_KEY|*_SECRET`, github/linear/notion/anthropic/openai/xai keys, tailscale `tskey-`, URL passwords ...): single module applied on event summaries/payloads, memory bodies, skills, diagnostics; lock test forbids a second redactor. Payload strings capped; handoff packets are redacted+capped+size-fitted THEN signed. Lease ids never appear in ledger events/briefs (holder only).
- Identity isolation between sessions: surface-level token only (see section 5 caveat).

## 8. Risks for a C# host
1. **Not on main**: Phases 52-54 (planning index, steering inbox, presence) are unmerged draft PRs; any Autonogrammer UI relying on "steering delivery" or `planning_sessions` has no server today. Pin to main `754c51a`; this branch is 4 commits behind main and is docs-only vs main.
2. **No push channel**: MCP is stateless HTTP; the only stream is SSE `/events/stream` which is loopback-only, bearer-required, and 503 without Greptime; frames omit payload; 500 ms poll latency; Dragonfly bus optional. Browser/WASM head cannot call it directly (Host/Origin guard 421/403) - route through Autonogrammer.Api.
3. **Tailscale/Railway**: production stores (Greptime, Timescale/Postgres, Dragonfly, Hindsight, RAGFlow) sit on Railway behind Tailscale forwarders (`docs/railway-tailscale.md`, `SUBSTRATE_DB_PROXY_ALLOW`, `SUBSTRATE_DB_ENDPOINT_MODE`); tailnet host names must never be written into repos/PRs (AGENTS.md). Autonogrammer must treat `SUBSTRATE_URL` as configuration, default `http://127.0.0.1:7410`, never embed endpoints. `publicOrigin` defaults to `https://substrate.swcstudio.space`.
4. **Token handling**: tokens live in `/etc/substrate/tokens/<surface>` (0600 root) and `/etc/substrate/*.env`; the omp extensions read them from disk each call and hard-code `~/.omp/...` and `/etc/substrate/tokens` defaults. A C# host should read `SUBSTRATE_TOKEN`/`SUBSTRATE_TOKEN_FILE` the same way (same order), send only `Authorization: Bearer`, never log; tokens are surface-scoped, operator authority is a server env list. Anonymous mode only when NO tokens configured; once any `SUBSTRATE_TOKEN_*` is set, an untokened client gets 401. The live host has tokens configured (token files for 10 surfaces) so Autonogrammer dev against `127.0.0.1:7410` needs the `omp` token (UNKNOWN whether anonymous bridge is on: resolve with an authenticated-free `curl -X POST /brief` only if the operator permits writes to audit; avoided here).
5. **Shared live instance**: development traffic hits the production ledger/index (append-only hash-chained ledger cannot be scrubbed; leases mirror to real Linear/Notion when keys configured). Autonogrammer tests must use a scratch instance, never the live 7410.
6. **Closed vocabularies**: `EVENT_KINDS` (12), `SURFACES` (closed enum) are locked by `check:phase-close`; new Autonogrammer surfaces/kinds need a substrate phase. Use `payload.action` for new concepts.
7. **Extensions track the mutable checkout** via symlinks (live omp loads whatever branch is checked out in `~/src/repos/agent-substrate`); production server runs a pinned release (`/opt/agent-substrate/releases/<sha>`), so extension and server versions can skew.
8. **Dirty tree noise**: agent-swarm hooks write `.planning/STATE.md` lines and `.claude/swarm-state.json` into this repo; keep Autonogrammer submodule pointer on a clean commit.
9. **Bun/TS dependency**: server requires Bun 1.4.0 (`import { SQL } from "bun"`); not runnable on Node. C# host must launch/point to an external process; no in-process embedding. omp extensions are TS run inside omp.
10. **Fail-closed paths**: with durable audit or ledger down, `graph_*`/`memory_write`/`coord_handoff` return errors/503; C# client must distinguish `claimed:false` (normal contention) from errors and handle `ok:false` heartbeat reasons (`lost|expired|unheld|not-holder`) by stopping work.
