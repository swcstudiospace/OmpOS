### 3.3 Envelope signing and fail-closed behaviour (swarm/envelope.py)
- Signature REQUIRED for `task.assign`, `gate.verdict`, `quality.gate.verdict`, `review.verdict`, `security.gate.verdict`, `promote.command`, `rollback.command`, `conflict.arbitration`. ## 5. Concurrency, limits, cancellation

- Two execution paths:
  (a) **In-omp `/swarm`** (what OmpOS gets by loading the extension): `/swarm` plans in python, then the main omp session calls `task` -> `a01-orchestrator`; A01 fans out ready lanes in one turn (several `task` calls; same slug may repeat; disjoint blast radii parallel; join then one Greptile review). Concurrency/time limits there are **omp's** (`task.maxRecursionDepth` default 2). `UNKNOWN: omp's task concurrency setting name/default: omp config list | grep -i task`. swarm_run.py/limiter/leases are NOT used on this path.
  (b) **`scripts/swarm_run.py` headless runner** (also launched by `hooks/autonomous_run.py`): per task `omp -p --mode json --no-title -e <abs omp dir> --cwd <repo> --approval-mode write --tools <frontmatter tools>,yield --append-system-prompt <SWARM_DIR>/agents/<slug>.md --max-time <n>s [--model M]` (`--runtime omp`; `auto` never picks omp; claude/grok alternatives; grok dispatch refused). Env for sessions: `SWARM_DIR SWARM_CHILD=1 SWARM_AGENT_SESSION=1 SWARM_AGENT=<slug> AIO_UPLIFT=0 AIO_SWARM=0`; result = `yield` payload of the terminal `agent_end` (fallback: last fenced json block).
- swarm_run limits: `--max-parallel` (default `SWARM_MAX_PARALLEL` else 4; ceiling 32), per-agent `agents.json max_parallel`, `--max-rounds 50`, `--max-turns 40`, `--task-timeout 1800` s (omp `--max-time` = timeout minus margin `min(60,max(5,timeout//10))`), `--swarm-timeout 0` (off), `SWARM_SCHEDULER` continuous|rounds, circuit trip `SWARM_FAIL_STREAK` (3 consecutive failures of distinct tasks), `INTERNAL_FAILURE_LIMIT=3`.
- `swarm/limiter.py` `AimdLimiter(max_n, min_n=1, cooldown)`: rate-limit signal (`detect_rate_limit`: HTTP 429, "rate limit", "overloaded", "quota", `Retry-After`) halves cap (floor min_n) and holds growth for `max(cooldown 60 s, Retry-After clamped to SWARM_RETRY_CAP_S=120)`; each success after the cooldown adds 1 up to max.
- `swarm/retry.py`: `backoff_s(attempt)=min(cap, base*2^(attempt-1))`, jitter +/-25%, base 0.1 s, cap 5 s (mirrors Rust gsd-failure); transient (retried) = `E-TIMEOUT E-DEP E-CAPACITY E-CONTRACT`; permanent (never retried) = `E-INPUT E-POLICY`; unknown text retried only if rate-limit detected. Task ladder: FAILED -> RETRY (bounded by `max_attempts` 3) -> ESCALATED; CHANGES_REQUESTED bounded by `MAX_REWORK_LOOPS=2` then ESCALATED.
- Cancellation:
  - in-omp bridge: AbortSignal or `session_shutdown` -> `killpg(SIGTERM)`, SIGKILL after 3 s; a deadline abort -> `E-TIMEOUT`; a cancelled call never returns success (D-07).
  - a running specialist subagent (omp `task` tool) is owned by omp; the extension only reaps its own python children. `UNKNOWN: how omp cancels task children on ACP session/cancel`.
  - swarm_run: SIGINT/SIGTERM/SIGHUP or `--swarm-timeout` -> writes `<swarm_dir>/cancel/<correlation_id>` = `{requested_wall, reason, grace_s}`, waits `SWARM_CANCEL_GRACE_S` (10 s) for sessions to leave, then SIGTERM -> 5 s `KILL_GRACE_S` -> SIGKILL of session process groups; whole shutdown fits `SWARM_SHUTDOWN_BUDGET_S` (15); a second signal = force. A host can cancel an external runner by signalling it or writing that cancel file.
- Autonomy levels (02-message-protocol.md section 5): **L0** observe only; **L1** act and log (post-hoc audit); **L2** act and notify; **L3** approval required (human or designated agent); **L4** human-only (agent may propose, never execute). Each agent declares `autonomy_ceiling` per action class in agents.json; operator policy can only LOWER. Enforcement: agents `yield {state:"BLOCKED", needs:"human-approval: ..."}` for L3/L4; guard blocks with `BLOCKED needs: human-approval (<capability>: <rule>)`.
- Gates by risk: see 3.2. Gate owners: quality=a08-qa, review=a09-reviewer, security=a10-security, release=a12-release; `waive` needs `extra.waived_by` (human, L3); verdict expiry `expires_s` default 86400; severities `info<minor<major<critical<blocker`, >= major => fail.

### Ultrathink

So GoT nodes/waves are consumed ONLY through this explicit script + file; the omp `/swarm` command does NOT read ultrathink WORKFLOW waves. `UNKNOWN: whether claude-ultrathink emits that exact summary shape: grep -rn "waves\|graphId" ~/src/repos/claude-ultrathink/src`.
  3. Bar rank 10 vs ultrathink rank 20 on the shared `bars:restack` channel.
  4. `swarm/hook_trigger.py` (via `hooks/on_a01_complete.py`) detached-launches omp with the verbatim prompt `/gsd-autonomous workflowz ultrathink orchestrate after a01 <corr> sid=<sid>` (`-e <omp ext> --cwd <target> --approval-mode write`; env minus signing material, `SWARM_AGENT=a01-orchestrator SWARM_CHILD=0 AIO_SWARM_AFTER_ORCH=1`); skipped for cloud agents (`CURSOR_AGENT|CURSOR_CLOUD_AGENT|CLOUD_AGENT`); dedupes via a trigger store; emits `swarm.start`.

### Substrate (everything fail-open when absent)
- Off unless `SUBSTRATE_URL` (http/https) is set and `SUBSTRATE_DISABLED != 1`; **when off no socket is opened**; any failure => None. Doors: REST `POST {SUBSTRATE_URL}/events` (tee) and MCP JSON-RPC 2.0 `tools/call` on `POST {SUBSTRATE_URL}/mcp`. Bearer from `SUBSTRATE_TOKEN` or `SUBSTRATE_TOKEN_<SURFACE>` (A01 surface `swarm-a01-orch`; A02..A30 -> `swarm-a02-req` ... `swarm-a30-custody` per `substrate_tee.AGENT_SURFACES`). Timeouts: 1.5 s per socket op (+0.5 s slack), body cap 1 MiB, 30 s back-off after a network failure, redirects never followed, HTTP(S)_PROXY honoured. No default URL.
- **correlation_id -> Graph ID**: Graph ID regex `ut-[0-9a-z]+-[0-9a-f]{8}` (`ut-<base36 epoch ms>-<8 hex>`, same format ultrathink mints). `orch_plan._bind_graph` (only with substrate on; fail-open; invalid `--graph-id` -> E-INPUT): offered id = `--graph-id` > env `SUBSTRATE_GRAPH_ID` > Graph ID found in the brief (`<ISSUES graphId="ut-...">` or `Graph ID: ut-...`) > freshly minted; sends MCP `graph_bind {correlation_id, graph_id}` as surface `swarm-a01-orch`; the SERVER's winner is used (`status created|existing`); cached in `<swarm_dir>/substrate-tee.db` table `bindings_by_server(substrate_url, correlation_id, graph_id, created)` (valid only for the server that made it); then `graph_register` records the node set. The Graph ID never enters stored notes or the brief hash, so re-planning the same brief still reuses. Substrate off => no Graph ID is bound at all. docs/substrate-integration.md: the mapping is "a correspondence, not string equality; one swarm run == one substrate graph".
- Tee: `runlog.emit` -> `substrate_tee.tee` maps each swarm event type to a substrate EVENT_KIND (`session.start prompt claim tool.call file.edit shell commit pr handoff session.end note warning`) and POSTs `/events` with the issuing agent's own token; dedupe table `seen(surface,msg_id,state)` 24 h; dry runs never tee (`tee=False`); session id format `<AGENT>@<replica>:<graph_id>`.
- Leases (`swarm/substrate_lease.py`, used by `swarm_run.py` ONLY): the runner claims `graph_claim` per task as that agent's surface, heartbeats every TTL/3, `graph_complete` at DONE, releases otherwise; TTL default 900 s (clamped 30..86400, `SWARM_LEASE_TTL_S`). Claim statuses `held|denied|refused|busy|unleased|off`. No answer / server error / no Graph ID bound => **task runs UNLEASED** (fail-open; `notes.lease` = `unleased` + reason, event `lease.unleased` severity warning). A REFUSAL (server answered "no") => task NOT dispatched; `denied` waits; heartbeat refusals mid-session: `expired` => re-claim under a new id; `lost|unheld|not-holder|refused` => stop session and FAIL task (retry ladder then ESCALATED). Local request-slot contention defers dispatch. Docs `docs/substrate-leases.md`.
- Handoffs (`substrate_handoff.py`): signed `coord_handoff` packets at agent boundaries (accountable agent changes, failing gate, escalation) + context rebuilt from the ledger into each assignment; events `handoff.unsent|unsigned|refused|misattributed`. Memory (`memory.py`): governed write through the substrate write door. Workspace wiring (`scripts/_install_substrate.py`, `swarm/workspace.py`): projects MCP entry `substrate` = `{type:"http", url:"${SUBSTRATE_URL}/mcp", headers:{Authorization:"Bearer ${SUBSTRATE_TOKEN}"}}` into `.mcp.json` (claude/omp), `.grok/config.toml`, `.cursor/mcp.json`; per-agent token env files at `${XDG_CONFIG_HOME:-~/.config}/agent-swarm/agents/<workspace key>/<slug>.env` (dir 0700, file 0600, contents `SUBSTRATE_TOKEN=...`).

## 8. Risks for the C# OmpOS host

1. **Pinning**: HEAD `27d2294` is local-only and the working tree is dirty (142 paths of real WIP). Pin the submodule to a pushed commit (origin/main `c900a51`; omp/swarm/scripts/agents.json are byte-identical to local HEAD). `.gitmodules` must use `https://github.com/swcstudiospace/agent-swarm.git`, never a local path. Do not modify the sibling's dirty tree.
2. **Native-extension trap**: the dirty tree (and likely a future v2.4 merge) makes `import swarm` fail unless `swarm._native` is built (PyO3/maturin/cargo 1.98.1/Python 3.12/Linux x86_64) or `SWARM_PURE_PYTHON=1`. The omp bridge forwards `process.env`, so the host can set `SWARM_PURE_PYTHON=1` defensively; it is a no-op on origin/main.
3. **Keys/secrets**: `/swarm` dispatch needs a real signing key in the omp process env, or `SWARM_ED25519_KEY_FILE` (absolute), or `~/.config/agent-swarm/signing-key.hex`; absent => planning works but dispatch is refused with `/swarm dispatch refused: ...`. `SWARM_ALLOW_INSECURE_DEV_KEY=1` is a dev-only escape hatch (public dev key; `security.dev_key` event per sign). The host must never log/echo env values. A key placed in omp's env is inherited by every in-session `task` subagent process (the runner strips it only for swarm_run-spawned sessions; the guard only denies reads of signer FILES and forging commands).
4. **Substrate absent**: all substrate calls are no-ops (no socket); no Graph ID is bound; leases/handoffs/memory/tee inactive; no error surfaced. Substrate present and refusing => swarm_run refuses to dispatch that task; the in-omp `/swarm` path never claims leases at all (leases live only in swarm_run.py), so non-leased execution is the norm there.
5. **Writes outside the submodule dir / into user state**:
   - `<git toplevel of omp cwd>/.swarm/` (+ self-written `.swarm/.gitignore` = `*`) in the USER's workspace (the OmpOS repo root if omp's cwd is inside OmpOS) unless `SWARM_DIR` is set; `events.jsonl` grows without bound (this repo's own = 79 MB).
   - `/swarm` startup writes `<cwd>/.claude/swarm-state.json` (creates `.claude/`), `<swarm_dir>/swarm-state.json`, `<swarm_dir>/gsd-lifecycle-audit.log`, and **APPENDS `swarm: <corr> LOADING|INITIALIZING ...` lines to `<cwd>/.planning/STATE.md` if that file exists** (swarm/state_store.py `append_gsd_line`; OmpOS has `.planning/STATE.md`). Mitigate with env `SWARM_GSD_STATE_FILE=` (empty string disables the mirror) and `SWARM_CLAUDE_STATE_DIR=<dir>`.
   - Bridge writes `<swarm_dir>/results/{ingest,findings}-<toolCallId>.json`.
   - `$HOME`: the extension only READS `~/.config/agent-swarm/signing-key.hex` and `~/.omp/agent/token-opt/live.json`; writes to `~/.config/agent-swarm/agents/...` happen only when `_install_substrate.py` is run explicitly; `_install_omp.py` writes only `<ws>/.omp/`.
   - `hooks/on_a01_complete.py` -> `hook_trigger` can spawn a detached `omp ... /gsd-autonomous workflowz ultrathink orchestrate` process; it is a Claude-style hook, not auto-run by omp.
6. **Process model**: every tool call cold-starts `python3` (600 s timeout, own process group). `/swarm` blocks its command handler until the dispatch turn ends (hold cap 30 min with UI, unlimited without) - under `omp acp` that may hold the ACP prompt open. `UNKNOWN: ACP behaviour of extension commands (ctx.hasUI/mode)`.
7. **Observability under ACP**: the bar widget is TUI-only; headless stderr lines only for `print|json` modes. The host must poll `<SWARM_DIR>/live.json`, tail `events.jsonl`, and read `tasks.db` read-only (or call `orch_status --json`), plus ACP session updates / `task` tool calls from omp. `swarm.run.*` events and activity-rich `runs[]` come from `swarm_run.py`; in-omp `/swarm` runs only yield Task-Store-derived rows (`producer:"derived"`), updated when A01 uses `swarm_transition`/`swarm_ingest`.
8. **Identity env collisions**: `inSwarm` is true for any top-level session with `SWARM_AGENT` or `SWARM_TASK_ID` set. Do NOT export those in the host's own omp env or the operator session becomes guarded and A01-only tools get blocked. The bridge strips `SWARM_TASK_ID/SWARM_CORRELATION_ID` only for python children, not from omp.
9. **Guard breadth**: in swarm sessions the guard blocks `eval`, `xd://run_code`, `xd://debug`, MCP-device writes, and a large bash RULES table including prod markers (`main|master|prod`): subagents get `BLOCKED needs: human-approval (...)` tool errors that the UI must surface as blocked/needs-approval states.
10. **Tracked state file**: `.claude/swarm-state.json` is TRACKED in the sibling repo and rewritten by runs; running swarm with cwd inside the submodule dirties it. Never run omp with cwd inside the submodule checkout.
11. **Size**: 30 agent prompts (~55 KB each), `agents.json` 2.5 MB, 407 skills; static but heavy to load; guard.ts (3614 lines) and swarm_bar.ts (2983 lines) are the largest TS files.
12. Other local worktrees (`agent-swarm-amend`, `-split`, `-prompt-bindings`) hold unmerged branches (e.g. unleased-task amendment, tool-bound subagent prompts) that are NOT on origin/main; this dossier describes the origin/main == local HEAD runtime for omp/swarm/scripts.
