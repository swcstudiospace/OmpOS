### What does NOT need a change for a `src/` library
* `deploy/api.Containerfile` and `deploy/worker.Containerfile`: both do `COPY src/ src/` (`api.Containerfile:22`, `worker.Containerfile:26`) then `dotnet restore <service>.csproj --locked-mode` (`api.Containerfile:27`, `worker.Containerfile:30`). A new library under `src/` is picked up automatically, but ONLY if its `packages.lock.json` is committed (comment at `api.Containerfile:26`). `.containerignore` excludes `bin`, `obj`, `.planning`, `plugins`.
* A NEW service under `services/` needs its own `COPY services/OmpOS.<Svc>/ services/OmpOS.<Svc>/` and publish lines, a `/services/` slnx entry, an slnf entry, a LayerMap L3 entry, a `deploy/<svc>.Containerfile` modeled on `deploy/worker.Containerfile`, and (if Railway-hosted) CI/runbook updates `[INFERENCE from 3171ee8 which did this for AgentWorker]`. `deploy/compose.yaml` was touched by `3171ee8` (+30 lines) for the worker profile.
* `.github/workflows/ci.yml` and `bootstrap.sh`: no per-project lines; both use the slnf. Exceptions: new test services (section 6) and the Android job (`ci.yml:157-193`, restores `apps/OmpOS.Android` alone).
* `.gitleaksignore`: only when test fixtures trip gitleaks (three entries name Remote tests, lines 26-29).

### Guards a new project trips by name or content
* `BannedSymbols.NoProcess.txt` (`T:System.Diagnostics.Process`) applies to every project EXCEPT names starting `OmpOS.Harness.` and `OmpOS.Sandbox` and any `*Tests` (`Directory.Build.props:55`). Computer Use / Browser Use code that spawns processes MUST live in a `OmpOS.Harness.*` project (or `OmpOS.Sandbox`). `BannedSymbols.txt` bans Newtonsoft.Json, `Task.Result`, `Task.Wait()`, `Process.Start(string)` everywhere.
* `ProjectGraphTests.ProjectGraph_WebNeverReferencesProcessSpawningAssemblies` (`ProjectGraphTests.cs:12,36-41`): `OmpOS.Web` must not reference `Harness.Acp`, `Harness.Rpc`, `Sandbox`. `ProjectGraph_RejectsApiReferenceFromNonTest`: nothing references `OmpOS.Api`.
* `TodoMarkerScanner`: uppercase `TODO|FIXME|HACK|XXX` in any first-party `.cs/.csproj/.props/.sh/.yml/.json/.slnf/.slnx/...` fails the gate unless an OQ row with an owner covers it (`TodoMarkerScanner.cs` doc comment; `docs/` and `.planning/` are skipped).
* `DeferredScopeTests`: identifiers `ADE-21`, `ADE-22`, `vscode` may not appear in code.
* `RepoHygieneTests`: no `Dockerfile*`/`docker-compose*` file names; no Docker words in `bootstrap.sh`, `ci.yml`, `deploy/compose.yaml` (Podman only).
* `GateParityTests` (`GateParityTests.cs:18-25`): the repo-check script list in `bootstrap.sh` and `ci.yml` must match; adding a gate step means editing both.
* `scripts/ci/check-licences.sh` item 8: no csproj may set `PackageLicenseExpression` other than AGPL-3.0-or-later or `PackageLicenseFile`.
* Rename caveat `[INFERENCE]`: `ProjectGraphChecker.FindRepoRoot` looks for the literal file `OmpOS.slnx`; `LayerMap` keys equal csproj names; `bootstrap.sh`, `ci.yml`, ~25 docs/tests name `OmpOS.Linux.slnf`; `Directory.Build.props` `Product`, `RepositoryUrl`; `check-licences.sh` greps `NOTICE` for `https://github.com/swcstudiospace/OmpOS`. A rename of projects/solution is a large cross-cutting change, not part of adding a project.
* `VersionPrefix` bump (0.15.0 -> 0.16.0) relocks all ~85 lock files (they embed `[0.15.0, )`, `Directory.Build.props:8`), and the `0.15.0` default in `deploy/api.Containerfile:102` (`ARG OMPOS_VERSION`).

## 7. Implications for the autonogrammer program (facts + inference)
* One new library per cohesive module is cheap (13 steps, mostly mechanical), but steps 3-6 must land in the same commit as the project, or the gate silently ignores it (`fd8f335` vs `3171ee8`).
* Accounts/Supabase (HTTP client, JWT), DragonflyDB (already `StackExchange.Redis` 3.4.5, `OmpOS.Coordination.Dragonfly`), TimescaleDB (`Npgsql` 10.0.3, `OmpOS.Sessions.Postgres`), GreptimeDB (compose service exists, no .NET client pinned: grep of `Directory.Packages.props` found none) need their package versions added centrally and licence-checked; GreptimeDB has no throwaway test service in `scripts/test-services.sh`, so any real-server test there either needs that script, `ci.yml` and `bootstrap.sh` extended together, or must be Live-gated.
* A Code/Cowork split, Artifacts and chat belong in L2 libraries plus `OmpOS.Presentation`; Browser Use / Computer Use process or CDP spawning must be in an `OmpOS.Harness.*` assembly (NoProcess ban). Dispatch (remote control of desktops from mobile/web) must keep `OmpOS.Web` free of process-spawning references and must not be referenced from `OmpOS.Api` by another product project.
* Layer fit: a new library that needs another L2 library requires a `SameLayerAllowed` tuple with justification; otherwise place the shared abstraction in L1.
