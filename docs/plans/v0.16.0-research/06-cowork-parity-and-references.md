## 4. Design notes that feed the Autonogrammer mapping

**Dispatch (C18) published mechanics (use as the target design)**
- Anthropic's Dispatch: phone app and desktop app pair, one persistent thread, work runs on the desktop, desktop must be awake (S8). Remote Control, the same family, is the best-documented transport: the desktop process opens only outbound HTTPS, registers with the API and polls; the server relays messages over a streaming connection; credentials are multiple, short-lived and single-purpose; each device enrols its own credential only shortly after a full sign-in; a Trusted devices list revokes instantly; unused credentials expire (S23, lines on connection and trusted devices).
- Mapping `[PROPOSAL]`: Avalonia desktop opens an outbound connection to the ASP.NET Core API on Railway (no inbound port on the user's machine); Blazor WASM web head and a mobile shell are the "phone"; Supabase passwordless sign-in is the full sign-in that gates device enrolment; a persistent thread plus per-session approvals; push notification for "done" and "needs approval". Offline desktop means queued task, not cloud execution (same as Anthropic's Dispatch).
- Safety text to carry over: Dispatch chains a mobile agent to a desktop agent so a hijacked instruction can touch files, connectors, browser and apps (S8 safety section); Dispatch-spawned computer-use approvals expire after 30 minutes (S22).

**Safety layering Anthropic ships (S2, S10, S17, S22)**: read tools versus write tools; deletion always asks; per-app and per-site grants; tiers by app category; blocklists; classifiers on untrusted content and on each action; Auto falls back to Manual after repeated blocks; Skip mode has no checks; network egress allow-list excluded for web fetch, web search and MCP. These are cheap to copy as policy and expensive to copy as classifier.

**What is hosted-inference dependent (cannot be copied)**: Auto-mode classifier models, injection classifiers, Claude in Chrome, Duet, Claude Design, Slides, Motion, Compliance and Analytics APIs, directory review.

## 5. Source discrepancies to remember

1. Computer use macOS version: Cowork page says background mode on macOS 15 or later (S10); the Code page says computer use requires macOS 14 or later (S22). Both can be true (feature vs background mode).
2. Dispatch: help center says closed to new users (S8, S12) while the Code doc tells readers to set it up (S22). Treat Dispatch as a frozen beta.
3. Memory: S1 says cloud Cowork shares chat memory; S15 says local Cowork sessions do not use memory.
4. The live-artifacts article is now a deprecation notice (S6), not a feature guide; older blog posts describing live artifacts are stale.
5. "Artifacts" vs "Claude Docs/Slides/Design": the templates are beta on Enterprise and default-off until an owner enables them; on Enterprise they turn on by default 2026-10-15 (S18).

## 7. Cross-cutting risks

1. **Hosted-inference dependence.** Auto approval, injection screening and Claude in Chrome are model features. Without Anthropic, Autonogrammer must either ship a smaller policy engine or leave Auto out (D3). Anthropic itself says classifiers are not perfect and Skip mode has no checks (S1, S2).
2. **Computer use has no sandbox.** Anthropic states it plainly (S10); Anthropic's own demo says run it in a VM (S28). Shipping it enabled by default would be a regression against the product's safety posture; keep it off by default with per-app grants.
3. **Dispatch is a remote-control chain.** Phone to desktop to files, browser and apps (S8). The attack surface is the account (Supabase passwordless link), the device enrolment, and the API relay. Require recent sign-in at enrolment, per-device revocation, expiring approvals, and audit every remote action to the ledger `[PROPOSAL]`.
4. **Moving target.** Cowork changed its execution model on 2026-10-06 and its UI model on 2026-09-16; a parity table of UI labels rots fast. Pin parity to capabilities, not names.
5. **Licence traps.** Skyvern (AGPL), `cua-som` (AGPL-3.0-or-later), Cua Spaces and Driver Bench (FSL-1.1-MIT, converts to MIT after two years), OpenWork `/ee`. Permissive candidates still need attribution and NOTICE handling.
6. **Linux/KVM and Windows VM prerequisites** limit a "VM-isolated local agent" to machines with virtualization enabled (S3); sandbox-runtime-style isolation has no such requirement but is weaker.
