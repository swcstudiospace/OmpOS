## Context

- The embedded `Avalonia.Controls.WebView` 12.1.1 (ADR-0009) exposes `InvokeScript` and web messages and nothing else: a string search of its net10.0 assembly for `CaptureScreenshot` and `Screenshot` found 0 hits and no method captures pixels; there is no CDP handle and no trusted input (`docs/plans/v0.16.0-research/07-browser-computer-use-feasibility.md:43-44`). It cannot be the agent surface. It also cannot be hosted by the Blazor web head (OQ-51, R-3) and was measured only on WebKitGTK under Xvfb (`docs/decisions/ADR-0009-browser-pane.md:3,92-129`).
- A vision loop needs screenshots, trusted input events, the accessibility tree and a profile the host controls. Chromium over the DevTools protocol gives all four on Windows, macOS and Linux. CefGlue was rejected in report 07 section 2.2 (Chromium 120, Avalonia 11 dependency, no arm64 redistributables); Playwright .NET is the named fallback (214 MB nupkg with a Node driver per OS, report 07 section 2.3).
- omp 18.12.6 ships its own `browser` eval prelude and **enables it by default** (`browser.enabled`, `default: true`, omp package `src/tools/browser/settings.ts:8-14`). It launches its own Puppeteer Chromium with no host approval, no URL policy and no audit. Left on, a Cowork session has two browsers, one of them ungoverned.
- Facts read in `hardkoded/puppeteer-sharp` master on 2026-10-28 that shape the launch design:
  - `LauncherBase.SetEnvVariables` copies the whole host process environment into the browser process and then applies `LaunchOptions.Env` on top, so `Env` can add or override a variable but cannot remove one; API keys in the host environment reach Chromium (`lib/PuppeteerSharp/LauncherBase.cs`, `SetEnvVariables`).
  - In pipe mode on Unix `ChromeLauncher.ConfigurePipeProcess` joins all arguments into one string and runs `/bin/sh -c "exec 3<&.. 4>&..; exec \"chrome\" <args>"`, so an argument containing a shell metacharacter changes meaning. The one argument this design cannot do without, `--proxy-bypass-list=<-loopback>` (documented in `net/docs/proxy.md` of the Chromium tree, lines 538 to 543), contains `<` and `>`.
  - `PipeTransport` is public with a public constructor `(Stream pipeWrite, Stream pipeRead)` and `ConnectOptions.TransportFactory` accepts any `IConnectionTransport` (`Launcher.cs:463-465`), so PuppeteerSharp can be used as a CDP client over a pipe the host created itself.
  - `LaunchOptions.Allowlist` "requires Chrome 149+", is CDP-only, cannot be combined with `BlockList`, and matches URLPatterns (hostnames, not IP ranges) (`LaunchOptions.cs`).
- Chrome for Testing publishes download URLs per platform and no checksums (`https://googlechromelabs.github.io/chrome-for-testing/last-known-good-versions-with-downloads.json`, read 2026-10-28: stable 156.0.8078.73). PuppeteerSharp's `BrowserFetcher` has `DownloadAsync` and a `BaseUrl`; the source read contains no checksum check, so it is not an acquisition step that satisfies "reviewed, with a checksum".
- The tool route to omp is ADR-0032's: `CoworkToolHost` served by `McpGatewayServer` through ACP `session/new.mcpServers`. A Cowork tool name contains no `__` and omp shows it as `mcp__cowork_<tool>`; an image result becomes an MCP `ImageContentBlock`; the route is feasible by source and unverified against a live omp turn (ADR-0010, OD-07). `McpToolInvoker.InvokeAsync` (`src/Autonogrammer.Harness.Mcp/McpToolInvoker.cs:33-50`) remains the path for registry tools and is not used by this provider.
- The transcript gap (tool-result images dropped, `src/Autonogrammer.Contracts/Ui/ToolUpdateContent.cs:5-24`) is closed by ADR-0032 D4. Vision capability per model is known to omp (`OmpModelInfo.InputKinds`, `AcceptsImages`, `src/Autonogrammer.Harness.OmpConfig/OmpModelInfo.cs:34`) and reaches the tool host as `CoworkSessionContext.ModelReadsImages`; the catalogue's models carry no image flag and `OmpCatalogueBlock` writes `AcceptsImages: false` for them (`src/Autonogrammer.Harness.OmpConfig/OmpCatalogueBlock.cs:54`).
- This host (Linux x64, uid 0): `/usr/bin/google-chrome` 153.0.8010.36 is present; `chromium`, `chromium-browser` and `chrome` are not on PATH; `~/.cache/puppeteer` holds Chrome 152.0.7977.75 and a headless shell, `~/.cache/ms-playwright` holds chromium-1248; `Xvfb` and `xvfb-run` exist. `scripts/web-smoke/run-smoke.sh:78-97` already resolves a browser as `CHROME_BIN`, then `chromium`, `chromium-browser`, `google-chrome`, `chrome`, then the Playwright cache, and starts it as `--headless --no-sandbox --disable-dev-shm-usage --remote-debugging-port=0` with an empty profile (`:150-155`). The script's `$CHROME` is a local variable, not an input. Nothing was installed.

## Decision

### D1. Two browsers, two products

The **agent browser** is a host-launched Chromium that the agent drives and the user watches. The **preview pane** of Code mode (ADR-0009, `Avalonia.Controls.WebView`) stays the user's own surface for ADE-15 and is unchanged. They never share a profile, a cookie jar or a process. Cowork shows the agent browser's pane only. Code mode keeps omp's own `browser` prelude exactly as today (no regression, no new governance; whether to govern it is OQ-371).

### D2. Engine and client

- Chromium (system, managed or explicitly configured; D3) driven over the DevTools protocol on a **pipe**, never a listening port: any local process could drive a debugging port.
- Client: **PuppeteerSharp 25.15.0** (MIT, verified on NuGet 2026-10-28), used as a CDP client only. The host owns the process: `ChromiumProcessLauncher` (in `Autonogrammer.Harness.BrowserUse`, which the NoProcess ban permits by name, `Directory.Build.props:52`) starts Chromium itself, builds the environment from an allow-list (a variable not on it is not passed), passes arguments as an argument list, never a shell string, and connects with `Puppeteer.ConnectAsync(new ConnectOptions { BrowserWSEndpoint = <placeholder>, TransportFactory = ... })` returning a `PipeTransport` over the streams it created. Unix: `/bin/sh -c 'exec 3<&0 4>&1 </dev/null >/dev/null; exec "$0" "$@"' <chrome> <args...>` with the child's stdin and stdout as the two pipes. Windows: `--remote-debugging-io-pipes=<read>,<write>` with inheritable anonymous pipe handles, as PuppeteerSharp does. This avoids the three launcher defects above. Version is read with `Browser.getVersion` over the pipe, so no version probe spawns a process.
- Raw CDP through `ICDPSession` for what PuppeteerSharp does not wrap: `Page.startScreencast`, `Fetch.enable`, `Accessibility.getFullAXTree`, `DOMSnapshot.captureSnapshot`, `Input.dispatch*`, `Browser.setDownloadBehavior`, `Browser.setPermission`, `Page.setInterceptFileChooserDialog`. Parameter names were checked against the protocol JSON of `ChromeDevTools/devtools-protocol` master on 2026-10-28: `startScreencast` takes `format`, `quality`, `maxWidth`, `maxHeight`, `everyNthFrame`, `maxFramesInFlight`, `sendLastFrame`; `screencastFrame` carries `data`, `metadata{offsetTop, pageScaleFactor, deviceWidth, deviceHeight, scrollOffsetX, scrollOffsetY, timestamp}`, `sessionId` and must be acknowledged with `screencastFrameAck`; `Browser.setDownloadBehavior` accepts `deny`.
- Fallback if the pipe-connect spike (verification step 1) fails: the same architecture over Microsoft.Playwright 1.64.1 `ConnectOverCDPAsync`; recorded in OQ-361, not adopted.

### D3. Locating and acquiring Chromium: never silent

Order: (1) `Cowork:BrowserUse:ExecutablePath` when set; (2) a managed install under `<state>/browser/chromium/<version>/` created by the acquisition step; (3) a system Chrome or Chromium at the well-known per-OS paths (Chrome, Chromium; the snap package `/snap/bin/chromium` is skipped because snap confinement is believed to block profile and pipe access [INFERENCE, unverified]); (4) state `BrowserNotInstalled`, which the pane and the Settings page show with the one action "Install a browser". The profile is always the host's own `--user-data-dir`, so using the user's installed Chrome binary shares nothing with the user's profile.
The acquisition step (`ChromiumAcquirer`) runs only when the user presses that action and confirms a dialog that names the version, the source URL host, the size and the licence line. It downloads the platform archive named by `chromium-manifest.json` (an embedded resource of `{version, platform, url, sha256, sizeBytes}` rows produced by a maintainer script `scripts/browser/pin-chromium.sh` and reviewed in a pull request) over TLS from `storage.googleapis.com` only, refuses redirects to other hosts, verifies size and SHA-256 before extraction, extracts without path traversal, sets the execute bit, and publishes by atomic rename. A manifest with no row for the platform means state `ManagedBrowserNotPinned` and the action is hidden. **No manifest rows are committed by this record**: the hashes must be produced from real downloads, and the owner must first read the Chrome for Testing and Chrome redistribution terms (not read in this research; OQ-362). Chromium is never bundled in an installer. Minimum major version **149** (the `Allowlist` floor); an older browser is refused with state `BrowserTooOld` and closed. The CfT stable build at the time of writing is 156.0.8078.73; the pin is chosen when the manifest is produced.

### D4. Process and profile isolation

- Profile: a fresh directory per Cowork session under `Directory.CreateTempSubdirectory` (a path of `[A-Za-z0-9._/\\:-]` only, else `ProfilePathUnsafe`), mode 0700, wiped at session end. No cookies, logins or extensions from the user. Sign-in on a site happens by the user's take-over inside the pane. Opt-in `PersistentProfile` keeps one named profile at `<state>/browser/profiles/<id>`; Chromium's `--password-store=basic --use-mock-keychain` means its cookies are protected only by the file mode, so the Settings text says so. Importing cookies from the user's browsers is not built (OQ-364).
- Environment: allow-list `PATH`, `HOME`/`USERPROFILE`, `TMPDIR`/`TEMP`, `LANG`, `LC_*`, `DISPLAY`, `WAYLAND_DISPLAY`, `XDG_RUNTIME_DIR`, `SystemRoot`, `LOCALAPPDATA`, `APPDATA`; every `OMP_*`, `*_KEY`, `*_TOKEN`, `*_SECRET`, `AUTONOGRAMMER_*` and every other variable is dropped.
- Sandbox: Chromium's sandbox stays on. If it cannot start, state `SandboxUnavailable` (no automatic `--no-sandbox`). `Cowork:BrowserUse:SandboxMode=Disabled` exists for tests on this root host only and the validator refuses it unless `AUTONOGRAMMER_BROWSER_ALLOW_NO_SANDBOX=1`.
- Flags (assembled by `ChromiumLaunchPlan`, one list, unit-tested): `--headless=new`, `--remote-debugging-pipe`, `--user-data-dir`, `--no-first-run`, `--no-default-browser-check`, `--disable-extensions`, `--disable-sync`, `--disable-background-networking`, `--disable-component-update`, `--mute-audio`, `--hide-scrollbars`, `--password-store=basic`, `--use-mock-keychain`, `--proxy-server=http://127.0.0.1:<port>`, `--proxy-bypass-list=<-loopback>`, `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`, `--window-size=W,H`. Each flag is launch-tested on the host Chrome 153; `--force-webrtc-ip-handling-policy` and `--disable-component-update` are [INFERENCE] until then.
- Lifetime: one browser process per Cowork session, at most `MaxConcurrentBrowsers` (default 2) per head; tab count, memory (`Process.WorkingSet64` of the browser, default cap 1536 MiB), idle (10 minutes) and wall time (2 hours) are bounded; disposal closes the browser through CDP, then kills the process tree.

### D5. Network policy: an egress guard in front of everything

`EgressGuardProxy` is a loopback HTTP proxy (HTTP forward and `CONNECT`) owned by the session, started before Chromium and used by every request, subresource included. It needs no dependency (`System.Net.Sockets`). Chromium reaches it with `--proxy-server` and `<-loopback>` removes Chromium's implicit bypass of loopback, so loopback targets also pass through it.

- The proxy resolves names itself, classifies **every** returned address, drops denied ones, and connects to the validated address (no second lookup: DNS rebinding has no window). Denied: loopback, RFC1918, link-local (including the cloud metadata address 169.254.169.254), CGNAT 100.64/10, unspecified, multicast, reserved, IPv6 unique-local and link-local; IPv4-mapped and NAT64 addresses are unwrapped and re-checked. Ports and address literals that `IPAddress.TryParse` accepts in more than one reading are refused.
- Local dev servers are reachable only through an explicit `LocalOriginGrant(host, port)` for `localhost`, `127.0.0.1` or `[::1]`, created by a user decision (a card with local-network wording, session scope, no "always"). This is what the frontend loop (D8) needs and what the test site uses.
- Schemes: only `http` and `https` (and `about:blank`). `file:`, `chrome:`, `chrome-extension:`, `devtools:`, `view-source:`, `javascript:` typed as a destination, `data:` and `blob:` as top-level navigation are refused by `NavigationGate` before the request; PuppeteerSharp `BlockList` repeats the scheme patterns as a second layer.
- Modes: `PromptOnNewOrigin` (default) and `Strict` (only `AllowedHosts` are reachable; the proxy refuses the rest; needs Chrome 149+ for the `Allowlist` second layer). `DeniedHosts` applies in both. Defaults ship empty beyond the built-in denials; no financial or crypto category list is shipped because no classifier exists (report 06 section 6 notes Anthropic blocks high-risk categories with classifiers, which cannot be reused).
- `NavigationGate` uses raw `Fetch.enable` with `patterns:[{resourceType:"Document"}]` so every document request, including each redirect hop and iframes, is paused: a new top-level origin raises the approval card (D9); a redirect to a denied target aborts the load before a request leaves. The card shows the host-observed full URL and, when the query is longer than 64 characters, a "this address carries N characters of data" line, which is the exfiltration signal.
- Residual risk accepted in the default `Cowork:BrowserUse:PolicyMode` (`PromptOnNewOrigin`): an already-approved page can load subresources from origins not yet approved (CDNs). `Strict` closes it.

### D6. The pane and the viewer stream

- Source: `Page.startScreencast` (`format: jpeg`, `maxFramesInFlight: 1`, acknowledged only after the viewer consumed the frame, `sendLastFrame: true` for a late viewer). Frames are produced only while a viewer is attached; with none, `stopScreencast`.
- Seam and heads: `IBrowserPaneFeed` (state plus frames) lives in `Autonogrammer.Contracts` (L0, additive, ADR-0008) beside `BrowserFrame`, `BrowserPaneState` and `BrowserControlState`, so the framework-free `BrowserPaneViewModel` in `Autonogrammer.Presentation` and both renderers share one shape without referencing the Harness layer. `LocalBrowserPaneFeed` (the Native desktop head, in-process, bounded: local pane up to 10 frames per second, JPEG quality 70, long edge 1280) is built. `RelayBrowserPaneFeed` for the Web and Android heads is **not built in v0.16.0**: ADR-0036 D13 keeps screenshots and browser streams off the relay until OQ-73 is answered. Until then those heads show `RemoteViewUnavailable` ("This browser runs on your desktop. Open Autonogrammer there to watch it.") plus the bounded progress text ADR-0036 allows (host name and last action, no query). The pane view model and both views (Avalonia `Image` on Bitmaps; Razor `<img>` fed by `data:` URIs, which the CSP already allows, `vercel.ts:21`) are tested with scripted frames on both renderers, so adding the relay is an adapter. Reserved for that adapter and unmeasured: 2 frames per second, quality 55, long edge 960, one frame in flight per viewer, 2 Mbit/s, drop and never queue (OQ-367); a `blob:` path would need a CSP change (OQ-368).
- Placement: `IDockPanel` is a content contract (ADR-0032 D3). The pane registers as one panel with `CoworkDockHost` (brief 69 unit 3), which hosts the registered list (Artifacts, Browser) with a tab strip and one visible panel at a time; each provider registers its own panel (OQ-374).
- Take-over: pane pointer and key events map to CSS pixels with the frame metadata and go out as `Input.dispatchMouseEvent`, `dispatchKeyEvent` and `insertText`. While the user holds control the agent's calls wait (`UserHasControl`). The keyboard is captured only in take-over and **F6 leaves it** (F6 is the existing region-cycle key, `src/Autonogrammer.Native.Views/MainView.axaml.cs:826`) so there is no keyboard trap. Take-over exists only on the desktop that runs the browser; no remote viewer sends input (OQ-369).
- The pane shows an **Agent view** strip: the last image the model received, with size, format, byte count and time, built from the bytes the tool returned (D8). The user sees what the model sees.

### D7. Tool family

One provider, `BrowserToolProvider : ICoworkToolProvider` (ADR-0032 D5), `ProviderId` `browser`; tool names obey the descriptor rule (start with `browser_`, 3 to 40 characters, no `__`), so the model sees `mcp__cowork_browser_navigate` and so on. `GetStateAsync` reports `Available`, `NeedsSetup` (`BrowserDisabled`, `BrowserNotInstalled`, `ManagedBrowserNotPinned`) or `Unavailable` (`BrowserTooOld`, `SandboxUnavailable`, `ProfilePathUnsafe`, `LaunchFailed`) with a fixed reason; `PreviewAsync` reads host state only (URL without query, element role and name from the accessibility tree) and never touches the page; `EndSessionAsync` closes the browser, wipes the profile and forgets session approvals. Calls run one at a time per session (host rule), so the provider holds no per-call lock.

| Tool | Effect, approval | Arguments | Result |
| --- | --- | --- | --- |
| `browser_navigate` | ReadOnly, ByPolicy, `Preview.Grant` = `("browser.origin", target origin)` | `url` | final URL, title, HTTP status, a `read` summary |
| `browser_click` | Actuating, ByPolicy | `ref` or `x`,`y` (screenshot pixels), `button`, `clickCount` | what changed (new URL, dialog, popup refused) |
| `browser_type` | Actuating, ByPolicy | `ref` optional, `text`, `submit` (Enter) | field accepted or approval outcome; typed text is never echoed or logged |
| `browser_scroll` | ReadOnly, ByPolicy | `direction`, `amount`, `ref` optional | new scroll position |
| `browser_read` | ReadOnly, ByPolicy | `view`: `tree` (default), `text`, `console`; `ref` for a subtree; `maxChars` | refs `e<n>` with role, name, state; or text; or the last 50 console and failed-request lines |
| `browser_screenshot` | ReadOnly, ByPolicy, `Results` Text and Image | `zoom{x,y,width,height}` optional, `viewport`: `desktop`, `tablet`, `mobile` | one image block plus a caption with scale factor and coordinate origin |
| `browser_wait` | ReadOnly, ByPolicy | `seconds` (at most 10) or `text` | condition met or timeout |
| `browser_back` | ReadOnly, ByPolicy | none | URL after navigation |
| `browser_close` | ReadOnly, ByPolicy | none | closed |

- Two stages of approval. **Stage 1** is ADR-0032's gate over the descriptors above: in Manual a ReadOnly call is allowed only when its `Preview.Grant` is stored (an `AllowedAlways` answer) and asked otherwise, an Actuating call is asked, Skip allows; for read calls `Preview.Grant` is `("browser.origin", current origin)`. **Stage 2** is the provider's own, through `ICoworkApprovalBroker`, for facts known only during the call: a top-level origin other than the requested one (redirect, link, popup), a form submit, a sensitive field, a download release (D9). Stage 2 is not skipped by Skip; it is the browser's security boundary. A consequence to accept: in Manual mode every `browser_click` and `browser_type` asks (OQ-376).

- Grounding is hybrid: `read` assigns element refs from the accessibility tree (`Accessibility.getFullAXTree` nodes carry `backendDOMNodeId`); refs belong to a snapshot generation and a stale ref fails with `StaleRef` and the instruction to call `read` again; the coordinate form is the fallback and is scaled back from the returned frame by the host.
- Page text for `text` and `tree` comes through a visibility filter (`DOMSnapshot.captureSnapshot` with `display`, `visibility`, `opacity`, `font-size`, bounds): nodes with no area, `display:none`, `visibility:hidden`, opacity under 0.1, font under 4 px, or far outside the page are dropped; invisible Unicode (zero width, bidi controls, the tag block U+E0000 to U+E007F) is stripped; length is capped at 20,000 characters. This reduces and does not remove hidden-text injection; screenshots show visible text regardless (D9).
- Tool calls carry a `CancellationToken` the Stop control cancels; limits: 60 actions per minute, 500 calls per session (warning at 400), per-tool timeout 60 s, page load timeout 30 s.

### D8. Vision, and the frontend-iteration loop

- **Model screenshots are separate from the viewer stream.** `browser_screenshot` calls `Page.captureScreenshot` on demand: a fixed viewport of 1280x800 CSS pixels at device scale 1, so the default image is 1280 pixels on the long edge and needs no scaling for models whose coordinate-safe size is 1280 (report 07 section 4.1). A ladder keeps each image under `MaxScreenshotBytes` (default 3 MiB, which is ADR-0032's per-image cap; the validator refuses a larger value): PNG; then JPEG quality 85; then JPEG 70; then a smaller `clip.scale`; all through CDP parameters, so no imaging dependency is added. `ScreenshotLongEdge` is 640 to 2576. Provider limits are model policy values, not constants (report 07 section 4.1).
- Bounds: at most one image per call (the host allows two), a minimum interval of 500 ms between screenshots, `MaxScreenshotsPerSession` 40 (images in `tool_result` count towards Anthropic's 100-image and 20-image-dimension thresholds, report 07 section 4.1); past the cap the tool returns a failure with `ImageBudgetExhausted` and the pane offers "Allow 20 more". Zoom returns a region at full resolution, up to the byte cap.
- Path and transcript: the provider returns a `CoworkImageBlock`; ADR-0032 maps it to an MCP `ImageContentBlock`, omp's MCP bridge keeps image blocks, and the model sees it; the transcript renders it through `ToolUpdateContent.Images` (ADR-0032 D4). Whether a stored transcript keeps the full image or a thumbnail of at most 320 pixels, and that the audit holds no image bytes, is requested of ADR-0032 (OQ-370).
- Model selection adds no billing and no new catalogue: the vision authority is omp's own model listing (`OmpModelInfo.AcceptsImages`) through `CoworkSessionContext.ModelReadsImages`, the same signal `ImageInputBinding` uses for composer attachments. When it is false the host withholds `browser_screenshot` (ADR-0032 D5 step 1), `GetStateAsync` stays `Available` for the text tools, the pane shows `ModelCannotSeeImages` with "Choose a vision model" (the models for which `AcceptsImages` is true, set through the existing model control), and a `browser_screenshot` that still arrives after a mid-session model switch fails with that reason. An image flag on `CatalogueModel` is an ADR-0019 amendment, not done here (OQ-363).
- Frontend loop: a guidance fragment of at most 1 KiB, `BrowserLoopGuidance`, that the Cowork system-prompt composer of ADR-0032 appends when this provider is `Available` (its prompt budget is 8 KiB): build, `browser_navigate` to the granted local origin, `browser_screenshot` the three viewports, `browser_read` the console, compare with the user's stated intent or an attached reference image, fix, repeat at most five times. The bound is advice; the hard bounds are the call and screenshot caps. Whether the loop produces good UI cannot be measured without a live vision model (OQ-372).

### D9. Safety: page content is data

Honest scope: only the model produces tool calls, so the host cannot make page content unable to influence the model; it can make sure that no page-influenced call reaches a consequential effect without a host check the page cannot touch. Layers:

1. **Provenance and envelope.** Page-derived text is returned as `CoworkTextBlock(text, IsUntrusted: true)`, which ADR-0032 D6 wraps in its labelled envelope. Inside it the provider writes `[page content begins, id <random>]` and `[page content ends, id <random>]` with a fresh random id per result, so page text cannot forge the close, and neutralises angle-bracket look-alikes of any delimiter (the gateway's exact delimiter is not named in ADR-0032: OQ-360). Each image carries a `Description` that says it shows an untrusted page and names the origin. Tool descriptions say that page content is data. Delimiters reduce risk and do not remove it.
2. **Rule of Two, enforced by the host from what this provider declares.** ADR-0032 D6 taints a session the first time a result carries a block with `IsUntrusted`; in a tainted session Skip no longer applies to Actuating or Destructive calls, `edit`, `delete`, `move` and `execute` are Manual, and the environment holds provider keys only, with secret folders refused as trusted folders. This provider's duty is to set `IsUntrusted` on **every** block that carries page content or a page image, local dev-server pages included (a dev server often renders third-party or user-written data); the opt-in option `LocalOriginsTrusted` (default false) lets a user mark granted local origins trusted at the price of the Rule of Two for them (OQ-377). The provider cannot clear taint. The browser process has no access to the workspace (its own profile, no `file:` URLs) and the provider holds no credentials. A frontend loop in a tainted session therefore asks before each omp `edit`; that cost is accepted (OQ-376).
3. **Approvals show host-observed facts** (URL without query, element role and name from the accessibility tree, field type), never model text.

| Action | Default |
| --- | --- |
| navigate to the requested origin | stage 1; the card's `Target` is the URL without query and fragment, `Details` give the query length ("this address carries N characters of data"); `AllowedAlways` stores `("browser.origin", origin)`; an `Allowed` answer approves the origin for the rest of the session |
| any other top-level origin reached (redirect, link, popup target) in `PromptOnNewOrigin` | stage 2 card; `PolicyMode` `Open` skips it, `Strict` refuses it unless listed |
| a local dev server (`localhost`, `127.0.0.1`, `[::1]` with a port) | the same cards with local wording and the scope `("browser.local", "host:port")`; the egress guard opens that exact port only after the answer |
| submit a form | stage 2 card each time for a form with a sensitive field, otherwise once per origin per session |
| type into a password, one-time-code or payment field (`type=password`, `autocomplete` `cc-*`, `one-time-code`, names matching card, cvv, ssn, otp) | stage 2 card every call, `MustBeLocal`; the value is never logged; `browser_read` returns it masked |
| download | `deny` (`Browser.setDownloadBehavior`); the user can turn on `Quarantine` for the session: files go to a 0700 directory, 50 MiB cap, executable extensions refused, released into the workspace only by a `MustBeLocal` card |
| file chooser | cancelled and reported; no upload tool exists in v0.16.0 |
| JavaScript dialogs | `alert` and `confirm` dismissed and reported; `beforeunload` accepted so navigation works |
| popups and new windows | closed and reported |
| permissions (camera, microphone, geolocation, notifications, clipboard) | denied through `Browser.setPermission` |
| autofill and password manager | off; the agent never receives a stored secret |

4. **Dispatch-origin turns** (`CoworkTurnOrigin.Dispatch`; ADR-0036 D6 row `browser_use`). The option `Cowork:BrowserUse:AllowDispatchSessions` is false by default, and the desktop reports the capability `browser_use` to the hub only when `Enabled` and `AllowDispatchSessions` hold. In such a turn `Open` is treated as `PromptOnNewOrigin`; origin cards may be decided by the controller (`MustBeLocal` false); sensitive typing, sensitive submits and download release are `MustBeLocal` and, with no local user, are denied; an `AllowedAlways` answer is treated as `Allowed` and never stored, so ADR-0036 D8 has no grant to withdraw (OQ-375).
5. **Indicator and stop.** While any actuating call is possible the pane and the Cowork header show "The agent is controlling the browser" with a **Stop** button and a keyboard chord (proposal `Ctrl+Shift+.`, to be set in the shortcut catalogue). The indicator is application chrome outside the frame, so a page cannot imitate or hide it. Stop cancels in-flight calls through the call token, revokes control (`ControlRevoked` until the user resumes) and leaves the browser open for inspection; "Close browser" ends the process. The chat's own Stop cancels the turn and reaches the provider through the same token.
6. **Audit and logs.** The host records every call through `ICoworkToolAudit` (no arguments, no result bytes); the provider's `Preview.Target` is the URL without query and fragment, so the audit holds no query. Guard denials, stage 2 decisions and taint changes go to `ILogger` through `LoggerMessage.Define` with event ids and the origin only; never page text, typed text or a full URL.
7. **omp's own browser stays off.** ADR-0032 D4 writes `browser.enabled: false` into the Cowork overlay. This record requires it and verifies it only in the live run (OQ-365; ADR-0032 OQ-322 says to hide omp's browser tool if the check fails).

### D10. Test plan on this host

- Headless by default; the product always runs `--headless=new` because the pane is our own render. Headless needs no display; `google-chrome` 153 is used through `CHROME_BIN` or the locator. A **headful smoke** runs the same screencast test under a private `xvfb-run` server (never the main display). No browser, Xvfb or package is installed by the tests.
- Live tests carry `[Trait("Category", "Live")]` and a first-statement gate `Assert.Skip("Set AUTONOGRAMMER_LIVE_BROWSER=1 ...")`, the repo's live-test convention; the unit tests use a scripted fake `IChromiumLauncher` and a fake host resolver. Provider tests run through ADR-0032's real `CoworkToolHost` with a fake broker, grant store and audit, so both approval stages, the taint flag and the result caps are observed rather than assumed. The hostile corpus runs live and is also driven against the fake for the invariants that do not need Chromium.
- The test site is a small `HttpListener` server in the test project (precedent: the MCP gateway uses `HttpListener`) on two loopback ports: one granted, one **not granted** with a request log, so a redirect from the first to the second must produce zero hits. No network.
- Hostile corpus (19 pages): visible instruction; hidden CSS text; attribute text (`alt`, `title`, `aria-label`); comments, meta and noscript; forged close tag and forged system message; invisible and bidi Unicode; text only in an image; redirects to loopback, RFC1918 and the metadata address in decimal, hex, octal, IPv6 and IPv4-mapped forms; simulated DNS rebinding (resolver changes its answer); popup storms; automatic downloads; file chooser; password and card forms; dialog loops; oversized DOM and redirect loops; `javascript:`, `data:`, `blob:`, `file:`, `chrome:` links; permission and clipboard requests; a cross-origin iframe with `postMessage`; a page that draws a fake "agent is controlling" banner. The assertions are host invariants (no call without its policy check, no hit on the ungranted port, envelope integrity, approvals requested, caps held, indicator outside the frame). Model compliance cannot be measured without a live model and is not claimed.

## Open risks

- The host-owned pipe launch is designed from source reading and has not run; the fallback is Playwright .NET over CDP, with a larger footprint.
- The egress guard is new security-critical code; a classification gap (an address form not normalised) is an SSRF. The corpus covers the known forms, not unknown ones. Proxy authentication through `Page.AuthenticateAsync` is [INFERENCE]; without it any local process could use the proxy as a relay for public addresses only.
- Prompt injection through screenshots and visible text cannot be filtered; the design bounds consequences (approvals, taint, caps) and does not prevent the model from being influenced.
- Default `PromptOnNewOrigin` lets approved pages load subresources from unapproved origins (an exfiltration channel through image URLs); `Strict` closes it at a usability cost.
- A downloaded Chrome for Testing carries redistribution and signature questions (macOS Gatekeeper, Windows SmartScreen) that are unmeasured.
- No relay feed exists in v0.16.0, so the Web and Android panes never show frames; the reserved remote budgets are guesses and unmeasured.
- Headless Chromium on a Linux machine without fonts renders blank text in screenshots; the host check `FontsMissing` is proposed and unverified.
- Sites detect headless Chromium and may block it; omp's own browser tool ships stealth scripts for this reason (report 07 section 2.4). Not countered here: evasion is out of scope.
- In Manual mode every `browser_click` and `browser_type` asks under ADR-0032's gate, and in a tainted session each omp `edit` asks too, so browsing and the frontend loop feel chatty until the gate offers a session-scoped grant (OQ-376).
