## Context

Anthropic's Cowork opens "anything made to put in front of someone" (documents, designs, dashboards, small tools) in a panel beside the chat, with export to Word, PDF, Markdown, HTML and zip, and sharing by link (report 06 C19). Its live artifacts are frozen since 2026-08-19 and Anthropic's own article is now a deprecation notice (C20, section 1 row 5). The program maps artifacts to ADAPT: the shared Generative UI renderer already draws surfaces, and Docs and Markdown edit-in-place plus file export are BUILD; hosted templates, MP4 export and external sharing are OMIT.

Four repo facts shape the design.

1. Generated content is untrusted. It is written by a model that reads web pages, files and tool output, so a prompt injection can make it write hostile HTML. The renderer therefore decides the security of the feature, not the model.
2. The repo already has a no-script path for markdown: `MarkdownRenderer` (`src/Autonogrammer.Presentation/Services/MarkdownRenderer.cs:22-25`) and `MarkdownAstBuilder` (`src/Autonogrammer.Native.Views/Views/Blocks/MarkdownAstBuilder.cs:30-33`) both use a Markdig pipeline with `DisableHtml()`, links are scheme-allowlisted and images render only as inline raster `data:` URIs (`A2uiSurfaceCatalog.IsAllowedImageSource`, `src/Autonogrammer.GenUi/A2uiSurfaceCatalog.cs:161-170`, which refuses `data:image/svg+xml`). The hostile-markdown tests already exist (`tests/Autonogrammer.UI.Tests/MarkdownSanitizationTests.cs`, `MarkdownSinkTests.cs`).
3. `Avalonia.Controls.WebView` 12.1.1 (MIT) is pinned (`Directory.Packages.props:93-95`) and accepted for Linux on the WebKitGTK adapter only (ADR-0009: load, selector and bounding box measured under Xvfb; Windows, macOS, Wayland, interaction, navigation policy and cookies not measured). It offers script evaluation and messages but no CDP, no screenshots and no per-response header control (report 07 2.1). The assembly injects a page-to-host bridge (`invokeCSharpAction`, `window.chrome.webview`, `window.webkit.messageHandlers`, `window.external`; strings read from `Avalonia.Controls.WebView.dll` 12.1.1) and exposes an `EnablePostMessageBridge` option, private-mode and non-persistent data-store options (member names read from the same assembly metadata; their owning types are confirmed when the code compiles).
4. The hosted web head runs under `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; style-src 'self' 'unsafe-inline'; connect-src 'self' <one API origin>; img-src 'self' data:; object-src 'none'; base-uri 'self'; frame-ancestors 'none'` (`vercel.ts:16-25`). CSP Level 3 section 7.8 ("CSP Inheriting to avoid bypasses", W3C working draft 2026-10-27, read 2026-10-28) says documents loaded from local schemes (`srcdoc`, `blob:`, `data:`) inherit a copy of the embedding document's policies, so that a page "can't bypass its policy by embedding a srcdoc iframe". A `srcdoc` iframe in the web head therefore cannot run an inline script, whatever its `sandbox` attribute says.

There is no artifact route, no artifact store and no Cowork surface today (report 03 section 3, report 02 header). The contract version is 1.5.0 (`src/Autonogrammer.Contracts/ContractVersion.cs:9`); `UiBlockConverter` maps unknown kinds to `UnknownBlock` (`src/Autonogrammer.Contracts/Ui/UiBlock.cs:5-9`), so an additive block kind is safe for old readers (ADR-0008).

## Decision

### D1. The one rule

Artifact content never becomes markup or a control of the application itself unless it passed a renderer that cannot execute it. Everything that can execute (HTML, scripts, Mermaid) runs only in an isolated surface: a separate browsing context with a restrictive CSP, no network by default, no navigation, and no bridge to the host. Where the host cannot isolate, the artifact shows as source with a named reason; it is never rendered "anyway".

### D2. The model

An artifact is a titled, typed thing with an append-only chain of versions.

| Field | Rule |
| --- | --- |
| `ArtifactId` | `Guid.CreateVersion7()` text, generated by the host, never by the model. |
| `Kind` | One of `Markdown`, `Code`, `Html`, `Svg`, `Mermaid`, `Csv`, `Image`. Fixed at creation; an update cannot change it. |
| `Title` | 1 to 120 characters; control characters, Unicode bidirectional controls (U+202A to U+202E, U+2066 to U+2069) and lone surrogates are rejected, not stripped. Rendered as text only. |
| `Language` | `Code` only: 1 to 32 characters of `[A-Za-z0-9+#._-]`; unknown languages render as plain text. |
| `MediaType` | Derived from the kind (`text/markdown`, `text/plain`, `text/html`, `image/svg+xml`, `text/x-mermaid` (application-defined), `text/csv`); `Image` takes `image/png`, `image/jpeg`, `image/gif` or `image/webp` and the bytes must start with the matching magic number. |
| `SessionId` | Optional link to the creating Cowork session (`SessionSurface.Cowork`, ADR-0030/0032). Deleting a session does not delete its artifacts: the artifact is the deliverable. |
| `DerivedFrom` | Set by copy: source artifact, version and content hash. |

Kinds not built, each with its reason:

| Not built | Reason |
| --- | --- |
| Word, PowerPoint, Excel, PDF files (report 06 C21) | Produced as files in the storage folder by the agent, not as artifacts: no safe in-process renderer exists for them, and an Office or PDF parser fed model output is a larger attack surface than the whole panel. Shown as file chips by ADR-0032. |
| Jupyter notebooks, React or JSX apps, LaTeX | Need a build or kernel step, or a script origin (CDN) that D8 denies by default. A React app is written as a self-contained `Html` artifact. |
| Slides, Design, Dashboard and Motion templates, MP4 export | Hosted-inference products (report 06 C19, section 9 D6); omitted by decision. |
| Audio, video, 3D models | No requirement; a media decoder is an untrusted-input parser. |
| TSV and other delimited text | `Csv` only (comma, RFC 4180); the rest is `Code` with language `text`. |

### D3. Versions

- A version is `(ArtifactId, Number)` with `Number` starting at 1 and increasing by exactly 1. It stores the content bytes, `ContentSha256` (lowercase hex over the exact stored bytes), `Bytes`, `ParentNumber` and `ParentContentSha256` (both null for version 1), `Author` (`Agent` or `User`, set by the host from the caller, never taken from tool arguments), `SessionId`, `CreatedAt` (injected `TimeProvider`), `ChangeNote` (at most 280 characters) and the requested permissions (D8).
- Versions are write-once. There is no operation that changes or deletes one version. Deleting an artifact deletes all its versions and grants (hard delete, report 06 C29).
- `Update` takes a required `BaseVersion`. It succeeds only when `BaseVersion` is the latest number; otherwise it fails with `StaleBase` and the latest number. When the new bytes equal the latest version's bytes (same hash) no version is created and the existing one is returned. This makes retries idempotent without a separate key.
- Every read recomputes the hash and checks the parent link. A mismatch raises `ArtifactIntegrityException`; the content is not rendered and the panel shows the integrity state. The server recomputes the hash of every uploaded version and never trusts the client's value.
- Copy creates a new artifact whose version 1 holds the chosen version's bytes, with `DerivedFrom` set and the title suffixed `(copy)`. The chain is not shared.
- A user edit (text kinds only) saves a new version with `Author = User`. A save against a stale base is refused; the dialog offers reload or "save as a copy". No merge is attempted.
- The model sees one chain per artifact and cannot branch it.

### D4. The tool family `artifact`

A provider implements `ICoworkToolProvider` (ADR-0032, project `Autonogrammer.Cowork.Abstractions`, L1) with `ProviderId` `artifact`. Its four descriptors are named `artifact_create`, `artifact_update`, `artifact_read` and `artifact_list` (ADR-0032 requires the provider id plus an underscore, lower snake case); the gateway serves them under its single `cowork` entry and omp shows them as `mcp__cowork_artifact_create` and so on. Descriptor effects: `read` and `list` are `ReadOnly`; `create` and `update` are `Actuating` with approval `ByPolicy`, meaning they write only the application's own artifact store (see the rules below); nothing in the family is `Destructive`. `Results` is `Text`. Tool results carry `IsUntrusted = false` for the artifact metadata the host built and the content text of `read` is wrapped as an untrusted block, because the user or an earlier version of the agent may have written it. All arguments are validated before any work; errors are tool results with a stable `code`, never exceptions across the gateway. In the table below the first column is the tool name without the `artifact_` prefix.

| Tool | Arguments | Result |
| --- | --- | --- |
| `create` | `title`, `kind`, `language?`, exactly one of `content` (text, or base64 for `Image`) or `from_file` (an absolute path), `media_type?` (images), `change_note?`, `permissions?` (`network`: up to 5 origins with a `reason` each) | `artifact_id`, `version`, `content_sha256`, `bytes`, `warnings[]` |
| `update` | `artifact_id`, `base_version`, exactly one of `content`, `from_file` or `edits` (a list of `{old, new}` exact-match replacements applied to the base version, text kinds only, each `old` must match exactly once), `title?`, `change_note?`, `permissions?` | the same, or `stale_base` with `latest_version` |
| `read` | `artifact_id`, `version?` (default latest), `max_bytes?` | metadata plus the content for text kinds; for `Image` metadata only (the model gets no pixels in v0.16.0) |
| `list` | `session_id?` (default the calling session), `kind?`, `limit` (at most 50), `cursor?` | summaries: id, title, kind, latest version, updated at, author of the latest version |

Rules:

- The gateway request body is capped at 1 MiB (`McpGatewayServer.MaxBodyBytes`, `src/Autonogrammer.Harness.McpGateway/McpGatewayServer.cs:34`, read at `:171-181`), so `content` is bounded below that. Larger images arrive through `from_file`, which the provider resolves under the same folder grants as every other Cowork file read (ADR-0032); a path outside a granted folder, a symbolic link that leaves it, or a non-regular file is refused with `file_not_allowed`. The same path is also the user's "create artifact from file" action, so artifacts do not depend on the model route being live ([ADR-0010](ADR-0010-omp-mcp-gateway-feasibility.md) is still "feasible, unverified").
- `warnings` carries what the renderer will do to the content (for example "3 SVG elements will not be shown", "Html asks for network access to api.example.com; it is blocked until the user approves"). The model learns the constraint in the result of the call that caused it.
- Writes are limited to `Cowork:Artifacts:MaxWritesPerMinutePerSession` (default 20) with `rate_limited` and a retry-after; this bounds a prompt-injected loop.
- Creating or updating an artifact writes only to the application's own store. `artifact_create` and `artifact_update` are `Actuating` and `ByPolicy`, and each returns `Preview.Grant = ("artifact.write", "cowork")` (ADR-0032 D6: a stored grant may satisfy `ByPolicy` for any non-`Destructive` call whose preview names a grant). In Manual mode the first write asks once; "Allow always" persists the grant and later writes need no prompt. In a session the host has marked tainted (ADR-0032: untrusted content was read, for example a web page), `Actuating` calls lose the Skip exemption and the stored grant, and ask like any other; the artifact tools follow that rule without a special case, and the prompt shows the host-observed title, kind and size, never model text. Requested network origins never take effect without the user (D8).
- `read` returns content the user may have edited (`author` is in the result). Tool results are data to the model like any other.
- Nothing in the family can delete, share or publish an artifact.

### D5. Rendering decisions per kind

| Kind | Desktop (Avalonia) | Web head (Blazor WebAssembly) | Script runs |
| --- | --- | --- | --- |
| `Markdown` | `MarkdownAstBuilder` (Markdig 1.4.2, `DisableHtml()`, links shown with their URL, images only inline raster `data:`). In-process. | `MarkdownRenderer` output as `MarkupString`. In-process. | never |
| `Code` | AvaloniaEdit 12.0.0 read-only with TextMate highlighting (ADR-0007). | Escaped text in `<pre><code>` (Razor encoding). | never |
| `Csv` | `Avalonia.Controls.DataGrid` 12.1.2 over a capped preview (D6). | A `<table>` with caption and column headers over the same preview. | never |
| `Image` | Avalonia `Bitmap` from validated bytes. | `<img>` with a `data:` URI of the validated bytes. | never |
| `Svg` | Isolated surface showing the sanitised SVG as an `<img data:image/svg+xml;base64>` in a document with `script-src 'none'`. | `<img data:image/svg+xml;base64>` of the sanitised SVG, directly in the page (an image context runs no script and loads no external resource). | never |
| `Mermaid` | Isolated surface with the pinned Mermaid bundle (D7). | Sandboxed `srcdoc` iframe loading the pinned bundle from the application's own static files (D7). | Mermaid only, never artifact script |
| `Html` | Isolated surface, scripts on (setting `Cowork:Artifacts:Scripts`, default `OnOpen`), network off. | Sandboxed iframe on a ticketed render document of the API (D7), scripts on. Without the API origin, in Demo, or while the ticket route is not public: sandboxed `srcdoc` iframe, which the inherited CSP makes script-free, labelled "static view". | artifact script, `Html` only |

An unknown kind (a newer client wrote it) shows metadata, the export action and "This version of Autonogrammer cannot display this kind"; nothing is rendered.

### D6. In-process renderers

- **Markdown** is not changed. An artifact's links open only on an explicit user action through the same link path as transcript markdown, showing the full URL first. Relative links and `artifact:` references are plain text in v0.16.0. Mermaid fences inside markdown stay code blocks.
- **Code** language tags map to TextMate grammars already shipped with `TextMateSharp.Grammars`; the selection is by exact tag, never by path.
- **CSV** uses an in-house RFC 4180 reader (quotes, embedded newlines, byte-order mark) with hard caps: 2,000 rows, 50 columns, 2,000 characters per cell, 1 MiB input; beyond them the view says "Showing the first N rows" and counts what was left out. Cells are text only. A cell that starts with `=`, `+`, `-`, `@`, tab or carriage return is marked "formula-like" in the view. Export neutralises formula-like cells with a leading apostrophe by default (D10).
- **Image** is validated by reading the container header without decoding: magic number against the declared type, width and height both at most 8,192 and at most 50 megapixels (decompression-bomb guard), size at most `Cowork:Artifacts:MaxImageBytes`. An `Image` artifact is never SVG.
- **SVG sanitiser** (pure code, no new dependency). Parsing is XML, not HTML: `XmlReaderSettings` with `DtdProcessing = Prohibit` (a DOCTYPE rejects the document), `XmlResolver = null`, `MaxCharactersInDocument = 262,144`, `MaxCharactersFromEntities = 0`, comments and processing instructions ignored; depth at most 64, elements at most 5,000, any attribute value at most 64 KiB. The output is written by an `XmlWriter` from an allowlist walk, never by editing the source string. Allowed elements: `svg g defs title desc path rect circle ellipse line polyline polygon text tspan linearGradient radialGradient stop clipPath mask pattern symbol use marker style image` and the filter primitives `filter feGaussianBlur feOffset feBlend feColorMatrix feComposite feFlood feMerge feMergeNode feDropShadow`. Everything else is dropped with its subtree: `script foreignObject iframe object embed audio video canvas animate animateMotion animateTransform set handler listener metadata switch feImage feTurbulence feConvolveMatrix feDisplacementMap feMorphology` and any element outside the SVG namespace. Attributes: an allowlist of presentation and geometry names; every `on*` is dropped; `href` and `xlink:href` keep only same-document `#fragment` references, plus `data:` raster URIs on `image`; `style` attributes and `style` elements pass a conservative CSS check (no `@` rules, no backslash, no comment, `url(` only with `#fragment`, function names from a short allowlist) or are dropped whole. Every removal is returned as a finding and surfaced as a `warnings` entry (D4) and a notice in the panel. A rejected document renders as source.
- **Why not an HTML sanitiser for SVG.** `HtmlSanitizer` 9.2.1039 (MIT, built on `AngleSharp` 1.7.2 and `AngleSharp.Css` 1.0.2, nuspec read 2026-10-28) is the usual choice. It parses markup with the HTML5 algorithm, whose foreign-content rules for SVG differ from the XML parser that finally shows an `<img>` SVG; sanitising with one parser and rendering with another is the mutation-XSS pattern. Here both sides are XML, and the result is displayed as an image, so parser parity holds by construction. It also adds two packages to defend a path that can be written with the BCL. Not adopted; the same reasoning applies to HTML, which is not sanitised at all (D1).
- **Why not an SVG renderer on desktop.** `Svg.Skia` 5.2.3 (MIT) depends on SkiaSharp 4.148.0, while `Avalonia.Skia` 12.1.4 depends on SkiaSharp 3.119.4 (nuspecs read 2026-10-28); `Avalonia.Svg.Skia` 11.3.0, the newest published, depends on Avalonia 11.3.0. Neither fits the pinned graph, so desktop SVG goes through the isolated surface and falls back to source when no surface exists.

### D7. The isolated surface

One contract, three implementations. The contract (`IArtifactSurface` in Presentation, state machine `Idle`, `Loading`, `Running`, `Stopped`, `NavigationBlocked`, `Unavailable(reason)`) guarantees:

1. The artifact document is built by the host from the stored bytes and a document policy (`ArtifactDocumentPolicy`, pure code, unit-tested as strings). The policy is the only place a CSP is written.
2. Policy for `Html` with scripts on: `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'; img-src data: blob:; font-src data:; media-src data: blob:; connect-src 'none'; frame-src 'none'; worker-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; manifest-src 'none'`. There is no `'unsafe-eval'`: code that needs `eval` or `new Function` fails, and that is a documented limit, not a switch. With scripts off the policy has `script-src 'none'`. `SVG` and `Image` documents use `default-src 'none'; img-src data:`. Approved network origins (D8) are added to `connect-src`, `img-src`, `font-src` and `media-src` only, never to `script-src`: remote script is arbitrary code with an approved exfiltration channel, so v0.16.0 has no CDN scripts and artifacts must be self-contained.
3. There is no bridge. The surface subscribes to no message event, exposes none, and never calls `postMessage`. On the desktop control the post-message bridge option is turned off, the data store is private and non-persistent, developer tools and default context menus are off. A test asserts the wrapper has no message subscription, and a live test loads a probe page that looks for `invokeCSharpAction`, `window.chrome.webview`, `window.webkit.messageHandlers` and `window.external` and records what it finds.
4. Navigation is allowed once, to the host-built document. Any later navigation, new-window request, `meta refresh`, form submission or `base` change is cancelled (desktop: navigation-started and new-window handlers; web: `sandbox` without `allow-popups`, `allow-top-navigation`, `allow-forms`, `allow-modals`, `allow-downloads`, `allow-pointer-lock`, `allow-presentation`, and a second `load` event on the frame is treated as an escaped navigation and the frame is destroyed). The state becomes `NavigationBlocked` and the panel says so.
5. The surface exists only while the panel shows it. Switching away, closing the panel, signing out or pressing Stop destroys it, so a hostile script cannot keep a CPU, a timer or audio running in the background. State is not preserved.
6. The panel chrome labels the region "Generated content, not part of Autonogrammer" and shows a persistent status line: `Running in a sandbox. No network.` or the approved hosts.

Implementations:

| | Desktop | Web, ticketed render | Web, `srcdoc` |
| --- | --- | --- | --- |
| Mechanism | `NativeWebView` from `Avalonia.Controls.WebView` 12.1.1, `NavigateToString` of the built document, CSP as a `meta` element placed first | `<iframe sandbox="allow-scripts" referrerpolicy="no-referrer" allow="">` pointing at `GET {api}/cowork/artifact-render/{ticket}` | `<iframe sandbox="allow-scripts" srcdoc=...>` |
| Policy delivery | Meta CSP only (the control gives no response headers); `frame-ancestors` and `sandbox` directives are ignored in a meta, so the host navigation filter and the control options carry that part | Response headers: the D7.2 policy, `sandbox allow-scripts` as a CSP directive (so a direct visit still has an opaque origin), `frame-ancestors <web origin>`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, `Permissions-Policy` denying every feature | Inherited from the page (CSP3 7.8) plus the meta policy of the document; policies intersect |
| Scripts | yes (Linux measured only at ADR-0009 scope; elsewhere compile-checked) | yes | inline script blocked by the inherited `script-src 'self'`; scripts loaded from the application's own static files are allowed |
| Used for | `Html`, `Mermaid`, `Svg` | `Html` | `Mermaid`, static `Html`, and `Html` when the ticket route is not available |
| Status | `Avalonia.Controls.WebView` accepted for Linux only (ADR-0009); `Unavailable(NoWebViewEngine)` or `Unavailable(NotSupportedOnThisPlatform)` shows source | Needs the API on a public origin (OD-03), `frame-src <api origin>` in the web CSP | Always available |

Why three. The desktop control cannot send headers, so it uses a meta CSP. A web `srcdoc` frame inherits the page policy and so cannot run inline script, which makes it right for static content and for Mermaid (the host and the bundle are same-origin files that the inherited `script-src 'self'` allows; the diagram source travels as escaped text inside the document, never as a message) and wrong for a small web app. A document served by the API under its own response CSP runs scripts without inheriting anything, but needs a ticket because a browser frame navigation cannot carry the bearer token.

Render tickets (web only). `POST /cowork/artifacts/{id}/versions/{n}/render-tickets` (bearer, owner-scoped) returns a URL whose last path segment is an HMAC-SHA256 token over account id, artifact id, version, content hash and an expiry of at most 60 seconds; the key is `Cowork:Artifacts:RenderTicketKeys` (two keys for rotation, each at least 32 random bytes, validated at startup; failures name the key, never the value). `GET /cowork/artifact-render/{ticket}` is anonymous (the ticket is the credential), re-reads the version, re-checks the hash and the grants, and returns the document. The ticket is a path segment, is excluded from access logs by a log-redaction rule, and the frame is created with no referrer. A leaked ticket exposes one immutable version for under a minute.

Mermaid. The pinned bundle is `mermaid` 12.2.0 `dist/mermaid.min.js` (npm `latest` on 2026-10-28; MIT; file 5.2 MB; SHA-256 `a8a6a6f805b074a8261a2825c86f99c8054acb3b35f50bb7e24a4f9f2c3c3b9f`; tarball integrity `sha512-w7nr/SFrLO7BaVTs3dQTvYSV6nYSBj0Yy9DjBhsIJtAcHqRzXSq4Pg32ujHZ/AdWsAMNEvvhbm5dt9E2tOiHzw==`). It is vendored once under `src/Autonogrammer.UI/wwwroot/lib/mermaid/` with `VERSION.txt` and `LICENSE` in the format of `lib/xterm/VERSION.txt`; the desktop links the same file as an embedded resource so there is one copy. A test hashes the embedded bytes against the pinned value. The host script initialises Mermaid with `securityLevel: 'strict'` and `startOnLoad: false` (both strings read in the bundle), no HTML labels, deterministic ids, `maxTextSize` 50000 and `maxEdges` 500; the exact key names of the last four are confirmed by the hostile Mermaid fixtures against the bundle, not assumed. The bundle's default `secure` list (`secure`, `securityLevel`, `startOnLoad`, `maxTextSize`, `suppressErrorRendering`, `maxEdges`, read from the bundle) is meant to stop an `%%{init}%%` directive from raising them, and a fixture proves it. On the desktop the document carries `script-src` hashes for the bundle and the host script and no `'unsafe-inline'`. A bundle that is missing or fails its hash makes the kind `Unavailable(MermaidAssetMissing)` and shows the source. The bundle contains `elkjs` (EPL-2.0, see Licence); admitting it is an owner decision (OQ-400), and the asset sits behind `IMermaidAssetProvider` so a build without it can replace the file with no contract change.

### D8. Network and storage approval (default off)

- An artifact starts with no network and no storage. The author (agent or user) may declare requested origins in the version's `permissions` (D3, D4). A declaration is a request, never a grant.
- Valid origins: `https` only, host name only (no IP literal, no `localhost`, no private, link-local or metadata address, no user information, no wildcard, default port), at most 5. Others are rejected at write time.
- When a version with requested origins is opened, the panel shows a status banner ("This artifact asks to connect to api.example.com") and a "Review access" button. The dialog lists each origin in its ASCII (punycode) and decoded forms, marks a mixed-script name, shows the agent's reason labelled "Written by the agent", and states: "Anything you type into this artifact can be sent to these hosts. Requests are made from your device." Buttons: "Allow for this session", "Allow for this version", "Deny"; focus starts on Deny and Escape is Deny. Nothing is approved by timeout or by default.
- A grant is stored with `(ArtifactId, Number, ContentSha256, origins, scope, device, time)`. It is bound to one immutable version: a new version, even one asking for the same hosts, asks again, so a prompt-injected update cannot reuse an earlier approval. "Allow for this session" is held in memory.
- Approved hosts change the document policy (D7.2) and, on the desktop, an allowlist in the resource-request handler. The panel header always lists the approved hosts as text. "Access" in the panel menu revokes at any time; revoking destroys and rebuilds the surface.
- Storage is not offered in v0.16.0: browser storage, file-system access and an account storage API all need a bridge or a shared origin, and D7 forbids both (an API-served frame with `allow-same-origin` would share one origin and one `localStorage` across every artifact of every user). `permissions.storage` accepts only `none`; a request for more produces the notice "This artifact asked to store data; storage is not available" and a `warnings` entry. The user's way to keep state is Export.
- Every grant and revocation is an audit event (hash and origins, no content): `artifact.grant` and `artifact.revoke`, with `artifact.created` and `artifact.updated` for versions, in the closed `cowork_events.kind` list fixed by phase 68 unit 3 (ADR-0031 M0006).

### D9. Persistence, limits and the account listing

- Local store (desktop, authoritative): `<stateRoot>/cowork/artifacts/<account tenant>/<ArtifactId>/` with `artifact.json` and, per version, `v0001.json` (manifest) and `v0001.bin` (content). `<account tenant>` is the lowercase hex of the first 16 bytes of SHA-256 of the account id (the same derivation as the Dragonfly tenant key, report 04 8.1), so a second account on the same device sees nothing. Version files are created with `FileMode.CreateNew`, written through a temporary file with mode 0600 inside a 0700 folder and renamed (the `FileSettingsStore` pattern, report 02 section 12), under one lock per artifact. The head is derived from the highest version file; there is no separate head pointer to disagree with the versions.
- Account store (API): tables `artifacts`, `artifact_versions` and `artifact_grants` in the `autonogrammer` schema, created by migration M0006 `cowork` (ADR-0031 D4), which phase 68 unit 3 writes with the columns of D3 and D8 and a content cap `CHECK (octet_length(content) <= 5242880)` (the Image limit). Flat names and no row-level security: every query filters by `account_id` (ADR-0031, OQ-342). Content is `bytea`. These are regular tables, not hypertables. Phase 71 unit 3 writes `PostgresArtifactStore` and no migration.
- Sync: the desktop pushes each new version with `PUT /cowork/artifacts/{id}/versions/{n}` in the background; the route is idempotent by content hash (same bytes: 200; different bytes for an existing number: 409). The desktop treats a 409 as divergence and keeps its copy as a new artifact. Local is authoritative; the server is the account listing and the web head's source. Sync is one setting, off by default (OQ-343): until the user enables it only artifact metadata (id, title, kind, version count, timestamps, hashes) reaches the account store and no body leaves the device, since nothing leaves the device except by the user's request. The web head shows a "sync is off" state for the artifact list. Signed out means no Cowork and no artifacts (Cowork requires an account, ADR-0030).
- Routes (owner-scoped; another owner's id is the same 404 as an absent one, the `FindOwnedSessionAsync` pattern at `services/Autonogrammer.Api/Endpoints/SessionEndpoints.cs:417-431`): `GET /cowork/artifacts`, `GET /cowork/artifacts/{id}`, `GET /cowork/artifacts/{id}/versions/{n}`, `GET /cowork/artifacts/{id}/versions/{n}/content`, `PUT /cowork/artifacts/{id}/versions/{n}`, `DELETE /cowork/artifacts/{id}`, `POST /cowork/artifacts/{id}/versions/{n}/render-tickets`, `GET` and `PUT /cowork/artifacts/{id}/versions/{n}/grants`, and the anonymous `GET /cowork/artifact-render/{ticket}`. The routes live in the module `Api/Cowork/Artifacts` and use the `cowork_disabled` pattern (ADR-0032 D1). The OpenAPI transformer lists the render route as `security: []`, and it has its own rate-limiter partition. The web head does not create artifacts; the Cowork agent is local. `GET .../content` always answers `Content-Type: application/octet-stream`, `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`, so stored HTML can never execute from the API origin by navigation.
- Limits (options with a validator that names the key, defaults proposed): text kinds 512 KiB per version, `Image` 5 MiB, `Mermaid` 128 KiB, `Svg` 256 KiB, 200 versions per artifact, 500 artifacts and 256 MiB per account, title 120 characters, change note 280. The PUT route allows a 6 MiB body for images and 1 MiB otherwise; the store content cap is 5,242,880 bytes (the `Image` limit) and the 512 KiB text limit is enforced by the service. A limit failure is a typed result (`too_large`, `quota_exceeded`), never a truncation.
- Telemetry: counter `autonogrammer.cowork.artifact.count` tagged `kind` and `result` (`created`, `updated`, `rejected`, `conflict`), the name proposed in report 04 8.3; no account id, title or content in any tag or log. Logging uses `LoggerMessage.Define` with an explicit `EventId` block (7100 to 7199, proposed) and logs the artifact id only.

### D10. Export, diff and copy

- Export a version as a file or the artifact (all versions or a chosen set) as a zip built with `System.IO.Compression` from the BCL: `manifest.json`, then `v0001/<name>.<ext>` per version, fixed entry timestamps from the version's `CreatedAt`, names built from a sanitised title (letters, digits, `.`, `_`, `-`, space; no separators, no reserved Windows device names, at most 80 characters, de-duplicated), total uncompressed size capped. There is no import of archives, so there is no zip-slip surface.
- Export defaults to the safe form where one exists and loses nothing legitimate: `Svg` exports the sanitised document ("Original" is a second choice with a one-line risk note); `Csv` neutralises formula-like cells; `Html` exports with the same meta policy as the panel ("Original" is a second choice and says that opening it in a browser runs its scripts with no sandbox); `Markdown`, `Code`, `Mermaid` and `Image` export the stored bytes. The `Html` wrapper puts the meta first and drops a leading DOCTYPE from the artifact so the browser does not enter quirks mode; nothing else in the artifact is touched.
- Diff between two versions of text kinds uses `DiffPlex` 1.9.0 (`InlineDiffBuilder`, `SideBySideDiffBuilder`; Apache-2.0, pinned but unreferenced until now), capped at 20,000 lines and 512 KiB per side and run off the UI thread with cancellation; over the cap the view shows counts only. Lines are shown as text. Images and other binary kinds diff as metadata (sizes, hashes, dimensions).
- "Copy" is two actions: duplicate the artifact (D3) and copy a text version to the clipboard (user initiated; no surface can touch the clipboard because the iframe `allow` is empty and the desktop surface is given no clipboard hook).

### D11. Accessibility of the panel

- The panel is a labelled region ("Artifact: title, version 3 of 5"), reachable in the F6 region cycle that `MainView` already implements (`MainView.axaml.cs:818-844`), with a toolbar: version picker, Diff, Copy, Export, Edit (text kinds), Access, Stop, Close. Every control is at least `Autonogrammer.Size.TargetMin` (32; 44 on Android) and has an `AutomationProperties.Name`; the web equivalents are native buttons with accessible names and `aria-keyshortcuts` where a shortcut exists.
- The isolated frame has `title="Generated content: {title} ({kind}), sandboxed"`. Keyboard focus can enter it with Tab; a script in it can trap focus, which the host cannot prevent. The mitigation is a "Skip generated content" link before the frame and a "Return to chat" button after it, the Stop button in the toolbar, and the rule that the surface is destroyed when the panel is hidden. This is a recorded residual risk, not a solved one.
- Status and state changes use one polite live region: "Version 3 created by the agent", "Running in a sandbox, no network", "Blocked: the artifact tried to open another page", "Access to api.example.com allowed for this version". A new version never moves focus; the panel shows a "New version" badge unless the panel is empty (first artifact of a session opens it, setting `Cowork:Artifacts:AutoOpen`).
- The diff view does not rely on colour: each line carries "Added" or "Removed" text and a `+` or `-` marker in addition to the `DiffAdded` and `DiffRemoved` roles. The CSV view is a data grid or a `<table>` with a caption, column headers, and row and column counts announced. No new colour role is introduced (the contrast gate `ThemeContrastTests` classifies roles); the untrusted frame border and the banners use existing roles, and no transition runs under reduced motion (`HeadMotionTests`, `CssContractTests`).
- Dialogs (access review, export, save conflict) trap focus while open, restore it on close, and are named.

### D12. Live artifacts are omitted

Report 06 C20 and section 9 D6: Anthropic froze live artifacts on 2026-08-19 and replaced the guide with a deprecation notice (S6). A live artifact is a page that reads connector data at view time under the viewer's access. That needs a channel from the artifact to connectors and credentials, which is the bridge D7 forbids by construction; it also needs hosted sharing. Omitted by decision; an artifact is a static, versioned result.

### D13. Transcript and contracts

`ArtifactBlock` (kind `artifact`, fields: `ArtifactId`, `Version`, `Title`, `ArtifactKind`, `Action` of `Created` or `Updated`) is added to `Autonogrammer.Contracts` as an additive block. It renders as a card that opens the panel; it never renders content inline. Old readers show `UnknownBlock`. The change is additive; the scaffold step bumps `ContractVersion` to 1.6.0 once for all v0.16.0 additions and no phase edits `ContractVersion.Current` (OQ-405). The tool results of the family also reach the transcript as `ToolResultBlock` text.

## Blocked, and by what

- Windows (WebView2), macOS (WKWebView) and Android WebView behaviour of the surface: no runner; code is compile-checked only. The Linux WebKitGTK adapter is measured at ADR-0009 scope only.
- Interactive `Html` on the web head through the ticketed render route: needs a public API origin (OD-03, hosting blockers) and `frame-src` in the web CSP.
- Live Supabase and Railway checks: credentials and paused deploys; tests use the in-memory store and a throwaway local TimescaleDB.
- Mermaid shipping: licence admission (OQ-400).

## Consequences

- New projects `Autonogrammer.Cowork.Artifacts` (L2, pure, safe for the web head: no process spawn, no file system) and `Autonogrammer.Cowork.Artifacts.Stores` (L2, file and Postgres stores and the sync client), each with a test project; both are created and registered (`Autonogrammer.slnx`, `Autonogrammer.Linux.slnf`, `LayerMap.cs`, locks, the architecture test project) by the serialised scaffold step (`briefs/00-scaffold-manifest.md`); phase 71 adds code only.
- `Autonogrammer.Native.Views` gains `Avalonia.Controls.WebView` and `Avalonia.Controls.DataGrid` references; the Android head inherits them and stays compile-checked.
- `Directory.Packages.props` gains one pin (`Avalonia.Controls.DataGrid` 12.1.2) and relabels the WebView group from "spike" to production; `DiffPlex` gets its first reference; `THIRD-PARTY-NOTICES.md` is regenerated.
- The web CSP generator (`scripts/vercel/render-csp.sh`, `vercel.ts`, `scripts/vercel/build-demo.sh`) adds `frame-src` for the ticketed render origin; `RenderCspScriptTests` and the web smoke change with it.
- The contract, `docs/api/openapi.json`, the Demo handler fixtures and `ClientRouteSurface` change together for every route the web head calls.
- `docs/parity` gets a Cowork artifacts section when the panel lands; `docs/architecture.md`, `docs/SUMMARY.md` and `CHANGELOG.md` are updated by the documentation unit of the brief.

## Candidate chosen

First-party artifact core (`Autonogrammer.Cowork.Artifacts`) with an in-house allowlist SVG sanitiser and CSV reader, the existing Markdig no-HTML pipeline and AvaloniaEdit for in-process kinds, `Avalonia.Controls.WebView` 12.1.1 as the desktop isolated surface, a sandboxed iframe (`srcdoc` or an API-served, ticketed document) on the web head, vendored Mermaid 12.2.0 inside the surface for diagrams, `DiffPlex` 1.9.0 for diffs and `Avalonia.Controls.DataGrid` 12.1.2 for tables. No HTML sanitiser package is adopted. Decisions D1 to D13 give the rules.

## Open risks

- The desktop surface is measured on Linux at ADR-0009 scope only; CSP-by-meta, navigation cancellation, the bridge option and the private data store are unmeasured on every engine, and Windows, macOS and Android are compile-checked only. Where the surface fails to start the kind falls back to source.
- A script in the web frame can navigate the frame itself (a link or `location` assignment); CSP has no `navigate-to` in the engines, so this is detected by the second `load` event and the frame is destroyed after the navigation began. The content that loaded in the sandboxed frame has no access to the application.
- A hostile page can trap keyboard focus (D11) and can burn CPU until the user presses Stop or leaves the panel; neither can be prevented from the host.
- Native JavaScript dialogs on the desktop control may appear as application-owned dialogs and be used to deceive; the control's option to suppress them is not verified. The document prefix replaces `alert`, `confirm` and `prompt` with no-ops as a mitigation, which an iframe-created realm could undo.
- A granted host can resolve to a private address (DNS rebinding); the surface cannot see resolved addresses. The dialog says requests are made from the user's device.
- `mermaid.min.js` bundles `elkjs` under EPL-2.0 and about 5.2 MB of code that was not audited library by library; Mermaid has had sanitiser bugs, so the bundle is pinned by hash, runs only in the isolated surface, and an update is an amendment of this record.
- Inline-embedding a 5.2 MB script in `NavigateToString` on every open is unmeasured for time and memory.
- Prompt-injected content can make a polished phishing page inside the sandbox even with no network; the labelled frame and the absence of any input path out of it are the controls.
- `from_file` depends on the folder-grant policy of ADR-0032 (`CoworkSessionContext.TrustedFolders` and the Storage folder; `ICoworkGrantStore` holds tool grants, not folders); the panel is content of the `IDockPanel` contract and registers with `CoworkDockHost`, which shows it in a tab strip beside the Browser panel (ADR-0032 D3). If either differs when ADR-0032 is accepted, only the path check or one registration changes.
- ADR-0031 fixes the role model and the migration runner; its M0006 carries `artifacts`, `artifact_versions` and `artifact_grants` with the 5,242,880-byte content cap, so the limits of D9 (512 KiB text, 5 MiB image) are enforced by the service within that cap.
