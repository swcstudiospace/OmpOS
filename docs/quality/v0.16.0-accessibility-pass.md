# Accessibility pass for v0.16.0

Status: **In progress; not fully verified.** `CoworkSurfaceAccessibilityTests` passed 8/8, desktop-headless `CoworkHeadlessAccessibilityTests` passed 2/2, and standalone artifact-dialog/Dispatch-action tests passed 8/8. A signed-out Demo Cowork browser check exercised F6 region cycling. The Android 44px target, axe, live assistive technology, authenticated browser flows, Android device, WebView2 and WKWebView remain unverified.

This is the AG-77-13 / D-17 matrix. “Pending” means a named check has not been run; “not established” is a gap, not a pass. “N/A” means the interaction is not present. Web target-size checks use 24 CSS px; the Android target is 44 logical px and needs device verification. See [known issues](../accessibility/known-issues.md).

## Assistive technology and platform limitations

No real screen reader, Android device, Windows High Contrast theme, WebView2 or WKWebView run is recorded here. `docs/accessibility/screen-reader-test-plan.md` describes the outstanding manual work. The 2026-10-29 reports in `docs/runbooks/evidence/web-accessibility-2026-10-29/` cover earlier surfaces only and do not establish results for this milestone.
