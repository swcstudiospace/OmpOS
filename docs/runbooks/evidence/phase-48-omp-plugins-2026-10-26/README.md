## Application evidence: the pipeline flyout with real omp (2026-10-26, Phase 50 integration pass)

Debug build of `apps/OmpOS.Native` under Xvfb with real omp 18.12.6, sandbox `HOME`, `PI_CODING_AGENT_DIR` and `OMPOS_STATE_DIR` under `/tmp/f8shot/m4-cfg`. To let the application find all four plugins: `~/.agents` of the sandbox is a symlink to the machine's `~/.agents` (GSD core), `OMPOS_SUBSTRATE_URL` is the address of the Substrate server running on this machine (127.0.0.1:7410) and `OMPOS_SUBSTRATE_TOKEN_ENV=SUBSTRATE_TOKEN` names the variable the token is read from (the value is never printed or stored). No prompt was sent. Chat: ctrl+n, click the model chip, wait 70 s, click the pipeline strip; terminal: ctrl+shift+t, wait 70 s, click the strip; each flyout is shown at the top and scrolled.

| File | What it shows (quoted from the flyout) |
|---|---|
| `app-chat-plugins-flyout-top.png` | Engine "Waiting for events". Ultrathink: "Ultrathink connection - Done - Connected to omp", "Prompt plan - Waiting". Swarm: "Agent Swarm connection - Done - Connected to omp", "Subagents - Waiting - Orchestrator has not started". Substrate group "Degraded": "Substrate - Done - Substrate is reachable; index up, ledger up, events writable", "Substrate brief - Degraded". |
| `app-chat-plugins-flyout-scrolled.png` | "The brief could not be read (HttpStatus, HTTP 403)", "Substrate answered with errors. Some steering records or memory may be missing." with Retry stage; "Agent Substrate connection - Done - Connected to omp"; "Event ledger - Done - 0 recent events"; GSD "Running": "GSD connection - Done - Connected to omp", "Workflow phase - Running - Phase 23: Web Head on the Shared Presentation Layer, 0 of 1 plans". |
| `app-terminal-plugins-flyout-top.png`, `-scrolled.png` | The same rows for an omp terminal session (the interactive omp is behind the flyout): Ultrathink, Swarm, Agent Substrate and GSD connections all "Done - Connected to omp"; Substrate group Degraded for the same brief answer. |

So the four plugins report "Connected to omp" in both the chat and the terminal session. The Substrate group is "Degraded", not connected, because the operator token available in this environment is refused (HTTP 403) by the brief endpoint; the connection and health rows are Done. Without `OMPOS_SUBSTRATE_URL` and `~/.agents` (the plain sandbox of the Phase 50 captures) the same flyout reads "Agent Substrate plugin - Skipped - Agent Substrate is switched off in the agent loop settings" and the GSD stage is "unavailable". The strip pills read "Ultrathink waiting", "Swarm waiting": the group state is that of the plan and subagent stages, which wait for a prompt; the connection rows inside the flyout are the connected state. No product change was needed for the states to be visible; two wording defects were fixed: the health-check reason showed the internal code ("did not answer its health check (HttpStatus)"), it now names the HTTP status only (`SessionEngineSet`).
